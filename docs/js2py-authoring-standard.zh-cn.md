# js2py 教材编写与验收标准

建立日期：2026-09-23。本标准落实读者提出的要求：面向有成熟前端工程经验、没有后端实践的人，不能用简短概念与 API 清单代替完整教学。

## 1. 读者模型不是一句装饰性说明

- 默认会组织前端工程、对接接口、使用 Promise/async-await，了解 TypeScript 基础类型。
- 不默认会 Express、SQL、事务、密码认证、Linux 服务或数据库运维。
- 不把 Python 写法直接等同于 JS，也不要求先掌握复杂泛型和类型体操。
- 必需基础讲透；与当前目标无关的高级知识明确放入选修，不靠堆砌术语体现“深度”。

## 2. 一节合格的正文应建立完整的理解过程

编写正文之前，先在[章节契约](/Users/mikmyp/Documents/code-projects/langshift.dev/docs/js2py-chapter-contracts.json)中声明前置章节、新能力、独立验收与暂不要求的内容。逐段核查示例、作业和验收是否偷用了后续知识；“本章暂时不必理解”的内容不能成为本章的独立重建要求。图上的前置关系无环不等于语义检查通过。

当前第 00 章只验收小脚本的理解、运行、修改与简单排错；工程复现放 L10，不能重新把锁文件、模块入口和测试套件变成第一课门槛。每个语法阶段都有小产物，不以一次教完整个工程取代循序渐进。


对核心知识点，至少回答：

1. **问题与动机**：没有它时会遇到什么具体困难？
2. **先修知识**：读者需要已经知道什么？前面的哪一步建立了它？
3. **概念和机制**：参与者、数据流、生命周期及职责边界是什么？
4. **前端类比与限制**：什么经验可以迁移？什么地方照搬会错？
5. **最小完整例子**：完整文件、依赖、运行目录、命令、输入与预期结果是什么？
6. **逐步解释**：关键行为为何发生？不是把每一行翻译成一句中文。
7. **失败与排错**：至少一个真实失败如何触发、观察、定位和恢复？
8. **变式练习**：哪些任务有提示，哪些要求独立实现？
9. **验收与答案**：怎样知道自己做对了？答案与任务如何分开？
10. **适用边界**：例子没有处理什么？何时需要进一步方案？

篇幅没有统一下限。不能为了短而省略必需机制，也不能为了长而重复定义、堆 API 或无关历史。深度由解释与可验证行为决定。

## 3. 正例与反例

不合格写法：

> Session 用于操作数据库。调用 add、commit、refresh 即可完成创建。

合格写法应继续解释：一次业务操作为什么需要事务；连接与 Session 是否相同；谁创建、提交、回滚和释放；提交失败后还能否继续使用当前状态；如何构造两步写入中第二步失败的实验；怎样在数据库与测试中验证第一步没有残留。

不合格写法：

> 用 Depends 实现鉴权，具体解析 Token 的逻辑自行补充。

合格写法应交代：客户端提供了什么；服务器如何验证；如何获取真实用户；身份验证与对象权限如何分工；凭证过期或成员关系变化时怎样拒绝；如何用两个用户构造越权测试。

## 4. 代码与运行契约

- 每个例子声明运行环境：浏览器语法、本地单文件、本地多文件、API、配置、示意或预期失败。
- 完整例子不得依赖读者“刚好运行过上一个编辑器”的变量或 import。
- 未实现内容只能出现在明确标记的练习起点或示意中，不能称为完整可运行项目。
- 可运行例子必须给出对应环境的验证，不以 MDX 编译或 Python 语法检查替代执行。
- 故意错误说明错误类型与发生阶段，避免把静态检查、语法错误、运行异常和业务错误混为一谈。
- 配置文件不用 Python 代码块伪装；服务器示例不用浏览器运行按钮制造假象。
- 同一项目源文件只维护一份，网页、下载包与参考实现由明确来源生成或读取。

## 5. 练习质量

至少有解释性检查、带提示修改与独立变式三个层次。答案独立呈现，不把整份答案直接放在题目中。

测试应覆盖相关正常与失败路径。允许学习者查文档，但应能解释代码、应对需求变化、定位失败；“复制后得到相同输出”不等于完成验收。

针对时间不固定的学习者，每章提供可恢复的检查点：当前代码、最后成功命令、已通过测试、未解决问题和下次第一步。

## 6. 语言、版本与维护

- 简体中文为本轮教学主稿，英文与繁体同步核心讲解和代码语义。
- 翻译不修改可执行文件名、代码字面量、预期输出或示例 ID；必要的本地化与业务逻辑分开。
- 技术事实优先依据官方文档；注明核验日期和实际测试版本，不把“最新”写成永不过期的承诺。
- 每次改动记录：本轮完成、验证证据、已知限制、尚未解决的问题。
- 保持既有章节 URL；知识重组与导航迁移分开设计，避免盲目改名破坏链接。
