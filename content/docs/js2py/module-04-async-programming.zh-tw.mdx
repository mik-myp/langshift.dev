## 1. 為什麼現在才把代碼裝進函數？

L03 已經能處理任意數量的任務，並說明空輸入、未知時長和零預算怎樣經過控制流。現在出現一個新需求：同一套規則既要用於 20 分鐘的學習安排，也要用於 40 分鐘的安排，還要在修改輸入後重新計算。

複製整段腳本雖然能暫時得到結果，卻會把規則複製出多個版本。修改一處、忘記另一處，就可能讓兩個地方對“0 分鐘是否有效”給出不同答案。我們希望給一段已有邏輯命名，明確它需要什麼、返回什麼、是否修改輸入，再從不同地方調用它。

**函數不是讓代碼看起來更工程化的盒子，而是帶著輸入、輸出和副作用約定的可調用對象。** 本章先把執行機制講清，再把它用於任務規則；不會為了學習 def 就提前引入類、裝飾器、模塊拆分或 FastAPI。

## 2. 定義不等於調用：先建立執行順序

文件：`definition_and_call.py`。

<Code language="python">{getFunctionExample('definition_and_call.py')}</Code>

預期：

```text
Before definition
After definition
Inside call
25
```

這幾行中有兩種不同的動作：

- 執行 `def add_buffer(minutes):`，創建函數對象，把名稱 add_buffer 綁定到它。**此時不執行函數體。** 括號中的 minutes 是形參，表示這段邏輯需要接收一個值。
- 執行 `add_buffer(20)` 才是調用：20 是實參，本次調用把局部名稱 minutes 綁定到這個整數，然後開始執行縮進的函數體。

`return minutes + 5` 先計算結果，再結束**當前這次函數調用**，把值交還給調用表達式。於是 `result = add_buffer(20)` 等待這次同步調用完成，將返回的 25 綁定給 result，然後繼續執行下一行。

可以把執行路徑寫成：頂層語句 → 執行 def → 頂層語句 → 進入調用 → 執行函數體 → return 回到調用處 → 後續頂層語句。示例裡的 Inside call 只是幫助觀察進入時機；計算規則不需要永遠夾帶這些診斷打印。

注意三個細節：

1. 函數體像 if/for 一樣通過冒號和縮進組織，但函數還建立了自己的局部名稱空間，後面會逐步解釋。
2. 空行用於閱讀分隔，不負責開始或結束函數；退回外層縮進才回到頂層代碼。
3. 普通函數沒有強制的 self 參數。實例方法屬於後續的類知識，不應把它當作所有 Python 函數的固定模板。

### 2.1 不能假定 Python 會提前綁定後面的函數名

文件：`errors/before_definition.py`。

<Code language="python">{getFunctionExample('errors/before_definition.py')}</Code>

第一行就產生 NameError，沒有標準輸出，因為執行尚未到達 def。Python 會先解析整個文件，但**解析成功不等於所有定義語句都已經執行**。修復時讓 def 在真正調用之前執行，再確認結果為 25。

JS 的函數聲明可以有提升行為，但這不能直接遷移成 Python 的規則；JS 用 const 綁定的函數表達式也不能與函數聲明混為一談。這裡建立的是 Python 的執行模型，不是聲稱“兩種語言所有函數都相反”。

先自己再調用一次 `add_buffer(0)`，預測它會進入幾次函數體、返回什麼。不要通過把變量改名來猜測調用順序。

## 3. return 與 print：一個傳遞結果，一個產生輸出

### 3.1 調用表達式必須有一個結果，即使結果是 None

print 把文字寫到標準輸出；return 把一個對象交給調用方。終端看見某個數字，並不意味著調用方拿到了那個數字。

文件：`return_paths.py`。

<Code language="python">{getFunctionExample('return_paths.py')}</Code>

預期：

```text
done
unknown
pending
Ready: Read
None
None
```

逐個區分這三個函數：

- status_label 在第一個匹配的 return 處立刻結束當前調用。已完成任務返回 done，不再檢查它的時長；0 分鐘待辦返回 pending。這裡返回的是字符串，不是自動打印它。
- announce 的函數體執行一次 print，但沒有寫 return，走到函數末尾後隱式返回 None。所以 Ready: Read 是函數的輸出，下一行 None 才是調用方隨後打印的返回值。
- maybe_announce 在空標題時執行不帶表達式的 return，直接返回 None，不打印標題；非空時走到函數末尾，也返回 None，但會產生輸出。這兩個路徑的副作用不同，返回值卻都為 None。

return 不只退出 if 或循環，而是退出當前函數；它也不會直接退出整個腳本。需要得到業務結果的函數，應逐條檢查返回路徑，不能只在一個分支 return 而讓其他分支意外落到 None。

### 3.2 復現“看見數字，卻不能繼續計算”

文件：`errors/printed_result.py`。

<Code language="python">{getFunctionExample('errors/printed_result.py')}</Code>

錯誤發生前的標準輸出：

```text
25
```

第六行產生 TypeError：result 是 None，不能與 10 做數值加法。問題不在這次加法的寫法，而在上游函數把“打印結果”誤當成“返回結果”。把函數體中的 print 改為 return，再運行，應只打印最終的 35。

不要用 `result or 0` 把這個錯誤隱藏掉；那會把違反函數合同的情況偽裝成合法結果。也不要為了讓終端出現 35 而在函數里硬編碼打印它。

### 3.3 返回兩個信息時，仍然是返回一個對象

L03 學過元組解包；它可以接收函數返回的元組：

```python case=tuple_result
def split_minutes(total):
    hours = total // 60
    minutes = total % 60
    return hours, minutes


hours, minutes = split_minutes(135)
print(hours)
print(minutes)
```

預期：

```text
2
15
```

`return hours, minutes` 打包成一個二元組，再由調用方解包。不是函數有兩次 return，也不是兩個獨立異步結果。當前輸入約定為非負整數；接口字段更多時，命名字典可能比不斷增加元組位置更易讀。

**暫停點 A**：預測定義與調用的打印順序；修復一次“只打印、不返回”；解釋一次提前 return。記錄調用時傳入的值、返回值和副作用，恢復時分別核對這三項。

## 4. 參數與實參：調用時到底給哪個名稱什麼值？

形參是 def 中的名稱，實參是一次調用提供的對象或表達式。它們不是同一個層次：函數只定義一次，可以接收很多次不同的調用。

文件：`arguments.py`。

<Code language="python">{getFunctionExample('arguments.py')}</Code>

預期：

```text
25
45
20
40
```

| 調用 | 本次 minutes / repeats / extra | 解釋 |
| --- | --- | --- |
| `estimate(20)` | 20 / 1 / 5 | minutes 必需；其他使用默認值 |
| `estimate(20, 2)` | 20 / 2 / 5 | 位置實參依照形參順序分配 |
| `estimate(20, extra=0)` | 20 / 1 / 0 | 用名稱指定 extra，不必先填 repeats |
| `estimate(repeats=2, minutes=20, extra=0)` | 20 / 2 / 0 | 關鍵字實參按名稱匹配，不按這裡的書寫順序匹配 |

在這個普通簽名裡，必需的位置參數寫在帶默認值的參數之前。`extra=0` 在調用位置是關鍵字實參，不是給調用方創建變量；這是 L03 的 `enumerate(..., start=1)` 所使用的同一種機制。

Python 會在進入這個函數體前完成參數綁定。參數數量或名稱不合適會失敗，但**綁定成功不會替你驗證業務類型或取值範圍**。當前例子約定輸入為合適的數字，不會自動解析 `"20"` 或拒絕負數。

## 5. 參數綁定不自動複製：把 L02 的引用模型帶進函數

調用時，形參這個局部名稱綁定到實參對象。**沒有自動深複製，也不能通過重新綁定形參，讓調用方的名稱自動改指向另一個對象。** 與其爭論“按值／按引用”兩個過於簡短的標籤，不如直接看具體對象和綁定。

文件：`argument_binding.py`。

<Code language="python">{getFunctionExample('argument_binding.py')}</Code>

預期：

```text
Read
Local
False
None
['python', 'functions']
```

| 操作 | 改變了什麼 | 調用方會看到什麼 |
| --- | --- | --- |
| 剛進入 replace_local | 局部 task 與 original 指向同一個字典 | 還沒有修改 |
| `task = {...}` | 僅把局部 task 改綁到新字典 | original 仍是原對象 |
| `return task` | 把新字典交給調用方保存為 replacement | replacement 與 original 不同 |
| `task["tags"].append(topic)` | 通過共享字典取得內部列表並修改它 | original 的 tags 內容改變 |

add_topic 以修改傳入對象為目的，這裡返回 None 是明確的設計，而不是忘寫 return。相反，如果函數承諾返回一份可繼續計算的數據，意外返回 None 就是錯誤。不要用“所有函數都必須無副作用”或“返回 None 都是壞寫法”代替具體合同。

一個函數即使使用了局部參數，也不代表與外部完全隔離。返回一個新列表也不保證其中的字典是新的；複製到哪一層，仍按 L02 的數據形狀分析。稍後創建任務時，我們會明確選擇隔離傳入的標籤列表。

## 6. 默認值何時建立？為什麼第二次調用會影響第一次？

### 6.1 默認表達式在執行 def 時求值

文件：`default_values.py`。

<Code language="python">{getFunctionExample('default_values.py')}</Code>

預期：

```text
20
0
None
35
```

每次**執行這條 def 語句**時，默認表達式各求值一次，並把得到的對象保留為這個函數的默認值；不是每次調用時重新讀取表達式。這裡執行 def 時 default_minutes 是 20，後面重新綁定為 35，並沒有替換函數已經保存的默認對象。

省略 minutes 才使用默認值。顯式傳 0 就得到 0，顯式傳 None 就得到 None；Python 不會把 None 自動當成“沒傳參數”。最後一次調用明確讀取當前 default_minutes，所以傳入 35。

不要把這個規則理解成“默認值永遠在整個進程中只計算一次”：如果以後在另一個函數里反覆執行 def，會創建不同的函數對象，各自建立默認值。當前先理解每個函數定義與其後多次調用的區別。

### 6.2 默認列表會被多次調用共享

文件：`pitfalls/shared_default.py`。這是可運行但有意展示風險的寫法。

<Code language="python">{getFunctionExample('pitfalls/shared_default.py')}</Code>

實際輸出：

```text
['python']
['python', 'functions']
['python', 'functions']
True
```

`tags=[]` 在定義時創建一份列表。兩次調用都省略 tags，所以都把局部 tags 綁定到這同一份默認列表。第二次 append 修改它，first 仍指向它，因此 first 觀察到的內容也改變了。

把輸出畫成時間線：第一次調用追加 python → 返回同一列表給 first → 第二次調用追加 functions → first 與 second 都指向已經有兩項的列表。問題既涉及默認值的建立時機，也涉及返回對象的共享，不能只背“不要用 []”。字典和其他可變默認對象同樣需要分析。

對熟悉 JS 的讀者，這個差異值得單獨對照。下面只展示語法與執行結果，不依賴網頁運行器：

<PythonEditor title="默認對象的建立時機" compare={true} canRun={false}>

```javascript case=default_comparison
  return history.length;
}

console.log(remember());
```

```python case=default_comparison

```
</PythonEditor>

Python 輸出：

```text

```


JS 此處的默認表達式在需要默認值的調用時求值；Python 此處在定義時建立。參見 [Python 默認參數](https://docs.python.org/3.13/tutorial/controlflow.html#default-argument-values)與 [MDN 默認參數](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Functions/Default_parameters)。這不是說 JS 不可能共享對象：顯式傳入同一對象仍然會共享。

### 6.3 用 None 表達省略，再決定是否複製輸入

文件：`fresh_defaults.py`。

<Code language="python">{getFunctionExample('fresh_defaults.py')}</Code>

預期：

```text
['python']
[]
False
['python']
['python', 'copy']
False
```

這裡有兩個不同的設計決定：

1. tags 為 None 時，在函數體內創建空列表。這段代碼每次調用都會重新執行，因此兩個省略 tags 的任務有各自的列表。
2. 顯式傳入標籤列表時，先淺複製。因為函數承諾返回可獨立編輯的任務，不應讓之後的任務編輯汙染調用方的標籤列表。

第一點只解決默認對象共享；不加第二點，調用方顯式傳來的列表仍會被共享。當前標籤都是不可變字符串，因此複製一層列表足夠；如果標籤裡還有可變字典，這不等於通用深複製。

本函數把顯式 None 和省略參數同樣解釋為“沒有標籤輸入”，這是主動選擇的政策。需要區分這兩種含義時，None 就不能同時充當兩者的標記；本章不引入自定義哨兵對象。也不使用 `if not tags` 混淆 None 與調用方明確傳來的空列表。

**暫停點 B**：分別測試省略參數、傳 None、傳 0、傳空列表和傳共享列表時的適用函數。寫明哪些調用合法、默認值何時用到、哪些對象被共享或複製；不要把不屬於某個函數合同的輸入當作它必須支持的情況。

## 7. 作用域：名稱從哪裡來，為什麼“外面明明有”仍然報錯？

### 7.1 每次調用有自己的局部綁定

文件：`local_scope.py`。

<Code language="python">{getFunctionExample('local_scope.py')}</Code>

預期：

```text

module
20
35
```

format_label 的形參 label 是本次調用的局部名稱，遮住了文件頂層的同名 label；prefix 也是局部名稱。調用後頂層 label 仍是 module。兩次函數調用各有自己的局部綁定，不因為名稱相同就自動變成全局狀態。

current_limit 沒有把 limit 定義為局部名稱，因此讀取本文件頂層的 limit。兩次調用之間，頂層把它從 20 改綁成 35，下一次調用就讀到 35。這與上一節**已經求值保存的默認值**不同：這裡在函數體運行時查找名稱。

對本章的普通函數，可以先用下面的查找路線建立模型：

| 層次 | 在哪裡找 | 本章例子 |
| --- | --- | --- |
| Local | 當前函數調用的局部綁定，包括形參 | label、prefix |
| Enclosing | 外層函數的綁定，若函數嵌套定義 | 後面閉包中的預算 |
| Global | 本文件頂層的名稱，以後會稱模塊級名稱 | limit |
| Built-in | Python 提供的內置名稱 | len、print |

這常被縮寫為 LEGB，但背縮寫不是驗收。它不是“局部沒值就永遠自動去外層找”的無條件兜底規則；下一小節會驗證例外。這個簡圖也不試圖提前覆蓋類體、註解等後續機制。

局部名稱不會因為調用結束就變成頂層變量。下面是獨立的預期失敗實驗：

```python case=local_unavailable

    prefix = "Task"
    return f"{prefix}: {title}"


print(make_label("Read"))
print(prefix)
```

失敗前輸出：

```text

```

第七行 NameError：返回的是格式化後的字符串，不是把 prefix 這個名稱導出給調用方。對象可以通過 return 繼續被使用，不表示原來的所有局部名稱都對外可見。

### 7.2 局部賦值會影響整個函數體中該名稱的含義

文件：`errors/local_before_binding.py`。

<Code language="python">{getFunctionExample('errors/local_before_binding.py')}</Code>

調用進入函數後，第五行產生 `UnboundLocalError`，沒有輸出。它是 NameError 的一種更具體情況：Python 已經把 budget 判定為此函數的局部名稱，卻在給它綁定值之前先讀了它。

```python case=scope_repair

print(new_budget)
```

預期：

```text

25
```

## 9. 簡單閉包：讓返回的規則記住一次配置

### 9.1 先區分兩次調用做了什麼

我們想得到一個 20 分鐘規則和一個 40 分鐘規則，而不是每次判斷都再傳預算。可以讓一個函數接收配置，返回另一個函數。

文件：`closure_factory.py`。

<Code language="python">{getFunctionExample('closure_factory.py')}</Code>

預期：

```text
False
True
True
False
```

按生命週期拆開理解：

1. 調用 `make_budget_rule(20)`，為這次外層調用建立 limit 的局部綁定。
2. 執行內部 def，創建 fits 函數；它會用到外層的 limit，但此時不執行 fits 的函數體。
3. `return fits` 把函數對象交給調用方。不是 `return fits(...)`，所以此處沒有提前判斷某個分鐘數。
4. 外層調用已經結束；之後 `small_rule(25)` 才執行返回的函數，並讀取它所關聯的外層 limit。
5. 第二次工廠調用另建一套綁定，產生另一個函數對象，所以 20 與 40 的規則能同時存在，彼此不串臺。

這種函數連同它使用的外層函數綁定，形成這裡所說的**閉包**。不必把外層整個運行過程想成一直在後臺執行，也不是把所有局部名稱導出到全局；需要的綁定仍可被返回函數訪問。

工廠、內部函數、閉包不是三個額外框架 API：這裡仍只有 def、調用、返回與名稱查找。完整機制來自之前各節的組合。

不是每幾行都值得包一個函數，也不是每個函數都要接收整個系統的數據。先回答四個問題，再選擇函數邊界：

| 問題 | 分類規則的示例答案 |
| --- | --- |
| 輸入是什麼？ | 一個 None 或整數時長；bool 和字符串不在合同內 |

把分類函數與彙總函數分開，是因為前者決定一項數據的含義，後者負責遍歷和累計。顯示結果則交給調用方。以後同一份返回數據可以被其他代碼使用，不必先從打印文字裡再解析出來。

下一份文件使用**文檔字符串**：函數體第一條語句是三引號字符串，簡要寫下用途和合同。它不是運行時校驗，也不是 return；函數繼續執行後面的語句。三引號可以容納多行文本，這裡只寫短說明。我們不要求現在使用文檔生成器或學習類型註解。

這樣的分工提高可驗證性，但不是“所有函數都必須純函數”的教條；例如前面的 add_topic 明確負責修改。重要的是調用方能看見合同、預測副作用，而不是被隱藏狀態影響。

## 13. 離開本章前，應拿得出哪些證據？

- 能解釋執行 def 與執行調用的區別，並畫出返回到調用位置的路徑。
