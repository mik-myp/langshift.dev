## 2. Name binding is not a fixed-type storage box

### 2.1 Predict the three lines first

File: `bindings.py`.

<Code language="python">{getScalarExample('bindings.py')}</Code>

Expected:

```text
30
45
30
```

Read assignment in two steps: evaluate the right-hand side, then bind the name on the left to the resulting object. Here, “object” means a runtime value with its own type and behavior; it does not assume you can write a class.

| Statement executed | Current binding of `minutes` | Current binding of `saved_minutes` | New output |
| --- | --- | --- | --- |
| `minutes = 30` | Integer `30` | Not yet bound | None |
| `saved_minutes = minutes` | Integer `30` | The same integer object | None |
| `print(minutes)` | Integer `30` | Integer `30` | `30` |
| `minutes = 45` | Integer `45` | Still integer `30` | None |
| The last two prints | Integer `45` | Integer `30` | `45`, then `30` |

`minutes = 45` changes the name's binding. It does not mutate the original integer `30` into `45`. Nor is `saved_minutes` a formula that keeps reading `minutes`. It reads the right-hand side once when that assignment executes.

Do **not** infer that “Python assignment automatically copies data.” Two names can refer to the same object. This example has no change propagating to the other name because we rebind a name, and integers themselves are immutable. L02 will explore shared references and container mutation separately. You do not need memory addresses, `id()`, or caching rules to explain this program.

The first line already printed in the terminal will not become `45` either. `print` performs an output action at that moment; it is not a UI subscription to a changing name.

### 2.2 Use your frontend experience without overextending the analogy

Reassignment here can be compared with JS `let`. However, ordinary Python assignment has no `let`/`const` declaration keyword, and it does not acquire JS `const` binding restrictions. This is a naming convention, not syntax enforcement:

```python case=constant_convention
MINUTES_PER_SESSION = 25
MINUTES_PER_SESSION = 30
print(MINUTES_PER_SESSION)
```

Output:

```text
30
```

Uppercase communicates that the author intends a constant. The interpreter does not prevent the reassignment above. Team conventions are not runtime guarantees.

This course uses `snake_case` for ordinary names, such as `saved_minutes`. Names are case-sensitive: `minutes` and `Minutes` differ. They cannot begin with a digit or use a reserved keyword such as `class`. Avoid using `print`, `str`, or `int` for your own variables, because that shadows the built-in functionality you will call later. Local scope belongs in the functions chapter.

## 3. Values have types; names can be rebound

### 3.1 Similar appearance, different values

| Expression | Type name | Meaning here |
| --- | --- | --- |
| `30` | `int` | An integer used in integer calculations |
| `30.0` | `float` | A floating-point number with finite precision |
| `"30"` | `str` | Two characters of text; looking numeric does not make it an integer |
| `True`, `False` | `bool` | Boolean values, with capitalized first letters |
| `None` | `NoneType` | The dedicated object used for absence, with meaning assigned by your application |

Calling these “basic single values” distinguishes this chapter from the next chapter's containers; it is not new Python declaration syntax. Strings also have sequence behavior, which we will study later.

`type(value)` lets you inspect the current value's type. Learn to call it here; metaclasses are not a prerequisite. File: `scalar_types.py`.

<Code language="python">{getScalarExample('scalar_types.py')}</Code>

Expected:

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>
<class 'int'>
<class 'str'>
```

`print(type(30))` calls the inner `type` first, then passes its result to the outer `print`. The word `class` in the output is how the type is displayed, not an instruction to define a class first.

At the end, `minutes` first refers to an integer and then to a string. The language permits this. But permission to rebind a name to another type does not make all mixed-type operations valid. As a program grows, one name carrying conflicting meanings becomes harder to understand. Real code often uses `raw_minutes` for the original text and `minutes` for the converted integer.

### 3.2 An expression, its result, and output are different things

`30 + 15` is an expression that evaluates to a value. `total = 30 + 15` keeps its result; `print(total)` writes the result to the terminal. Writing `30 + 15` on a script line does not automatically echo it as some interactive consoles would.

The examples retain `print` so you can observe results, not because calculations need it to work.

### 4.1 Start with positive numbers, then inspect the type

File: `numbers.py`. Predict the first seven lines before considering the final three edge cases.

<Code language="python">{getScalarExample('numbers.py')}</Code>

Complete output:

```text

3.5

```

| Expression | Result | Explanation |
| --- | --- | --- |
| `7 + 2`, `7 - 2`, `7 * 2` | `9`, `5`, `14` | Addition, subtraction, multiplication |
| `7 / 2` | `3.5` | True division; `/` returns a floating-point result even with two integers |
| `7 // 2` | `3` | Floor division, not retaining the fractional part |
| `7 % 2` | `1` | The remainder paired with floor division |
| `7 ** 2` | `49` | Exponentiation; do not substitute `^` |
| `7.0 // 2` | `3.0` | A floored result, but a floating-point operand keeps the result a `float` |

Similarly, `8 / 2` is `4.0`, not `4`. The important part of `//` is the floor rule; do not memorize it as “division that returns an int.” These rules are documented in Python's [numeric types](https://docs.python.org/3.13/library/stdtypes.html#numeric-types-int-float-complex).

Multiplication and division bind more tightly than addition and subtraction. Use parentheses when intent could be unclear:

```python case=precedence
print(2 + 3 * 4)
print((2 + 3) * 4)
print(-(3 ** 2))
print((-3) ** 2)
```

Output:

```text
14
20
-9
9
```

The final two lines mean “square, then negate” and “square the whole negative number.” Express your intent with parentheses rather than memorizing the full precedence table now. Division by zero raises `ZeroDivisionError` instead of producing JavaScript Number's `Infinity`. Do not use zero as the divisor in our time conversion.

### 4.2 Negative numbers expose the “remove the decimal part” misconception

`-7 / 2` is `-3.5`. Flooring moves toward the smaller integer, so `-7 // 2` is `-4`, not `-3`. Its paired remainder is `1`, because:

```text
-7 = (-4) * 2 + 1
```

For integers with a nonzero divisor, quotient and remainder satisfy `a == (a // b) * b + a % b`. A nonzero Python integer remainder has the divisor's sign. JS `%` uses a different negative-number remainder rule: JS `-7 % 2` is `-1`. Check the [Python expression reference](https://docs.python.org/3.13/reference/expressions.html#binary-arithmetic-operations) and [JS remainder documentation](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Remainder) when you need to distinguish them.

Our deliverable uses positive minutes. You do not need negative modulo to implement the task; the experiment prevents the incorrect rule that `//` merely cuts off fractional digits.

### 4.3 Large integers and fractions: different precision issues

This static comparison illustrates the language boundary. This chapter's acceptance uses local CPython rather than the webpage runner.

<PythonEditor title="Python int and JavaScript Number" compare={true} canRun={false}>
```javascript case=integer_precision
console.log(2 ** 53);
console.log(2 ** 53 + 1);
```

```python case=integer_precision

```
</PythonEditor>

Python output:

```text

9007199254740993
```

JS Number prints `9007199254740992` twice. Python `int` is not constrained by JS Number's safe-integer range; it preserves integer precision within available resources. This does not imply unlimited computation or memory. JS also has a separate `BigInt` type, so this comparison does not mean JS cannot handle large integers. See [Number.MAX_SAFE_INTEGER](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER).

A `float` cannot represent every decimal fraction exactly:

```python case=float_precision
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

Output:

```text
0.30000000000000004
False
```

`==` compares values for equality; the next section introduces it more fully. This is not a random calculation failure: binary floating-point approximations produce an observable difference. Displaying two decimal places does not make the arithmetic exact. We use time estimates rather than financial settlement for practice; exact-decimal approaches come after their prerequisites. The official [floating-point tutorial](https://docs.python.org/3.13/tutorial/floatingpoint.html) explains the limitation.

## 5. Comparisons, Boolean values, and absence

### 5.1 `=` binds; `==` compares values

`minutes = 30` is assignment. `minutes == 30` produces a Boolean without changing the name. Python has no `===`. However, Python `==` is not simply JS loose equality or JS strict equality: it does not turn `"30"` into an integer here, yet different numeric types can compare equal.

This independent script combines comparisons and absence checks. File: `boolean_none.py`.

<Code language="python">{getScalarExample('boolean_none.py')}</Code>

Expected:

```text
True
False
True
True
True
False
None
True
False
```

Read the results individually:

- `30 == 30.0` is `True`: different types, equal numeric values.
- `"30" == 30` is `False`: numeric-looking text is not automatically converted for this comparison.
- `True == 1` is `True`: `bool` is a subtype of `int`, so Boolean values are related to `1` and `0` in numeric comparisons. Know the boundary, but keep concepts such as “completed” and “quantity” distinct in application code. Do not use this relationship as an excuse to skip data checks.
- `!=` means not equal; `<`, `<=`, `>`, and `>=` mean less than, less than or equal, greater than, and greater than or equal. These produce Boolean results. They do not automatically print a conclusion or redirect execution.

For now, observe Boolean values. `if`, `and`, `or`, and general truthiness are not yet taught. You do not need conditional statements to handle these results, and should not assume that `bool("False")` parses Boolean text.

### 5.2 `None` is different from a name that does not exist

Here we agree that `assignee = None` means “no assignee yet.” The assignment has bound the name; reading `assignee` is valid and returns `None`.

Keep these states separate:

| State | Interpretation in this example |
| --- | --- |
| `assignee = None` | The name exists; our convention says there is no assignee yet |
| `assignee = ""` | The name exists and holds an empty string; whether an empty name is allowed needs another rule |
| `assignee = "None"` | Four letters of ordinary text, not the absence object |
| Reading `assignee` without ever binding it | An unbound name, producing the `NameError` explored in L00 |

`0` and `False` have their own meanings too; they are not alternative spellings of `None`.

Treat `value is None` here as a narrowly defined check: is this value the dedicated `None` object? It is not string matching, and it does not treat an empty string as `None`. More generally, `is` concerns object identity, not another strict-equality operator. **Do not use `is` to compare numeric or string contents.** Further identity questions belong with containers and references. See the [None constant](https://docs.python.org/3.13/library/constants.html#None) and [PEP 8's comparison recommendation](https://peps.python.org/pep-0008/#programming-recommendations).

## 6. Strings: cleaning text does not mutate the original

A task title may contain leading and trailing spaces. We want a cleaned title for display while retaining the original for comparison.

Single and double quotes both delimit ordinary Python strings; these delimiter characters are not automatically included in the output. JS backtick templates cannot be copied unchanged. The f-string introduced later is our interpolation tool here.

First understand `raw_title.strip()`: the name after the dot is a string method, and the parentheses call it now. With no arguments here, it returns a string without leading and trailing whitespace. It does not delete internal spaces or mutate `raw_title`. Calling an existing method does not require defining classes or methods first.

File: `strings.py`.

<Code language="python">{getScalarExample('strings.py')}</Code>

Expected:

```text
[  Read Python basics  ]
[Read Python basics]
18
Python basics
It is "Python".
first
second
```

The first two lines concatenate square brackets around the text to make spaces visible. Those brackets are ordinary characters inside quotes, **not list syntax**.

`title` receives the cleaned result; `raw_title` still retains spaces on both sides. Strings are immutable. A method can return processed text, and you must use or keep that result. Writing only `raw_title.strip()` and then printing `raw_title` does not change what the name subsequently refers to.

`+` joins text when both operands are strings; it does not add a separating space for you. `len(title)` returns the length. All characters in this example are ASCII, and `Read Python basics` has 18, including spaces. Python `str` length counts Unicode code points, not necessarily visible characters; JS `String.length` counts UTF-16 code units. Unicode character counting is not an exit requirement here, but this simple example must not be generalized to all emoji or display widths.

`'It is "Python".'` uses outer single quotes around text containing double quotes. Inside a double-quoted string, `\"` is another way to include a double quote. `\n` represents a newline, so the final `print` produces two lines of text. To include a literal backslash, write `\\`. See the [text introduction](https://docs.python.org/3.13/tutorial/introduction.html#text) and [string methods](https://docs.python.org/3.13/library/stdtypes.html#string-methods).

Learn boundary cleanup, concatenation, and length here. A catalogue of dozens of methods, indexing, and slicing can wait.

## 8. f-strings produce text, not reactive views

`"Minutes: " + str(minutes)` works, but repeated manual concatenation makes it easy to omit a space or conversion. An f-string prefixes the quoted string with `f` and embeds expressions inside braces. Python evaluates them when that line executes and places their formatted results into a new string.

File: `formatting.py`.

<Code language="python">{getScalarExample('formatting.py')}</Code>

Expected:

```text
Estimate: 95 minutes
Estimate: 95 minutes
Estimate: 120 minutes
Decimal hours: 1.58
1.5833333333333333
```

`report` was constructed when `minutes` was `95`. Rebinding `minutes` to `120` does not rewrite an existing string. Constructing a new f-string in a later print reads the new value. This resembles an ordinary string already produced by a JS template literal, not a Vue computed property or a subsequent React render.

In `{hours:.2f}`, `hours` before the colon is the value; `.2f` requests fixed-point formatting with two decimal places. It changes the generated text, not `hours`. The final line still displays the original floating-point result. Formatting is not exact financial arithmetic or a business rounding policy.

If you omit the opening `f`, braces remain literal text instead of interpolating a name. See the [output tutorial](https://docs.python.org/3.13/tutorial/inputoutput.html#formatted-string-literals) and [format specification](https://docs.python.org/3.13/library/string.html#format-specification-mini-language). Mastering the entire formatting language is not required here.

- [Python assignment statements](https://docs.python.org/3.13/reference/simple_stmts.html#assignment-statements): right-hand evaluation, binding, and the distinction from mutation.
- [Python data model](https://docs.python.org/3.13/reference/datamodel.html#objects-values-and-types): objects, types, values, and immutability; reading the whole reference is not required now.
- [Python comparisons](https://docs.python.org/3.13/reference/expressions.html#comparisons): why numeric equality and object identity answer different questions.

This chapter uses CPython 3.13 as a teaching baseline, not as a claim about the latest release. Downloaded source, displayed examples, and maintainer runtime checks are maintained together.
