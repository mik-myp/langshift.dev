## 2. 名稱綁定：不是給變量裝上一個固定類型的盒子

### 2.1 先預測三個輸出

文件：`bindings.py`。

<Code language="python">{getScalarExample('bindings.py')}</Code>

預期：

```text
30
45
30
```

賦值可以分兩步看：先求右邊的值，再把左邊的名稱綁定到那個值所對應的對象。這裡說「對象」只是說明運行時的值有自己的類型和行為，不要求你已經學會編寫類。

| 執行語句 | `minutes` 此時綁定 | `saved_minutes` 此時綁定 | 新輸出 |
| --- | --- | --- | --- |
| `minutes = 30` | 整數 `30` | 尚未綁定 | 無 |
| `saved_minutes = minutes` | 整數 `30` | 同一個整數值對象 | 無 |
| `print(minutes)` | 整數 `30` | 整數 `30` | `30` |
| `minutes = 45` | 整數 `45` | 仍是整數 `30` | 無 |
| 後兩次輸出 | 整數 `45` | 整數 `30` | `45`，然後 `30` |

`minutes = 45` 改的是名稱的綁定，不是把原來的整數 `30` 原地修改成 `45`。`saved_minutes` 也不是一條「以後持續讀取 minutes」的公式。它在賦值發生時讀取了一次右邊的值。

這裡也**不能反推「Python 賦值會自動複製數據」**。兩個名稱可以指向同一個對象；本例之所以沒有連帶修改，是因為我們重新綁定名稱，而整數本身不可變。容器的共享引用與修改在 L02 用另一組實驗講解；現在不用記憶地址、`id()` 或緩存規則來解釋這個程序。

終端已經打印的第一行同樣不會變成 `45`。`print` 是當時發生的一次輸出，不是訂閱名稱變化的 UI。

### 2.2 與前端經驗的連接，以及類比的邊界

你可以把本例的重新賦值與 JS 的 `let` 類比，但 Python 的普通賦值前沒有 `let`/`const` 聲明詞，也沒有因此獲得 JS `const` 的綁定限制。下面是命名慣例，不是語法保護：

```python case=constant_convention
MINUTES_PER_SESSION = 25
MINUTES_PER_SESSION = 30
print(MINUTES_PER_SESSION)
```

輸出：

```text
30
```

全大寫表示「作者希望把它當常量」，解釋器不會阻止上面的重新賦值。不要把團隊約定當作運行時約束。

本書普通名稱採用 `snake_case`，例如 `saved_minutes`。名稱大小寫敏感，`minutes` 與 `Minutes` 不同；不能以數字開頭，不能佔用 `class` 等關鍵字。也不要把 `print`、`str`、`int` 當自己的變量名，否則會遮住後面要調用的內置功能。局部作用域規則留到函數章節。

**停靠點 A：** 不運行，解釋把第一行的 `30` 改成 `20` 後哪幾行輸出會變。若還覺得 `saved_minutes` 應該自動變成 `45`，先畫上述綁定表，而不是繼續背運算符。

## 3. 值有類型，名稱可以重新綁定

### 3.1 同樣的外觀，不同的值

| 寫法 | 類型名 | 此處表達的含義 |
| --- | --- | --- |
| `30` | `int` | 整數，可以參與整數計算 |
| `30.0` | `float` | 浮點數，用有限精度近似表示數值 |
| `"30"` | `str` | 兩個字符組成的文本，不會因為像數字就自動變成整數 |
| `True`、`False` | `bool` | 布爾值，首字母大寫 |
| `None` | `NoneType` | 專門表示「此處沒有值」的對象，含義由業務約定 |

我們把這些稱作本章的基本單值，便於與下一章的容器區別；這不是一種新的 Python 聲明語法。字符串也有序列行為，後面再展開。

`type(value)` 可以觀察當前值的類型。這裡先學會調用它，不需要研究元類。文件：`scalar_types.py`。

<Code language="python">{getScalarExample('scalar_types.py')}</Code>

預期：

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>
<class 'int'>
<class 'str'>
```

`print(type(30))` 先調用內層 `type` 得到類型，再把結果交給外層 `print`。輸出裡的 `class` 是類型的顯示形式，不是提示你必須先寫一個類。

末尾的名稱 `minutes` 先綁定整數，後來綁定字符串；語言允許這樣做。但「允許重新綁定不同類型」不意味著「不同類型可以混著做所有運算」。程序越長，同一個名稱承擔互相沖突的含義就越難理解，因此真實代碼通常會用 `raw_minutes` 保存原始文本，用 `minutes` 保存轉換後的整數。

### 3.2 表達式、結果與輸出是三件事

`30 + 15` 是會求出一個值的表達式。`total = 30 + 15` 保存它的結果；`print(total)` 才把結果寫到終端。僅把 `30 + 15` 寫在腳本一行上，不會像某些交互控制檯那樣自動回顯。

後面的每個輸出示例都保留了 `print`，不是因為運算必須依賴它，而是為了讓你觀察計算結果。

## 4. 數值運算：重點不是符號，而是結果規則

### 4.1 先看正數，再檢查類型

文件：`numbers.py`。先只預測前七行，再看後面三個邊界。

<Code language="python">{getScalarExample('numbers.py')}</Code>

完整輸出：

```text
9
5
14
3.5
3
1
49
3.0
-4
1
```

| 表達式 | 結果 | 原因 |
| --- | --- | --- |
| `7 + 2`、`7 - 2`、`7 * 2` | `9`、`5`、`14` | 加、減、乘 |
| `7 / 2` | `3.5` | 真除法；兩個整數使用 `/` 也得到浮點結果 |
| `7 // 2` | `3` | 向下取整的除法，不是保留小數部分 |
| `7 % 2` | `1` | 與整除結果配對的餘數 |
| `7 ** 2` | `49` | 冪運算；不要用 `^` 代替乘方 |
| `7.0 // 2` | `3.0` | 結果向下取整，但有浮點操作數時結果仍是 `float` |

同樣，`8 / 2` 是 `4.0`，不是 `4`。`//` 的「整」指取整規則，不能簡單記作「返回 int 的除號」。這些規則來自 Python 的[數值類型定義](https://docs.python.org/3.13/library/stdtypes.html#numeric-types-int-float-complex)。

乘除比加減優先；有意圖不清的組合就寫括號，不靠讀者猜：

```python case=precedence
print(2 + 3 * 4)
print((2 + 3) * 4)
print(-(3 ** 2))
print((-3) ** 2)
```

輸出：

```text
14
20
-9
9
```

最後兩行分別是「平方後取負」與「負數整體平方」。現在先用括號表達清楚意圖，不需要背完全部運算符優先級。除數為零會報 `ZeroDivisionError`，不是得到 JavaScript Number 的 `Infinity`；本章不要把零作為時間換算的除數。

### 4.2 負數會揭穿「去掉小數」的誤解

`-7 / 2` 是 `-3.5`；向下取整是走向更小的整數，所以 `-7 // 2` 是 `-4`，不是 `-3`。與它配對的餘數是 `1`，因為：

```text
-7 = (-4) * 2 + 1
```

對整數且除數不為零，商和餘數滿足 `a == (a // b) * b + a % b`。在非零餘數的情況下，Python 整數 `%` 的結果與除數同號。JS 的 `%` 使用餘數規則，不是同一套負數行為；例如 JS 的 `-7 % 2` 是 `-1`。需要核對時查看 [Python 表達式參考](https://docs.python.org/3.13/reference/expressions.html#binary-arithmetic-operations)和 [JS remainder 說明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Remainder)。

本章產物用正分鐘數，不需要依賴負數取餘做業務功能；這裡的實驗是為了防止把 `//` 錯記成「砍掉小數」。

### 4.3 大整數和小數：兩種不同的精度問題

下面的靜態對照展示兩種語言的邊界；本章以本地 CPython 的運行結果驗收，不依賴網頁運行器。

<PythonEditor title="Python int 與 JavaScript Number" compare={true} canRun={false}>
```javascript case=integer_precision
console.log(2 ** 53);
console.log(2 ** 53 + 1);
```

```python case=integer_precision
print(2 ** 53)
print(2 ** 53 + 1)
```
</PythonEditor>

Python 輸出：

```text
9007199254740992
9007199254740993
```

JS Number 兩行都輸出 `9007199254740992`。Python `int` 不受 JS Number 的安全整數範圍約束，會在可用資源範圍內保持整數精度；這不代表計算和內存無限。JS 的 `BigInt` 是另一種類型，不能把這裡的對照擴展成「JS 無法處理大整數」。詳見 [Number.MAX_SAFE_INTEGER](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)。

`float` 則不能精確存儲所有十進制小數：

```python case=float_precision
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

輸出：

```text
0.30000000000000004
False
```

比較符號 `==` 表示比較值是否相等，下一節正式展開。這個結果不是 Python 隨機算錯，而是二進制浮點近似經過運算後可見的誤差。不要用「只顯示兩位」冒充「已經精確計算」；本章用時間估算而不是金額結算來練習，精確十進制方案等有前置基礎後再教。官方[浮點教程](https://docs.python.org/3.13/tutorial/floatingpoint.html)解釋了這一限制。

**停靠點 B：** 現在應該能獨立說明 `95 // 60` 與 `95 % 60` 各代表什麼，以及 `7.0 // 2` 為什麼帶 `.0`。如果只記住輸出，還沒能解釋規則，先用紙筆換一組數。

## 5. 比較、布爾值和「沒有值」

### 5.1 `=` 保存綁定，`==` 比較值

`minutes = 30` 是賦值；`minutes == 30` 會產生一個布爾值，並不修改名稱。Python 沒有 `===`。但也不能把 Python 的 `==` 整體叫作 JS 的寬鬆相等或嚴格相等：它不會把 `"30"` 自動轉成整數來比較，同時數值類型之間又允許數值相等。

下面把比較與缺失值放在一個獨立腳本里。文件：`boolean_none.py`。

<Code language="python">{getScalarExample('boolean_none.py')}</Code>

預期：

```text
True
False
True
True
True
False
None
True
False
```

逐項解釋：

- `30 == 30.0` 為 `True`：類型不同，但數值相等。
- `"30" == 30` 為 `False`：數字文本不會在這裡自動轉成整數。
- `True == 1` 為 `True`：`bool` 是 `int` 的子類型，布爾值在數值比較中與 `1`、`0` 有關係。知道這個邊界即可，業務上仍然應把「是否完成」和「數量」當作不同含義處理，不鼓勵靠它省略數據檢查。
- `!=` 表示不相等；`<`、`<=`、`>`、`>=` 分別表示小於、小於等於、大於、大於等於。它們產生布爾結果，不會自動輸出文字結論或改變程序走向。

現在只是觀察布爾值，還沒有教 `if`、`and`、`or` 或通用真值規則；不要求提前用條件語句處理這些結果，也不要自行把 `bool("False")` 當成文本解析方案。

### 5.2 `None` 與「名稱不存在」不是一回事

在這個例子中，我們約定 `assignee = None` 表示「尚未指定負責人」。這條賦值已經綁定了名稱，讀取 `assignee` 合法，並得到 `None`。

以下幾種狀態必須分開：

| 狀態 | 本例中如何解釋 |
| --- | --- |
| `assignee = None` | 有這個名稱，約定它暫時沒有負責人 |
| `assignee = ""` | 有這個名稱，值是空字符串；是否允許空名字要另定規則 |
| `assignee = "None"` | 四個字母組成的普通文本，不是缺失值對象 |
| 從未給 `assignee` 賦值就讀取 | 名稱沒有綁定，按 L00 的實驗會得到 `NameError` |

`0` 和 `False` 也各有自己的值，不能當作 `None` 的同義寫法。

本章把 `value is None` 學成一個邊界明確的檢查：看值是不是那個專用的 `None` 對象。它不是字符串匹配，也不會把空字符串視為 `None`。`is` 一般討論對象身份，不是另一個嚴格相等符號；**不要拿 `is` 比較數字和字符串內容**。其他身份問題等容器與引用章節再展開。參考 [None 常量](https://docs.python.org/3.13/library/constants.html#None)和 [PEP 8 的 None 比較建議](https://peps.python.org/pep-0008/#programming-recommendations)。

## 6. 字符串：清理文本不等於修改原值

任務標題可能帶著首尾空格。我們希望顯示清理後的標題，同時保留原始值用於核對。

Python 單引號和雙引號都可以表示普通字符串；引號用於界定文本，輸出時不會自動帶上這些界定符。在 JS 中常見的反引號模板寫法不能原樣搬過來，下一節後的 f-string 才是本章的插值工具。

文件：`strings.py`。

<Code language="python">{getScalarExample('strings.py')}</Code>

預期：

```text

```

前兩行故意在文本外拼接方括號，讓空格不再「看不見」。這個例子裡的方括號是引號內的普通字符，**不是列表語法**。

`title` 得到了清理後的結果，原來的 `raw_title` 仍保留兩側空格。字符串不可變；方法可以返回處理後的字符串，你需要接收或使用返回值。只寫 `raw_title.strip()` 然後再次輸出 `raw_title`，並不會清理這個名稱後來讀到的內容。

## 7. 顯式轉換：輸入看起來像數字，不代表已經是數字

### 7.1 先決定要計算，還是要連接文本

`"30" + "15"` 是 `"3015"`，`30 + 15` 是 `45`。它們都合法，但解決的是不同問題。`"30" + 15` 則不能直接運算；Python 不會在這裡替你決定把哪一邊轉換成什麼。

內置的 `int`、`float`、`str` 在本章分別用於取得整數、浮點數與文本表示。文件：`conversions.py`。

## 8. f-string：把值做成文字，不是建立響應式視圖

手動寫 `"Minutes: " + str(minutes)` 可以工作，但隨著信息增多容易漏空格、漏轉換。f-string 在引號前加 `f`，在文本中的花括號內寫表達式；Python 在執行到這一行時求值，把格式化結果放入一段新字符串。

文件：`formatting.py`。

<Code language="python">{getScalarExample('formatting.py')}</Code>

預期：

```text
Estimate: 95 minutes
Estimate: 95 minutes
Estimate: 120 minutes
Decimal hours: 1.58
1.5833333333333333
```

`report` 在 `minutes` 等於 `95` 時就構造好了。後來把 `minutes` 改成 `120`，不會回頭改寫已經生成的字符串。最後一次直接構造新的 f-string，才會讀到新的分鐘數。這和 JS 模板字符串求值後的普通字符串一樣，不是 Vue 的計算屬性或 React 的下一次渲染。

`{hours:.2f}` 中，冒號前的 `hours` 是要格式化的值，後面的 `.2f` 要求固定小數格式、顯示兩位小數。它改變生成的文字，不修改 `hours`；最後一行還會顯示原來的浮點結果。格式化不是精確金額計算或業務舍入策略。

若忘記開頭的 `f`，花括號只是普通文本，不會插入變量。f-string 與格式說明的權威說明分別在[輸出教程](https://docs.python.org/3.13/tutorial/inputoutput.html#formatted-string-literals)和[格式規範](https://docs.python.org/3.13/library/string.html#format-specification-mini-language)中；本章不要求掌握整個格式語言。
