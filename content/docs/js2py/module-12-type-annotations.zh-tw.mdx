## 1. 什麼時候值得把數據和行為放在一起？

此前用字典保存任務、用函數修改任務，沒有錯，也不會因為出現 class 就自動落後。當多個函數都依賴同一組字段和規則時，把一份狀態與圍繞它的行為組合成對象，可以讓調用者更容易找到正確操作。但類不會自動產生數據庫、身份權限或不可破壞的約束。

本章把“任務完成”做成一個可以追蹤的小模型。你需要理解對象裡有什麼、多個名字是否指向同一對象、誰允許修改狀態，而不是學完語法就把每個字典改成類。

## 2. 從已有字典方案比較，而不是從術語開始

任務有 title、minutes、done。原來可以寫 mark_done(task)，從字典取 done，必要時更新，再返回是否發生變化。對象版本寫 task.mark_done()。關鍵不是句點更漂亮，而是狀態和行為的關係更直接；是否減少錯誤還要看規則設計和測試。

類描述怎樣建立及操作某類對象；實例是一次創建得到的具體對象。Task("Read", 30) 和再創建一次相同參數的 Task，不是同一個實例。讓另一個名字指向已有 task 則沒有複製。不要把“字段內容相同”和“身份相同”混為一談。

Python 類不是 TypeScript 的 interface：類定義和實例都在運行時存在。Python 類也不要簡單等同於 JavaScript 原型對象；本章先理解可觀察的創建、屬性和方法，不假定你已經會任何後端框架。

## 3. self 是收到的實例，不是隱藏的全局變量

下面是可以獨立運行的最小例子：

```python
class Counter:
    def __init__(self, start: int = 0) -> None:
        self.value = start

    def increase(self) -> int:
        self.value += 1
        return self.value


first = Counter()
second = Counter(10)
print(first.increase(), second.value)
print(Counter.increase(first))
```

```text
1 10
2
```

通常的實例方法訪問會把實例綁定為第一個參數。first.increase() 在這裡與 Counter.increase(first) 做同一件事；self 是約定的名字，不是特殊關鍵字。與 JS 的 this 綁定經驗不同，方法定義裡明確寫出接收實例的參數，但通過實例調用時不再手動傳它。

`self.value = start` 在當前實例上設置屬性；局部變量 value 與 self.value 不是一個存儲位置。__init__ 在新實例建立後負責初始化，不應返回業務對象。本章不實現底層對象分配；把 __init__ 理解為初始化步驟就足夠。

<details>
<summary>解釋題答案：把 second = first 之後會發生什麼？</summary>

兩個名字引用同一個實例。經任何一個名字調用 increase 都改變同一份 value。重新構造 Counter(first.value) 得到的是另一個計數器；這兩種操作不能只因初始數字相同就被稱為相同的複製。

</details>

## 4. 初始化校驗建立起點，不是永久封印

任務初始化要檢查非空白標題、普通非負整數 minutes，以及嚴格 bool 的 done。驗證成功後才把結果保存到實例。構造時失敗意味著調用者拿不到這個正常構造完成的 Task；不要用默認零值偷偷吞掉失敗。

mark_done 返回第一次變化是否發生，重複完成不重複計數；remaining_minutes 根據當前 done 計算，而不是再保存一個可能忘記同步的總計字段。很多狀態錯誤來自維護重複信息，並非缺少繼承層次。

不過 Task 的屬性仍公開可寫。構造通過後直接把 task.minutes 改成 -1，當前模型不會自動再次校驗。使用方法是一種約定，不是安全沙箱。以後服務入口、數據庫約束和業務操作各有責任；不能因為定義了一個“模型類”就停止驗證。

## 5. 組合先問“擁有哪個容器，共享哪些對象”

Plan 持有任務列表，是“有多個 Task”，不是“是一種 Task”。它複製傳入的外層列表，避免調用者清空自己的列表時意外清空計劃。但列表中的 Task 實例有意共享，所以把 read 標為完成後，計劃看到的剩餘時間也變化。

這不是深複製，也不是把任務凍結成快照。畫三個箭頭：原列表指向 task，Plan.tasks 指向同一個 task，兩個列表自身不同。若業務要求獨立快照，必須另外定義複製哪些狀態及後續更新的政策，不能只寫 list(...) 就聲稱完成。

本章用普通 for 循環彙總，避免為了簡寫提前要求生成器表達式。Plan 也不是一個防禦所有錯誤輸入的公共 API：它約定接收 Task 列表，未實現任意對象轉換。

## 7. 在使用 dataclass 前，先解釋這一行 @

`@dataclass` 放在類定義上方，表示類創建後交給 dataclass 處理，再把結果綁定回類名。對於本章簡單使用，可以理解為寫完 class 後再做 `Estimate = dataclass(Estimate)`。它不是每次讀取字段時執行的魔法。L13 會完整拆解裝飾器的求值、包裝與註冊；這裡先建立足夠使用該庫的局部機制。

dataclass 根據聲明的字段生成常用方法，例如初始化、可讀表示與字段比較。RawEstimate 故意沒有校驗：把字符串放進標為 int 的 minutes 仍能構造成功。Estimate 則在自動初始化調用的 __post_init__ 中明確驗證，規則來自我們寫的代碼，不來自類型註解。

`field(default_factory=list)` 提供一個創建默認值的函數。未傳 tags 時，每個實例各調用一次 list，得到自己的空列表；傳 list 而不是 list()。但調用者顯式傳入列表時，默認工廠不負責複製它，所以 __post_init__ 再複製外層列表，並檢查元素為文本。

不要直接用共享的 tags = [] 當實例默認值。本章 dataclass 會拒絕這種常見可變默認聲明；普通類的類屬性卻可能悄悄共享，下一節會實際觀察。__post_init__ 同樣只守初始化階段，之後直接 append 非文本值仍可能破壞約定。

## 12. 驗收、暫停與下一步

獨立解釋一個實例從創建、校驗、持有引用到狀態變化的過程；畫出 Plan 的淺複製；修復共享列表；區分 == 和 is；證明 RawEstimate 不驗證；完成 WorkLog 並製造一個共享默認缺陷讓測試捕捉。最後回答：這個模型已經替我解決數據庫或權限了嗎？答案必須是否定的。

暫停記錄模型契約、誰擁有哪個容器、最後通過的命令與測試數、已知可繞過的寫入口和下一步。恢復時優先重跑隔離與失敗測試，不只運行 app 看幾行熟悉輸出。
