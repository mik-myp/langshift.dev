## 1. 這是一次獨立交付，不是最後一份實現答案

你已經能理解後端教程，不代表在沒有參考實現時還能做出可維護的選擇。本章不提供表結構、路由設計、遷移命令、事務算法或完整後端代碼。你需要在自己的協作任務 API 上完成一個受控的新需求，並能解釋為什麼選擇它、怎樣發現自己做錯、以及如何恢復。

前置是 **O06 的能力與證據**，不是“頁面能打開”：已有項目必須有隔離恢復、訪問控制和受控發佈基礎。如果前章缺環境、未做恢復或尚未通過主線驗收，G01 可以閱讀和準備需求，但不能替它補上已驗收標籤。章節狀態由主線統一控制。

本任務以“任務評論”作為 capstone 中標籤擴展的等價受控變式，不要求兩個功能同時實現，也不降低 capstone 的交付門檻。它帶來的新複雜度是：同一對象上的作者與項目 owner 權限不同；評論有併發版本、撤回狀態和重複請求；新數據又必須經歷升級、發佈回退和恢復。不是多加一個 CRUD 表就算結束。

下載 [G01 需求與證據包](/learning-assets/js2py/g01-graduation.zip)，進入 `g01-graduation`。包內只有產品契約、合成場景數據、證據/評閱模板、評分規則和**材料格式檢查器**；沒有可以直接上線的後端參考答案。所有學生場景默認 `not_run`，沒有虛構試用數據。

## 2. 四件事必須各有證據，不能互相代替

| 結論 | 誰提供什麼證據 | 不能據此推導什麼 |
| --- | --- | --- |
| 課程內容完成 | 作者完成正文、資源、鏈接和主線所要求的審查 | 讀者已掌握，或所有前章環境都已跑通 |
| 作者參考驗證 | 作者在聲明的環境實際執行自己擁有的樣例/材料檢查 | 學生的另一套實現也正確 |
| 學生畢業 | 獨立項目證據、負向場景、恢復、現場變更與人工評閱 | 可不設限制地面向全網運營 |
| 真實公網運營 | 明確主機/域名/密鑰歸屬、HTTPS、安全發佈、預算、監控與真實使用證據 | 一次通過就永久安全、無限容量或無需維護 |

## 3. 新需求：評論屬於任務，作者身份不能被重寫

邏輯上，每條評論有身份、所屬任務及項目、服務器確定的作者、純文本、創建時間、成功修改後的版本，以及撤回狀態。評論正文為 1–1000 個 Unicode 碼點，不能只含空白，NULL 不合法；不支持富文本、附件、嵌套回覆或實時推送。邏輯事實不是給定物理表設計：字段如何存、接口如何表達、衝突怎樣響應，必須由你論證。

當前有效項目成員可以讀、列出和創建評論，也可以修改或撤回自己尚可見的評論。項目 owner 可以撤回本項目任何評論，**不能改寫其他作者的正文**。被移除的成員，即使仍持有未過期舊憑證或曾是作者，也不能再讀取或操作該項目評論；其他當前成員仍能看到歷史作者歸屬。停用賬號與未登錄者不能因“成員行還在”獲得訪問權。

撤回後的普通讀取只顯示墓碑式元數據，不暴露原正文；列表、詳情、歷史、導出和日誌不能成為繞路。撤回後編輯必須失敗，不允許舊請求讓正文復活。內部保留還是清除原文由你選擇並說明維護與備份後果；不要聲稱能從已經存在的所有備份中追溯性擦除內容。

該文件是三語教材共用的機器可讀產品契約，不是數據庫 DDL。產品要求和你選擇的實現約束要分開記錄：例如“過期成員無權訪問”是要求，“使用某個框架實現”不是評分項。超出範圍的微服務、公共註冊或新認證協議不會代替必需證據。

## 4. 數據、角色與失敗不能只用一個 Alice 演示

合成數據包含兩個項目、兩個 owner、普通成員、已移除成員、外部用戶和停用用戶；同一人可能在另一項目仍有權限。邏輯 ID 只用於描述場景，你需要提供它們與自己模型的對應關係，不必把它們變成數據庫主鍵類型，也不能導入生產數據覆蓋真實用戶。

<Code language="json">{getGraduationExample('fixtures/actors-and-data.json')}</Code>

最有區分力的證據往往是“正確登錄但對象不屬於他”：把別的評論 ID 與自己的項目路徑組合；用作者字段冒充別人；成員被移除後重放舊請求。僅測試 401 說明你檢查了登錄，不證明你檢查了每個對象邊界。被拒絕之後還必須檢查沒有修改、沒有洩漏正文，不是隻看一個狀態碼。

同樣，輸入邊界不是選一個空字符串就夠：空白 Unicode、NULL、最大長度、超長一個碼點，以及包含標記字符的純文本都屬於數據契約。前端不需要重新制作複雜界面；API 與必要的展示約定可以表達純文本語義，不得把 HTML 字符串當可執行富文本。

## 5. 併發、重複請求與未知結果是三類不同問題

兩個編輯基於同一舊版本，不能都靜默覆蓋成功；你要聲明衝突表現，並用獨立請求證明實際交錯。編輯與撤回相遇時，已提交的撤回不能被遲來的編輯逆轉。成員移除提交後才開始的請求必須拒絕；對已經在執行中的請求，你必須聲明一致的邊界並測試，不可事後挑有利的一次輸出。

重複創建的業務契約是：在至少 24 小時的保留窗內，同一已認證操作人、同一任務、同一請求身份和相同內容代表一條邏輯評論，並返回同一身份；同一範圍的請求身份換了正文應衝突，原評論不變。不同操作人或任務的請求不得互相取到緩存結果。過期後的行為由你選擇，但必須有界、可解釋、可測，而不是承諾永久 exactly-once。

重放仍須滿足當前權限：成員被撤銷後，不能因為“以前請求成功過”而讀到舊響應。響應丟失也不意味著數據庫沒提交；S16 專門要求驗證已接受但客戶端沒拿到響應時，再次請求不會製造重複評論。這是產品要求，不是讓你複製某個冪等中間件。

故障證據要指出失敗發生在哪裡、哪些狀態應該保留、哪些不應存在，以及後續合法操作如何恢復。只寫“捕獲異常”沒有說明數據庫剩下什麼；只看最終行數也可能漏掉曾經對外承諾成功卻沒有記錄的情況。外部結果和持久狀態需要能彼此解釋。

## 6. 場景目錄是驗收條件，不是現成測試套件

包內 24 個場景覆蓋功能、對象權限、併發、重複請求、失敗、查詢、升級、回退、恢復、運維、試用和獨立能力。它們不包含請求實現或數據庫答案，你要根據自己的接口契約構造可復現證據。

<Code language="json">{getGraduationExample('scenarios.json')}</Code>

一份有說服力的運行記錄能回答：哪個提交/遷移版本，在什麼獨佔環境，哪兩個主體提交了什麼經過脫敏的輸入，實際返回什麼，後來數據庫或服務狀態如何，以及怎樣重新觀察。併發記錄還要能證明發生了交錯，而不是順序執行兩次後稱其為競爭。

場景 `pass` 是你的聲明，評閱者仍要審查；`fail` 保留反例，`blocked` 說明缺少什麼和誰能解除，`not_run` 不編造時間和輸出。完整測試數量、覆蓋率、截圖多寡都不能替代關鍵負向條件。穩定分頁只要求不變數據集的順序明確；發生插入/刪除時的邊界必須說明，不能拿確定排序冒充跨請求快照。

<summary>核對區二：兩次創建都返回成功、最終只有一行，是否已證明重複請求正確？</summary>

還不夠。需要確認是同一範圍和請求身份，返回的是同一評論身份，原正文沒有被不同載荷覆蓋，另一用戶拿不到該響應，撤權後的重放仍被拒絕，且響應丟失路徑能恢復。最終一行也可能來自後續補刪或誤合併；只有能解釋接受結果和持久狀態的一組證據，才覆蓋這個產品契約。這裡不給實現算法。

## 7. 兼容升級、回退與恢復必須經過已有數據

空庫能啟動不證明升級安全。已有用戶、項目、成員和任務應保留身份和允許的原操作；舊任務初始沒有評論，不能捏造默認作者。帶有任意評論（包括墓碑）的任務不允許物理刪除；無評論任務原刪除行為保留。通過刪除項目繞過該規則同樣不可接受，具體項目刪除政策要與你的選擇一致並留證。

回退證據必須寫清“哪個應用版本與哪個結構版本兼容”。如果舊版本不能理解新狀態，允許你聲明安全凍結或受控回退條件，但不允許靠盲目 downgrade 丟掉已接受評論，再把啟動成功說成恢復成功。兼容性和數據保留承諾需要實測，不是為演示設計的空數據庫結論。

恢復則要求把備份真正恢復到另一個明確隔離的目標，核對關係、版本、撤回隱私和重複請求行為，並記錄恢復用時與可接受/實際數據丟失窗口。只恢復表數量可能漏掉“撤回正文重新可見”或“請求去重狀態沒恢復”。恢復時刻之前的備份可能含舊內容，保留政策和恢復後的數據窗口必須解釋，不能假裝備份隻影響性能。

沒有批准的目標、賬號、預算和 O06 證據時，受邀試用記為 blocked。條件具備後限 2–5 名受邀者、非敏感數據，並提交至少一次可追溯的匿名反饋及驗證過的調整。不得虛構參與人或把本地迴環地址標成公網 HTTPS。

## 8. 評分要有硬門檻，不能用漂亮文檔抵消越權

<Code language="json">{getGraduationExample('rubric.json')}</Code>

六項評分合計 100，參考合格線為 80；24 個場景對應的必需行為都要有人工審查通過的證據，hard_gate 標記為 false 也不是豁免。硬門檻失敗不能抵分，O06 必須獨立核實。越權、數據丟失、偽造證據、憑證洩漏、無法解釋獨立變更，都不能用額外界面或更高覆蓋率抵消。評分器不是畢業自動機，最終決定屬於評閱者。

獨立能力允許查官方文檔和使用輔助工具，但必須說明哪些工作得到協助。現場變更可以收緊“新評論”長度而保留歷史長評論讀取；評閱的是你能否識別受影響的契約、調整驗證並說明兼容性，不是在限定時間內盲寫最多代碼。另需解釋一個自己遇到的真實問題：初始判斷、反證、定位材料、修復結果和仍未解決的限制，不能把別人替你寫的結論背下來。

## 9. 格式檢查器故意不能替你畢業

材料包沒有外部 Python 依賴，不需要 pytest、數據庫、Docker 或前端構建。可選檢查器僅使用標準庫，本次以 Python **3.13.15** 驗證；只閱讀 JSON/Markdown 時連 Python 都不需要安裝。以下命令在包目錄執行，`python3 --version` 應先確認當前解釋器。

```bash
python3 --version
python3 check_evidence.py templates/evidence.json
python3 -m unittest discover -s tests -v
```

```text
{"artifact_files_verified": false, "backend_verified": false, "format_valid": true, "graduation_awarded": false, "public_operation_verified": false, "scenario_status_counts": {"blocked": 0, "fail": 0, "not_run": 24, "pass": 0}}
```

返回 0 只說明材料格式合格：場景 ID 齊全、聲明分離、引用格式完整、路徑不是越界路徑、時間等字段可解析。它**不打開證據文件核對哈希，不認證報告真實性，不調用後端，不掃描所有秘密，也不確認評分或部署**。測試特意在內存構造一份虛構但格式正確的報告，證明它仍可能通過格式檢查且 backend_verified 永遠是 false。這個單元測試不是虛構上線證據。

作者實際運行了 15 項材料單元測試，包括空模板、缺場景、重複 ID、無引用的 pass、越界路徑、虛假時間、缺原因的 blocked、懸空合成數據和損壞 JSON。未運行任何學生項目的 24 項業務場景。不要把兩種數量合併成“39 項後端測試通過”。

## 10. 暫停點記錄證據，不預設你的實現順序

可以按需求理解、設計評閱、行為觀察、交付/恢復證據、獨立答辯等狀態暫停，但這些是材料成熟度，不是指定先建哪個表、再寫哪個接口的開發路線。你可以用自己的開發順序，只要每項承諾最終都可核對。

<Code language="json">{getGraduationExample('templates/checkpoint.json')}</Code>

每次暫停至少記下代碼/結構版本、獨佔目標、最後實際命令、最後已證實事實、未解問題、下一條要收集的證據及已停止的資源。恢復時先確認當前狀態與記錄是否一致；不要因為“上次應該通過了”跳過檢查。缺環境要保留 blocked 及責任人，缺測試結果要保留 not_run，而不是填一個預期的成功值。

證據包可以引用相對路徑與摘要以便評閱定位，但請先脫敏；不要上傳完整環境變量、Token、連接密碼、真實用戶正文或私鑰。運行日誌的關聯 ID 應幫助還原問題，不應成為另一個數據洩漏入口。格式檢查器不是保密審計，提交者仍負責人工檢查。

## 11. 本章交付界限與必要來源

學生最終交付自己的模型與接口決策、遷移審查、實現和迴歸、失敗與併發記錄、發佈回退與隔離恢復、受邀反饋、維護預算/限制，以及獨立問題說明。可下載包僅幫助表達這些要求，不能代替產物。課程內容完成、作者材料驗證、學生畢業和真實公網運營仍是四個分別判斷的結論。

核驗日期 **2026-09-28**。必要官方依據僅用於澄清既有驗收邊界，不引入新架構：

- [OWASP API1 對象級授權](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/)：登錄成功不等於有權訪問給定對象。
- [PostgreSQL 18 SQL Dump 與恢復](https://www.postgresql.org/docs/18/backup-dump.html)：產生備份和實際恢復驗證是不同事情；本章不給恢復實現步驟。
- [HTTP 語義中的冪等方法](https://www.rfc-editor.org/rfc/rfc9110.html#name-idempotent-methods)：重複請求效果與方法語義有關，創建評論的產品去重承諾不會由一個 POST 方法名自動獲得。

未完成、未聲稱完成：學生後端、學生業務場景運行、O06 代驗收、畢業評定、真實受邀使用、公網發佈或長期運營。本章可審查的是要求與材料工具本身，其他狀態由真實證據和主線評閱決定。
