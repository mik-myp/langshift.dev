## 1. 现在的问题：不再只有一个值

L01 中，我们用几个名称保存标题、时长，再生成一段文字。只有一项任务时，这样足够；如果有两项任务，每项又有标题、标签、负责人和时长，继续增加 `title_1`、`title_2`、`minutes_1` 很快就容易配错。

我们需要两种组织方式：**把同一类条目放在一起，以及把同一条记录的不同字段放在一起。** 接下来还会遇到一个更隐蔽的问题：复制一个任务草稿后，为什么改了草稿的标签，原任务也变了？

这一章不以背容器 API 为目标。我们要能画出数据关系，解释修改沿着哪条引用发生，再决定哪里应该共享、哪里应该隔离。

## 2. 先决定数据表达什么，再选择容器

下面只是学习地图，具体机制会逐节实验，**不是看完这张表就算学会了四种类型**。

| 容器 | 当前适合表达的意思 | 访问方式 | 本章关注的限制 |
| --- | --- | --- | --- |
| `list` 列表 | 有顺序的一组任务或标题，允许重复 | 位置索引 | 可以修改；顺序改变后，同一个索引可能指向另一项 |
| `dict` 字典 | 一条任务的有名字的字段 | 键，例如 `"title"` | 可以修改；不存在的键与值为 None 不相同 |
| `tuple` 元组 | 固定位置含义的一组值，例如坐标 | 位置索引 | 元组自身的槽位不能替换，不代表内部对象都不可变 |
| `set` 集合 | 不重复的标签、成员关系 | 成员检查，不按位置取值 | 无位置顺序保证；成员必须可哈希，稍后解释 |

这不是“列表只能装同类型，元组必须装不同类型”的语言规定。选择首先来自数据含义。为了可读性，我们的任务列表放任务、标签列表放字符串，不把所有类型随意混在一起。

JS 的 Array、Object、Set 能帮助你产生直觉，但不能把 Python 容器当作换了拼写的同一套对象：越界、相等判断、缺失字段和集合成员都有差异。

## 3. 列表：位置、修改和返回值

### 3.1 方括号里的条目，与读取条目的方括号

`["Read names", "Practice values"]` 创建一个列表。逗号分隔条目，两个字符串仍然是两个值，不是拼接成了一段文字。

创建之后，`titles[0]` 表示读取索引为 `0` 的条目。列表从 `0` 开始编号；两项列表的有效非负索引是 `0` 和 `1`。`titles[-1]` 从尾部读取最后一项，`-2` 是倒数第二项。负索引不是循环回绕，越过开头仍然会出错。

`len(titles)` 返回条目个数，不是最后一个索引。空列表写作 `[]`，长度是 `0`，没有可读取的第一个条目。

### 3.2 先说明这个实验会用到的操作

- `titles[1] = "Practice containers"` 替换现有位置上的条目，修改列表，不是重新绑定 `titles`。
- `titles.append("Review")` 把**一个条目**追加到末尾，直接修改列表，返回 `None`，不是返回新列表。
- `titles.pop(0)` 删除并返回索引 `0` 的条目；剩余条目的位置向前移动。不传索引时，`pop()` 取走最后一项。
- `titles[0:1]` 是切片：从索引 `0` 开始，到索引 `1` 之前，得到一个新列表。右边界不包含在结果里。这里先观察外层列表，是否复制内部对象留到第 7 节。
- `"Review" in titles` 检查是否有相等的条目，产生布尔值，不是取得索引，也不是执行循环体。

输出整个列表时，你看到的是容器的表示形式：保留方括号，字符串条目显示引号。单独 `print(titles[0])` 则输出那个字符串本身，不带界定引号。它不是自动把 Python 数据转换成 JSON。

重点追踪三次变化：先替换第二项，再追加第三项，最后移除第一项。`pop(0)` 后的 `titles[0]` 已经是 `Practice containers`。所以“某项曾经在索引 0”不是这项任务永久的业务身份；后面做真正的后端时会另外学习标识符。

### 3.3 修改成功，不代表方法返回容器

`result` 是 `None`，但列表已经追加成功。**方法的副作用和返回值必须分别看。** `append` 为修改服务，`pop` 则既修改又交还被移除的值，不能概括成“所有修改方法都返回 None”。

修复不是改成另一种索引，而是不要接收 `append` 的结果来覆盖列表名称：保留 `titles.append("Review")` 这次调用，再单独读取列表。也不要套用 JS Array `push` 的返回值经验，Python `append` 不返回新长度。

## 4. 字典：用键表达一条记录

### 4.1 为什么标题、时长、负责人不该靠位置猜

如果把一条任务写成 `["Read names", 25, None]`，读者需要记住每个位置的含义。字典可以写成 `{"title": "Read names", "minutes": 25, "owner": None}`，让字段名称直接出现在数据里。

花括号包住键值对；每一对用冒号连接键与值，逗号分隔各对。本章用字符串作为键。`task["title"]` 取对应值；Python 字典不是通过 `task.title` 读取这个字段。

把字典写成多行时，大括号已经界定了表达式，换行和缩进是排版帮助，不是下一章才会学习的控制流代码块。最后一对后面的逗号也允许保留。

### 4.2 已有键被替换，新键被加入

文件：`dictionaries.py`。

<Code language="python">{getContainerExample('dictionaries.py')}</Code>

预期：

```text
Read names
{'title': 'Read names', 'minutes': 30, 'owner': None, 'done': False}
None
False
3
```

本例先创建三个字段，接着修改已有的 `minutes`，再加入原先没有的 `done`。同一个键不会因此出现两份；对已有键赋值是替换其关联值。

`task.pop("owner")` 删除该键并返回原来关联的值，所以这里得到 `None`。这是本例原本就存入的值，不是“删除没有成功”。之后 `"owner" in task` 为 `False`，字典只剩三个字段。

注意同名方法的参数含义：列表 `pop(0)` 使用位置，字典 `pop("owner")` 使用键；字典的 `pop` 需要提供键，不是无参数删除最后一项的列表操作。

Python 3.13 的字典保留插入顺序，替换已有键的值不会把它重新排到末尾。但保留顺序不等于按索引访问：`task[0]` 是查找整数键 `0`，不是读取第一个字段。字典的相等比较关注键和值，不以插入顺序是否相同为条件。

到这里先使用明确的字符串键，不把 JS 对象的数字属性名转换规则套过来。Python 的键有自己的类型，例如整数键 `1` 与字符串键 `"1"` 不同；不是所有对象都能作键，集合章节会补上“可哈希”这个限制。

## 5. 字段缺失与字段值为 None，必须分开

### 5.1 方括号在表达一个较强的要求

`task["owner"]` 表示“我要读取这个键关联的值”。键不存在时，不会自动生成一个 None 字段，而是抛 `KeyError`。

故意失败的文件：`errors/missing_key.py`。

<Code language="python">{getContainerExample('errors/missing_key.py')}</Code>

没有正常输出；第 2 行的错误最后一行是 `KeyError: 'owner'`。先核对需求：这个字段必须存在，还是允许缺失？不能为消除异常就一律塞入 None，否则会改变数据表达的意思。

### 5.2 `get` 的默认值只针对缺失

`task.get("owner")` 在键缺失时返回 `None`，不会抛上述 KeyError。提供第二个参数，如 `task.get("owner", "unassigned")`，则只在**键缺失**时返回这个默认值。它不会把已存在的 None、空字符串、0 或 False 自动替换掉，也不会把默认值写回字典。

因此，如果业务需要区分“没这个字段”和“字段明确为空”，仅检查 `get` 的结果是不是 None 不够，还要检查键是否存在。这里先分别打印这些事实，不提前写条件分支。

文件：`missing_values.py`。

<Code language="python">{getContainerExample('missing_values.py')}</Code>

预期：

```text
True
None
False
None
None
unassigned
[]
False
```

| 检查 | 为什么得到这个结果 |
| --- | --- |
| `"owner" in task` | 键已经存在，虽然值是 None |
| `task.get("owner")` | 返回已经存入的 None |
| `"deadline" in task` | 没有这个键 |
| `task.get("deadline")` | 缺失时默认返回 None，单看结果与上面无法区分 |
| `task.get("owner", "unassigned")` | 键存在，不用默认值 |
| `task.get("deadline", "unassigned")` | 键缺失，返回默认值 |
| 最后再检查 `deadline` | 仍然缺失，`get` 不会插入默认字段 |

输出 `[]` 的那一行是两个方括号字符夹着空标题，**不是打印了一个空列表**。它证明空字符串也没有被 `get` 的默认值替换。这沿用 L01 让空白可见的方法。

`in` 对字典检查的是**键**，不是所有值。`"Read" in {"title": "Read"}` 为 False，因为这里的键是 `title`。选择不同容器时，必须重新确认成员检查究竟查什么。

服务端以后也可能需要区分“请求没有提供字段”和“明确要求清空字段”；现在只是建立数据表达基础，没有开始讲接口更新协议。依据：[字典类型与 get](https://docs.python.org/3.13/library/stdtypes.html#mapping-types-dict)。

## 6. 共享引用：改名称，还是改对象？

### 6.1 回到 L01 没有提前展开的问题

L01 中两个名称绑定同一个整数后，重新赋值一个名称不会改变另一个名称。但列表可以被原地修改。赋值规则没有变，变的是我们现在对对象做的操作。

本节将 `is` 从 L01 的 None 检查扩展为一个实验工具：判断两边是否是**同一个对象**。不需要查看地址或记忆 `id()` 数字。

文件：`aliases.py`。

<Code language="python">{getContainerExample('aliases.py')}</Code>

预期：

```text
True
['todo', 'review']
['todo', 'review']
['done']
False
```

执行 `alias = original` 后，只有一个列表，两个名称都能访问它。`alias.append("review")` 通过其中一个名称修改这个列表，所以从 `original` 看也能看到新条目。并不是 Python 把一次修改广播到了两个副本，因为本来就没有两个副本。

随后 `alias = ["done"]` 创建另一个列表，并让 `alias` 改为指向它。`original` 仍指向原来的列表；重新绑定一个名称，不会把原列表里的条目重置掉。

| 写法 | 改变的对象或关系 |
| --- | --- |
| `alias = other` | 改变名称 `alias` 的绑定 |
| `alias[0] = value` | 修改 `alias` 当前指向的列表中的一个位置 |
| `alias.append(value)` | 修改 `alias` 当前指向的列表，新增一个条目 |
| `task["tags"] = new_tags` | 修改字典的一个关联，让这个键指向另一份值 |

这也是为什么“赋值左边有没有下标”会影响理解，不能把所有带 `=` 的行都解释成同一种名称重新绑定。

### 6.2 值相等，不等于同一个容器

两个内容相同、分别创建的列表可以 `==` 相等，同时 `is` 为 False。与 JS 对照时，不能把 Python `==` 直接当成 JS 对数组使用 `===`。

## 7. 复制：必须说清复制到哪一层

### 7.1 先看只有字符串条目的列表

`original.copy()` 创建一个新的外层列表。这与 `draft = original` 不同。列表的完整切片 `original[:]` 也创建浅复制；我们先统一用明确的 `.copy()`。

文件：`list_copy.py`。

<Code language="python">{getContainerExample('list_copy.py')}</Code>

预期：

```text

```

追加发生在新列表上，原列表没有增加条目。字符串条目本身不可变，这个例子暂时没有暴露内部共享的风险；不能据此认定 `.copy()` 会递归复制任意结构。

### 7.2 新字典，旧的内层列表

**浅复制**的意思是新建外层容器，但其中保存的条目或值仍引用原来的对象。字典的 `.copy()` 也遵循这个原则。

现在让任务的 `tags` 字段保存一个列表。`draft["tags"]` 先从字典取出这个列表，后面的 `.append(...)` 再修改该列表；不是向字典新增一个名叫 append 的字段。

文件：`shallow_copy.py`。

<Code language="python">{getContainerExample('shallow_copy.py')}</Code>

预期：

```text
False
True
Read
['python', 'basics']
Practice
```

画出关系，比背“浅拷贝”三个字更重要：

| 执行阶段 | 外层字典 | `tags` 指向的列表 |
| --- | --- | --- |
| 创建 `original` | 一份 | 一份，内容是 `python` |
| `draft = original.copy()` | 两份不同的字典 | 两个字典仍共享同一份列表 |
| 改 `draft["title"]` | 只替换草稿字典中的关联 | 不涉及标签列表 |
| 改 `draft["tags"]` 取得的列表 | 外层仍是两份 | 共享列表被追加，因此原任务也看到新标签 |

给 `draft["title"]` 赋新字符串，不会修改原字典的 `title` 关联。可是两次下标访问 `draft["tags"]`、`original["tags"]` 取得的是同一个可变列表。这是两种不同的操作对象，不是字典复制“有时成功、有时失效”。

文件：`isolated_copy.py`。

关键是 `draft["tags"] = original["tags"].copy()`：右边新建列表，左边只替换草稿字典中的 `tags` 关联。修改之前就切断了这条不希望共享的路径。

**这不是通用深复制函数。** 如果标签条目以后变成可变字典，或增加另一份可变字段，这段代码不保证它们也独立。应重新画关系、明确哪些层会修改。也不是所有共享都错误：看板和任务详情有时就应该引用同一份任务。

Python 的 `copy` 模块提供浅复制、深复制等工具，但它需要后面的模块知识，深复制的边界也要具体分析。本章不要求复制一行 `import copy` 后把机制当作已经解释完毕。参见 [copy 模块对复制语义的说明](https://docs.python.org/3.13/library/copy.html)。

## 9. 元组：固定的是槽位，不是整个对象图

列表适合需要增删条目的序列。有些数据由固定位置承载含义，例如二维坐标；元组可以表达这组槽位不被原地增删或替换。

`(2, 5)` 是两个元素的元组。单元素元组必须保留逗号：`("todo",)`；`("todo")` 只有用于分组的括号，结果仍是字符串。空元组写作 `()`。可以按索引读取、用 `len` 计数，但没有列表的 `append`。

文件：`tuples.py`。

<Code language="python">{getContainerExample('tuples.py')}</Code>

预期：

```text
2
1
<class 'str'>
<class 'tuple'>
('task-1', ['python', 'basics'])
```

最后的 `record` 有两个槽位：字符串和列表。`record[1].append(...)` 先取出列表，再修改列表；元组的第二个槽位仍然指向原来的那个列表，所以没有违反元组自身不可变的规则。

把“元组不可变”理解为“里面每层都深度只读”会出错。对于本章这个例子，固定的是元组持有的引用，不是被引用列表的内容。

故意失败的文件：`errors/tuple_assignment.py`。

<Code language="python">{getContainerExample('errors/tuple_assignment.py')}</Code>

它没有正常输出；第 2 行产生 `TypeError`，指出 tuple 不支持条目赋值。这次企图替换的是元组自己的槽位，而不是修改从槽位取出的列表。

如果需求是得到新坐标，可以创建新的元组，例如把名称重新绑定到 `(9, position[1])`；如果需求本来就需要频繁替换槽位，应重新考虑列表是否更适合。不能只为让异常消失而盲目换类型。参见[元组与序列](https://docs.python.org/3.13/tutorial/datastructures.html#tuples-and-sequences)。

## 10. 集合：关心成员，而不是条目位置

### 10.1 用“还缺哪些标签”建立动机

一项任务的标签可能重复录入。如果我们只关心标签是否存在，而不要求记录先后顺序和出现次数，集合可以表达“不重复的成员”。

非空集合可以写成 `{"python", "basics"}`；它使用花括号，但没有字典的键值冒号。**空花括号 `{}` 是字典，空集合必须写 `set()`。** `set` 是内置功能，不需要导入。

先说明本例要用的操作：

| 操作 | 本例的意思 |
| --- | --- |
| `tag in tags` | 检查成员是否存在，产生布尔值 |
| `tags.add(tag)` | 加入一个成员，已有则不增加重复项 |
| `tags.discard(tag)` | 移除一个成员；不存在时也不因此报 KeyError |
| `required - tags` | 新集合：要求有、但当前没有的成员 |
| `required & tags` | 新集合：两边都有的成员 |
| `required \| tags` | 新集合：两边所有不重复成员 |

后三种运算不会在本例中修改原集合。`add`、`discard` 则原地修改，返回 None，不是返回新集合。

集合没有列表那样的位置顺序保证，也不支持 `tags[0]`。为了让教材输出稳定，我们调用内置 `sorted(tags)` 得到一份排好序的**列表**再打印。当前只有小写 ASCII 字符串，可以用普通字母顺序预测结果；`sorted` 不会给原集合建立位置编号，也不修改它。

文件：`sets.py`。

<Code language="python">{getContainerExample('sets.py')}</Code>

预期：

```text
2
True
['basics', 'practice', 'python']
['sql']
['python']
['basics', 'practice', 'python', 'sql']
0
```

开头写了两次 `python`，但它是同一个成员值，因此长度为 2。不要靠打印原集合得到的偶然顺序安排界面，也不要用集合保存需要保留重复和先后关系的学习记录。集合适合哪种业务含义，比背三个符号重要。

### 10.2 为什么列表不能作为集合成员？

集合成员和字典键需要**可哈希**。在这里先理解必要约束：对象要能提供生命周期内稳定的哈希值，并且相等的对象必须具有相同哈希值，容器才能按相应规则组织和查找成员。我们不需要计算这些数字，也不需要提前实现类的方法。

本章使用的 `str`、`int` 可以作为键或集合成员；`list`、`dict`、`set` 不可以。元组只有在每个元素都可哈希时才可哈希，所以“元组自身不可变”还不足以保证带列表的元组能放进集合。不要把“不可变”和“可哈希”当成完全等价的术语。

故意失败的文件：`errors/unhashable_member.py`。

<Code language="python">{getContainerExample('errors/unhashable_member.py')}</Code>

没有正常输出；第 2 行产生 `TypeError: unhashable type: 'list'`。代码尝试加入的是列表 `["python"]`，不是字符串 `"python"`。如果需求是一个标签，传入那个字符串即可；不要为了过关随意把任意对象变成文本。

同样，拿列表作字典键也会得到 TypeError。这与 JS Set 可以按对象身份保存数组对象的用法不同，不能把“JS 能放进去”当作 Python 的许可。

另外，成员去重依赖相等关系，不只是外观拼写。L01 已经解释过 `True == 1`，因此集合不会把这两个值当成两个独立成员；字典也不能靠它们区分两个不同键。本章用同类字符串标签，避免把布尔状态和编号混为一类。依据：[集合类型](https://docs.python.org/3.13/library/stdtypes.html#set-types-set-frozenset)、[hashable 术语](https://docs.python.org/3.13/glossary.html#term-hashable)、[sorted](https://docs.python.org/3.13/library/functions.html#sorted)。

### 哪些关系独立，哪些关系有意共享

| 关系 | 设计意图 |
| --- | --- |
| 模板、第一份任务、第二份任务的外层字典 | 三份不同的字典，改标题或时长不污染模板 |
| 三个字典的 `tags` 列表 | 三份不同的列表，改一份标签不影响另两份 |
| `board[0]` 与 `first` | 同一份任务字典，从看板修改后，`first` 应看到变化 |
| `board[1]` 与 `second` | 同一份任务字典，不是在放入列表时自动复制 |

所以最后两个数字是 `40` 和 `25`：从看板修改第一份任务，`first` 看到 40，而模板保留 25。我们不是追求所有对象永远互不关联，而是在设计上区分**需要共享的任务本身**与**不该共享的草稿标签**。
