## 1. 數據庫有一個 user_id，不代表請求來自這個人

D 系列為了演示關係和事務，曾讓調用者填寫 owner_id。那是明確的教學輸入，不是認證。任意客戶端都能改 JSON；TypeScript 類型、隱藏按鈕和 CORS 都不能證明身份。本章把“誰在調用”從請求體移到服務驗證過的憑證上。下一章才決定這個人有權操作哪些對象。

## 2. 先分清四樣東西，再跟隨一次登錄

```text
password -> Argon2id verify -> active user
                                  |
                     random bearer returned once
                                  |
DB: token digest + user_id + auth_version + expiry
                                  |
next request: Bearer -> digest lookup -> user/version/expiry checks
                                  |
                         authenticated actor
```

**用戶記錄**表示賬號，不是一次請求。**密碼**是用戶知道的長期秘密。**密碼哈希**讓服務器能驗證密碼而不保存明文；它不是可以解密回原密碼的密文。**會話令牌**是登錄後臨時持有的 Bearer 憑證：誰拿到它，誰就可能代表該會話發請求，因此不能把它當成普通調試字符串。

瀏覽器路由狀態中的 loggedIn=true 只是 UI 狀態。服務必須獨立驗證每條受保護請求；前端不顯示退出按鈕、客戶端忘記清掉令牌，都不應該改變服務端撤銷結果。客戶端收到一次登錄 200，也不意味著它永久擁有身份，更不意味著可以訪問別人的項目。

## 4. Argon2id 的工作不是“把密碼快速變成一串字符”

<Code language="python">{getIdentityExample('security.py')}</Code>

閱讀這個完整模塊時先看 hasher、password_matches、login，不必一次記住每個函數。PasswordHasher 來自成熟的 argon2-cffi 庫，明確選擇 Argon2id；每次 hash 由庫生成隨機鹽。鹽、算法版本、內存/迭代參數和結果一起編碼在保存的字符串中。驗證時把這個編碼結果和候選密碼交給 verify，不自己拆字符串、比較自算密碼哈希或設計加密算法。

這裡固定 m=65536 KiB、t=3、p=4，採用該庫文檔中的低內存配置量級。內存與計算成本用於提高離線猜測成本，也會佔用你的服務器資源：參數不是越大越好，更不是吞吐承諾。上線前必須在目標機器測量，並結合併發預算與限流。兩個用戶選擇同一個密碼應得到不同哈希；本章實際測試了這一點。

成功驗證後檢查 check_needs_rehash，必要時用當前參數重新哈希。此時才有明文密碼可用，不能從舊哈希“升級計算出新密碼”。這裡只改變哈希編碼策略，不把參數升級等同於用戶改密；真正改密會提高 auth_version。

未知賬號也驗證一個啟動時生成的 dummy hash，避免“沒有用戶就立即返回”的明顯分支差異；**不承諾端到端恆定耗時**。正確結構下的未知賬號、錯誤密碼、停用賬號都返回同樣的 401。格式不合法仍可返回脫敏的 422；不能把所有失敗都混成數據庫異常。

<details>
<summary>解釋性答案：為何密碼不能用 SHA-256，而會話令牌摘要卻可以？</summary>

人選的密碼可能可猜，快速散列會讓離線嘗試便宜；需要成熟的帶鹽、可調成本密碼哈希。會話令牌由 secrets.token_urlsafe(32) 生成，含 32 個隨機字節，不是短密碼或 user_id。對它做 SHA-256 用於數據庫查找與避免保存原令牌，並沒有自造密碼哈希算法。數據庫摘要也不是可直接提交的 Bearer，入口還檢查原令牌格式。不過數據庫洩露仍是安全事件，不能因只存摘要就取消數據庫訪問控制和備份保護。

</details>

## 5. 每次請求重新建立身份，不緩存“上次登錄成功”

login 先在事務中鎖定用戶，驗證密碼與啟用狀態，產生隨機令牌，保存摘要及當時的 auth_version，提交後才返回 access_token。默認壽命 900 秒，可配置範圍 60–3600 秒。本例使用應用的 UTC 時鐘，生產多實例仍需時間同步；使用 UTC 不會自動修復錯誤的機器時鐘。

authenticate 按順序執行：解析 Bearer 格式、對原令牌求摘要、查會話、鎖用戶、重新讀取會話，然後檢查啟用狀態、revoked_at、到期時間和版本一致性。任何失敗都得到通用 401，並帶 WWW-Authenticate: Bearer。查到摘要不是最後一步：數據庫裡保留著過期或已撤銷記錄也必須拒絕。

為什麼鎖順序寫進代碼？普通請求取用戶共享鎖，改密/全部撤銷取用戶排他鎖；再按用戶、會話、項目、任務的順序取得後續鎖。這樣撤銷會等待已經開始並持鎖的授權操作結束，提交後到來的請求看見新版本。它不是“讓已經發出的響應倒流回來”，也不是無代價的併發優化。會話先做一次無鎖定位，再在用戶鎖之後重新讀取，避免把定位時的舊狀態當最終判斷。

每個請求使用自己的 Session 和事務，絕不在線程之間共享 Session。engine 是連接池入口，不是用戶會話；auth_sessions 是業務表。READ COMMITTED 在引擎配置中明確寫出，SQL 參數隱藏且 echo=false。不要混淆三種“會話”。

## 8. 用不洩露令牌的真實客戶端走完生命週期

另開終端，進入同一實驗目錄。客戶端固定請求迴環地址，通過 `ProxyHandler({})` 顯式禁用環境代理，拒絕跟隨重定向，用 getpass 讀密碼，將令牌寫入模式 0600 的本地會話文件，不打印原令牌。**不要 cat 這個文件，也不要提交或打包它。** 它是終端實驗設施，不是建議瀏覽器把令牌長期放進 localStorage。僅把 URL 寫成 127.0.0.1 不夠：urllib 默認會讀取 http_proxy，原本發給本地的密碼也可能先到代理。迴歸測試設有值的代理環境、去掉 no_proxy，用自建迴環代理/目標證明目標收到請求而代理為 0，重定向目標也為 0；不能假定操作系統默認會繞過代理。

<Code language="python">{getIdentityExample('client.py')}</Code>

```bash
uv run --locked python client.py --port 8061 --session .session-alice.json login Alice
uv run --locked python client.py --port 8061 --session .session-alice.json request GET /users/me
cp -p .session-alice.json .session-before-change.json
uv run --locked python client.py --port 8061 --session .session-alice.json change-password
uv run --locked python client.py --port 8061 --session .session-before-change.json request GET /users/me
```

登錄成功為 200，公開用戶讀取為 200，改密為 204 且正文為空，舊副本再請求為 401。客戶端改密成功會刪除當前本地令牌文件；服務端提高 auth_version 才是真正讓所有舊令牌失效的原因。用新密碼重新登錄後再試兩種撤銷：

```bash
uv run --locked python client.py --port 8061 --session .session-alice.json login Alice
uv run --locked python client.py --port 8061 --session .session-alice.json request POST /auth/logout-all
uv run --locked python client.py --port 8061 --session .session-alice.json request GET /users/me
```

最後一步應為 401。單會話撤銷路徑是 /auth/logout，只設置當前會話 revoked_at，不影響另一個有效會話；/auth/logout-all 提升賬號版本，連發起操作的令牌也失效。密碼不是令牌，改密後不能繼續把原令牌當新密碼使用。

<details>
<summary>生命週期推演答案：停用後再啟用，會不會復活舊令牌？</summary>

不會。管理員 disable 把 is_active 置 false 並提升 auth_version；enable 再提升版本。舊會話即使沒有過期、revoked_at 仍為空，也因版本不匹配而失敗。啟用後必須重新登錄獲得新版本會話。僅刪除瀏覽器裡的令牌不能替代服務端撤銷；僅改密碼哈希而不檢查版本也不能自動撤銷已經簽發的令牌。

</details>

## 10. 獨立重建與會話數量變式

**獨立重建：** 在新目錄只帶環境和遷移文件，按本章契約自己寫輸入/公開模型、哈希與會話服務、HTTP 入口和受控賬號命令。不要導入參考 app。驗收必須包含錯誤密碼、未知用戶、篡改、過期、單次/全部撤銷、改密、停用再啟用、錯誤脫敏與真實重啟。解釋每條 SQL 讀取為什麼不能被客戶端狀態替代。

**變式：** 增加 GET /users/me/session-count，只統計當前用戶、當前認證版本、未撤銷且未到期的會話。不能返回摘要或令牌，也不能把數據庫所有歷史會話數量當答案。兩個有效登錄應計 2，撤銷其中一個後計 1；全部撤銷並重新登錄後計 1，Bob 的會話不能影響 Alice。
