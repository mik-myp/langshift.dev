## 1. Cross one learning boundary at a time

You already organize frontend projects, write JavaScript, and integrate APIs. You do not need another introduction to programming itself. That experience does not, however, automatically explain Python's names, syntax, or execution model, and it does not imply that you have implemented a backend.

This chapter therefore does **not** begin by scaffolding a complete Python project. Its smaller but substantive goal is to **create a Python file, explain every line, run and modify it, and repair an error you deliberately introduce**.

Later chapters build language knowledge, files and modules, testing and environments, then HTTP, FastAPI, databases, and deployment. The destination is unchanged; its requirements simply do not become prerequisites for starting.

### Prerequisites, outcomes, and exclusions

| Item | This chapter's contract |
| --- | --- |
| Prior knowledge | Using an editor and terminal; the general JS ideas of assignment, strings, and function calls |
| New knowledge | Python names versus strings, assignment, calling `print`, sequential execution, running a `.py` file, and locating simple errors |
| Independent outcome | Write a similarly small script without the answer, predict its output, and explain and fix a failure |
| Not yet required | `import`, defining functions, reading JSON files, virtual-environment mechanisms, lockfiles, pytest, entry guards, or API servers |

These excluded subjects have not been removed from the curriculum. They will receive full treatment after their prerequisites. **Exercises and exit checks in this chapter will not quietly require them.**

## 2. Understand three lines before dealing with installation

Do not run anything yet or open a collection of configuration files. This is the complete program, saved as `first_steps.py`:

<Code language="python">{getFirstScriptExample('first_steps.py')}</Code>

It is expected to print two lines:

```text
Hello!
Python
```

“Expected” matters: explain the result from the code first, then run it to check your prediction. A terminal without errors is not sufficient evidence of understanding.

### 2.1 `course = "Python"`: assign a value to a name

`"Python"` is a string literal representing text. Its surrounding quotes are source-code syntax, not part of the text itself.

`course` is the name we chose. After the assignment executes, later code can use this name to retrieve the corresponding value. This assignment does not start with `let`, `const`, or `var`.

First establish the observable behavior: after assignment, `course` can be read; a different spelling is a different name. Mutable objects, copying, and scope are not prerequisites here. Subsequent chapters give those topics their own examples.

### 2.2 `print("Hello!")`: call an existing function

`print` is a Python built-in function; this example does not need to import it. Parentheses perform a call, and `"Hello!"` is the supplied content. Here it writes that text to standard output, visible in the terminal during normal local execution, followed by a newline.

**Calling an existing function** does not require **learning how to define your own function immediately**. Your understanding of JS calls helps; the new task is to understand this particular Python call.

### 2.3 `print(course)`: retrieve the value, then output it

There are no quotes around `course`. Python looks up that name's value and passes the value to `print`. The result is `Python`, not `course`.

The distinction can be checked independently:

```python
course = "Python"
print(course)
print("course")
```

Expected result:

```text
Python
course
```

The second line reads a name; the third directly uses a literal. Similar-looking text in an editor does not necessarily mean the same thing to Python.

### 2.4 Trace execution instead of memorizing output

| Position | What happens | New output |
| --- | --- | --- |
| Line 1 | The name `course` receives the value `"Python"` | None |
| Line 2 | `print` is called with `"Hello!"` | `Hello!` |
| Line 3 | The value of `course` is retrieved and passed to `print` | `Python` |

Saving an assignment does not automatically display its value. We are executing a script file and explicitly printing what we want to observe. Do not transfer the browser developer console's interactive feedback directly to file execution.

Blank lines can separate code and produce no output. Outside a string, `#` can start a line comment. The last line below is a note for the reader:

```python
course = "Python"
print(course)
# This comment does not print anything.
```

## 3. Use JS experience without erasing differences

This comparison is for reading syntax. The required execution work happens in your local terminal, not in the webpage editor's runtime.

<PythonEditor title="Read a name and print its value" compare={true} canRun={false}>
```javascript !! js
const name = "Python";
console.log(name);
```

```python !! py
name = "Python"
print(name)
```
</PythonEditor>

Both print `Python` in this example. That does not make `const` equivalent to Python assignment or make every feature of `console.log` and `print` identical.

A Python name can be assigned a new value later. Observe that behavior first:

```python
course = "Python"
print(course)
course = "FastAPI"
print(course)
```

Output:

```text
Python
FastAPI
```

The first output occurs before reassignment. A later assignment does not go back and change text already printed. These are ordinary strings: **writing `"FastAPI"` does not install a framework or start a server.**

## 4. What executes a `.py` file?

In frontend development, an editor changes files while a browser or a runtime such as Node.js executes code. Distinguish these responsibilities for Python too:

- **Editor:** creates, changes, and saves source. Syntax highlighting does not mean execution happened.
- **Python language:** defines what these statements mean and how they are written.
- **Python interpreter:** the program that reads and executes the code. The local course uses CPython, one implementation of Python.
- **Terminal:** lets you issue startup commands and see output or errors. Shell commands are not Python source.

The minimal sequence is:

```text
Save first_steps.py
        ↓
Start the Python interpreter in the terminal and name the file
        ↓
The interpreter reads the file, checks syntax, then executes it
        ↓
Observe output or an error in the terminal
```

`.py` is the conventional extension for Python source. Renaming a JavaScript file to that extension does not translate its contents into Python.

Some documentation shows an interactive Python session with a `>>>` prompt. That prompt is not source to paste into your file. This chapter consistently runs files rather than switching between execution modes.

## 5. Prepare only what this chapter needs

The course uses **CPython 3.13** as its teaching baseline, not as a claim about the latest release. This script has no third-party Python dependencies and needs neither project configuration nor FastAPI.

We use **uv to obtain and select the interpreter**, reducing differences between machines. Here it is a running tool: understand each command's purpose without learning the full dependency-management workflow. If uv already works, skip its installation.

### 5.1 Install and check uv

Verify installation commands against the [official uv installation guide](https://docs.astral.sh/uv/getting-started/installation/). The following commands fetch and execute an official installer. Follow your organization's software policies on managed devices; do not apply this pattern to an untrusted address.

**macOS / Linux terminal:**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows PowerShell:**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

After installation, open a new terminal and run:

```bash
uv --version
```

A uv version shows that the new terminal can find the tool. If the command is still missing, follow the installer output and check your terminal/path setup. Python source has not started executing, so editing it will not fix this failure.

### 5.2 Obtain and identify the interpreter

Run these lines in the terminal, not inside a `.py` file:

```bash
uv python install 3.13
uv run --no-project --python 3.13 python --version
```

The first prepares Python 3.13 and can reuse an existing installation. The second selects that interpreter and asks it for its version. Expect a result beginning with `Python 3.13.`; the patch number may differ.

Initial installation may require network downloads. Download progress and uv diagnostics come from the tool, not from your program. Once installed, this particular script performs no network requests.

### 5.3 Create an ordinary practice folder

From a location where you keep exercises, run:

```bash
mkdir js2py-first-steps
cd js2py-first-steps
```

This creates and enters a folder; **it does not scaffold an application**. If it already exists from an earlier session, enter it without deleting and recreating it.

Open that folder in your editor, create `first_steps.py`, enter the three lines from section 2, and save. Make sure it was not saved as `first_steps.py.txt`, particularly on systems that hide filename extensions.

Alternatively, [download the chapter files](/learning-assets/js2py/u00-first-script.zip), extract them, and open a terminal in the resulting `u00-first-script` folder. Writing and downloading are two ways to obtain the same file, not two required tasks. Downloading does not replace understanding. Leave the `solutions` folder closed until you attempt the independent exercise.

## 6. Run the file and understand the command

With `first_steps.py` in the terminal's current directory, run:

```bash
uv run --no-project --python 3.13 python first_steps.py
```

Read the command in parts:

| Part | Role here |
| --- | --- |
| `uv run` | Start a command through uv |
| `--no-project` | Do not use a uv project in the current or parent directories as the execution context |
| `--python 3.13` | Select a Python 3.13 interpreter |
| `python` | The program to run is the Python interpreter |
| `first_steps.py` | The file for that interpreter, located relative to the terminal's current directory |

This is not a parameter table to memorize. A fixed path avoids ambiguity about which Python your machine selects. **Do not run `uv init`, create a lockfile, or install a test framework for this lesson.** A later engineering chapter will explain why environments and dependencies need isolation.

Normal program output:

```text
Hello!
Python
```

Next, change the first line's `"Python"` to `"FastAPI"`, **save**, and run the same command again. The second output line changes; the first remains `Hello!`. Restore the original file afterward.

If nothing changes, compare three things: the file saved by the editor, the terminal's current directory, and the file named in the command. Do not immediately reinstall Python; you may be editing and executing different files.

## 7. Two reversible failure experiments

Make a backup copy of `first_steps.py` inside this practice folder. Change one thing at a time, observe the result, and restore it before the next experiment. Leave other projects alone.

### 7.1 Misspelled name: valid syntax, failed lookup during execution

Change only `course` in the last line to `cours`:

```python expected-error=NameError
course = "Python"
print("Hello!")
print(cours)
```

You will see `Hello!`, followed by an error containing `NameError`. The first two lines have executed. Execution cannot proceed normally when the third line tries to retrieve a name that has not been assigned.

Read the error type and message at the end, find your own filename and line number above it, then inspect that source line. `course` and `cours` are different names. Fix the spelling; do not install a package named `cours`.

You do not need to memorize every traceback field. Locate your own file and understand this failure's immediate cause. After repairing it, rerun and check that both normal output lines return.

### 7.2 Missing quote: the file cannot be parsed before execution

Remove the closing double quote on the first line:

```python expected-error=SyntaxError
course = "Python
print("Hello!")
print(course)
```

This produces `SyntaxError`, and neither `print` in the file executes. The interpreter finds invalid syntax before it starts executing the statements.

Exact wording and caret placement can vary between patch versions. You do not need to memorize them. Restore the quote, save, and rerun to complete the experiment.

### 7.3 Identify the failing layer first

| Symptom | Check first | Do not start by |
| --- | --- | --- |
| `uv` command not found | Installation and whether a new terminal can find it | Editing Python business logic |
| Cannot open `first_steps.py` | Directory, filename, and accidental `.txt` extension | Installing a Python package |
| `SyntaxError` | Highlighted source, including quotes and parentheses | Switching frameworks |
| `NameError` | Whether that name was assigned and spelled consistently | Reinstalling the environment |
| Old output remains | Saved file and the actual file being executed | Assuming program output is a cache problem |

This is a guide to these experiments, not an exhaustive explanation of every error with the same name. Preserve the actual command and message rather than guessing from an error type alone.
