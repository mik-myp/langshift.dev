## 1. 这是一次独立交付，不是最后一份实现答案

你已经能理解后端教程，不代表在没有参考实现时还能做出可维护的选择。本章不提供表结构、路由设计、迁移命令、事务算法或完整后端代码。你需要在自己的协作任务 API 上完成一个受控的新需求，并能解释为什么选择它、怎样发现自己做错、以及如何恢复。

前置是 **O06 的能力与证据**，不是“页面能打开”：已有项目必须有隔离恢复、访问控制和受控发布基础。如果前章缺环境、未做恢复或尚未通过主线验收，G01 可以阅读和准备需求，但不能替它补上已验收标签。章节状态由主线统一控制。

本任务以“任务评论”作为 capstone 中标签扩展的等价受控变式，不要求两个功能同时实现，也不降低 capstone 的交付门槛。它带来的新复杂度是：同一对象上的作者与项目 owner 权限不同；评论有并发版本、撤回状态和重复请求；新数据又必须经历升级、发布回退和恢复。不是多加一个 CRUD 表就算结束。

下载 [G01 需求与证据包](/learning-assets/js2py/g01-graduation.zip)，进入 `g01-graduation`。包内只有产品契约、合成场景数据、证据/评阅模板、评分规则和**材料格式检查器**；没有可以直接上线的后端参考答案。所有学生场景默认 `not_run`，没有虚构试用数据。

开始前先阅读[贯穿项目指南](/zh-cn/docs/js2py/project-integration)，在自己的产品仓库中标记当前 V0—V4 检查点。G01 的新需求必须建立在已经通过的迁移、权限、发布和恢复证据上；不能从空的需求包直接跳过前面阶段。

## 2. 四件事必须各有证据，不能互相代替

| 结论 | 谁提供什么证据 | 不能据此推导什么 |
| --- | --- | --- |
| 课程内容完成 | 作者完成正文、资源、链接和主线所要求的审查 | 读者已掌握，或所有前章环境都已跑通 |
| 作者参考验证 | 作者在声明的环境实际执行自己拥有的样例/材料检查 | 学生的另一套实现也正确 |
| 学生毕业 | 独立项目证据、负向场景、恢复、现场变更与人工评阅 | 可不设限制地面向全网运营 |
| 真实公网运营 | 明确主机/域名/密钥归属、HTTPS、安全发布、预算、监控与真实使用证据 | 一次通过就永久安全、无限容量或无需维护 |

本章作者只验证需求包及格式检查器。未运行你的项目，没有代你签发毕业结论，也没有主机、域名和部署凭证可以证明公网上线。受邀试用也不是公共注册：参与人数、数据风险和运维承诺不同。四种状态在模板中分开保存，不能用一个 `passed=true` 抹平。

它可能属于别的提交、只测了 happy path、绕过了真实数据库，甚至只运行了格式检查器。评阅需要把版本、环境、输入、结果和持久状态关联起来，再看独立变式与恢复。截图可以辅助定位记录，但不能替代原始可复核材料；作者验证、学生验证与线上证据必须分别署明来源。

## 3. 新需求：评论属于任务，作者身份不能被重写

逻辑上，每条评论有身份、所属任务及项目、服务器确定的作者、纯文本、创建时间、成功修改后的版本，以及撤回状态。评论正文为 1–1000 个 Unicode 码点，不能只含空白，NULL 不合法；不支持富文本、附件、嵌套回复或实时推送。逻辑事实不是给定物理表设计：字段如何存、接口如何表达、冲突怎样响应，必须由你论证。

当前有效项目成员可以读、列出和创建评论，也可以修改或撤回自己尚可见的评论。项目 owner 可以撤回本项目任何评论，**不能改写其他作者的正文**。被移除的成员，即使仍持有未过期旧凭证或曾是作者，也不能再读取或操作该项目评论；其他当前成员仍能看到历史作者归属。停用账号与未登录者不能因“成员行还在”获得访问权。

撤回后的普通读取只显示墓碑式元数据，不暴露原正文；列表、详情、历史、导出和日志不能成为绕路。撤回后编辑必须失败，不允许旧请求让正文复活。内部保留还是清除原文由你选择并说明维护与备份后果；不要声称能从已经存在的所有备份中追溯性擦除内容。

## 4. 数据、角色与失败不能只用一个 Alice 演示

合成数据包含两个项目、两个 owner、普通成员、已移除成员、外部用户和停用用户；同一人可能在另一项目仍有权限。逻辑 ID 只用于描述场景，你需要提供它们与自己模型的对应关系，不必把它们变成数据库主键类型，也不能导入生产数据覆盖真实用户。

<Code language="json">{getGraduationExample('fixtures/actors-and-data.json')}</Code>

最有区分力的证据往往是“正确登录但对象不属于他”：把别的评论 ID 与自己的项目路径组合；用作者字段冒充别人；成员被移除后重放旧请求。仅测试 401 说明你检查了登录，不证明你检查了每个对象边界。被拒绝之后还必须检查没有修改、没有泄漏正文，不是只看一个状态码。

同样，输入边界不是选一个空字符串就够：空白 Unicode、NULL、最大长度、超长一个码点，以及包含标记字符的纯文本都属于数据契约。前端不需要重新制作复杂界面；API 与必要的展示约定可以表达纯文本语义，不得把 HTML 字符串当可执行富文本。

## 5. 并发、重复请求与未知结果是三类不同问题

两个编辑基于同一旧版本，不能都静默覆盖成功；你要声明冲突表现，并用独立请求证明实际交错。编辑与撤回相遇时，已提交的撤回不能被迟来的编辑逆转。成员移除提交后才开始的请求必须拒绝；对已经在执行中的请求，你必须声明一致的边界并测试，不可事后挑有利的一次输出。

重复创建的业务契约是：在至少 24 小时的保留窗内，同一已认证操作人、同一任务、同一请求身份和相同内容代表一条逻辑评论，并返回同一身份；同一范围的请求身份换了正文应冲突，原评论不变。不同操作人或任务的请求不得互相取到缓存结果。过期后的行为由你选择，但必须有界、可解释、可测，而不是承诺永久 exactly-once。

重放仍须满足当前权限：成员被撤销后，不能因为“以前请求成功过”而读到旧响应。响应丢失也不意味着数据库没提交；S16 专门要求验证已接受但客户端没拿到响应时，再次请求不会制造重复评论。这是产品要求，不是让你复制某个幂等中间件。

故障证据要指出失败发生在哪里、哪些状态应该保留、哪些不应存在，以及后续合法操作如何恢复。只写“捕获异常”没有说明数据库剩下什么；只看最终行数也可能漏掉曾经对外承诺成功却没有记录的情况。外部结果和持久状态需要能彼此解释。

<Code language="json">{getGraduationExample('scenarios.json')}</Code>

一份有说服力的运行记录能回答：哪个提交/迁移版本，在什么独占环境，哪两个主体提交了什么经过脱敏的输入，实际返回什么，后来数据库或服务状态如何，以及怎样重新观察。并发记录还要能证明发生了交错，而不是顺序执行两次后称其为竞争。

场景 `pass` 是你的声明，评阅者仍要审查；`fail` 保留反例，`blocked` 说明缺少什么和谁能解除，`not_run` 不编造时间和输出。完整测试数量、覆盖率、截图多寡都不能替代关键负向条件。稳定分页只要求不变数据集的顺序明确；发生插入/删除时的边界必须说明，不能拿确定排序冒充跨请求快照。

<details>
<summary>核对区二：两次创建都返回成功、最终只有一行，是否已证明重复请求正确？</summary>

还不够。需要确认是同一范围和请求身份，返回的是同一评论身份，原正文没有被不同载荷覆盖，另一用户拿不到该响应，撤权后的重放仍被拒绝，且响应丢失路径能恢复。最终一行也可能来自后续补删或误合并；只有能解释接受结果和持久状态的一组证据，才覆盖这个产品契约。这里不给实现算法。

</details>

## 7. 兼容升级、回退与恢复必须经过已有数据

空库能启动不证明升级安全。已有用户、项目、成员和任务应保留身份和允许的原操作；旧任务初始没有评论，不能捏造默认作者。带有任意评论（包括墓碑）的任务不允许物理删除；无评论任务原删除行为保留。通过删除项目绕过该规则同样不可接受，具体项目删除政策要与你的选择一致并留证。

回退证据必须写清“哪个应用版本与哪个结构版本兼容”。如果旧版本不能理解新状态，允许你声明安全冻结或受控回退条件，但不允许靠盲目 downgrade 丢掉已接受评论，再把启动成功说成恢复成功。兼容性和数据保留承诺需要实测，不是为演示设计的空数据库结论。

恢复则要求把备份真正恢复到另一个明确隔离的目标，核对关系、版本、撤回隐私和重复请求行为，并记录恢复用时与可接受/实际数据丢失窗口。只恢复表数量可能漏掉“撤回正文重新可见”或“请求去重状态没恢复”。恢复时刻之前的备份可能含旧内容，保留政策和恢复后的数据窗口必须解释，不能假装备份只影响性能。

没有批准的目标、账号、预算和 O06 证据时，受邀试用记为 blocked。条件具备后限 2–5 名受邀者、非敏感数据，并提交至少一次可追溯的匿名反馈及验证过的调整。不得虚构参与人或把本地回环地址标成公网 HTTPS。

## 8. 评分要有硬门槛，不能用漂亮文档抵消越权

<Code language="json">{getGraduationExample('rubric.json')}</Code>

六项评分合计 100，参考合格线为 80；24 个场景对应的必需行为都要有人工审查通过的证据，hard_gate 标记为 false 也不是豁免。硬门槛失败不能抵分，O06 必须独立核实。越权、数据丢失、伪造证据、凭证泄漏、无法解释独立变更，都不能用额外界面或更高覆盖率抵消。评分器不是毕业自动机，最终决定属于评阅者。

独立能力允许查官方文档和使用辅助工具，但必须说明哪些工作得到协助。现场变更可以收紧“新评论”长度而保留历史长评论读取；评阅的是你能否识别受影响的契约、调整验证并说明兼容性，不是在限定时间内盲写最多代码。另需解释一个自己遇到的真实问题：初始判断、反证、定位材料、修复结果和仍未解决的限制，不能把别人替你写的结论背下来。

## 9. 格式检查器故意不能替你毕业

材料包没有外部 Python 依赖，不需要 pytest、数据库、Docker 或前端构建。可选检查器仅使用标准库，本次以 Python **3.13.15** 验证；只阅读 JSON/Markdown 时连 Python 都不需要安装。以下命令在包目录执行，`python3 --version` 应先确认当前解释器。

```bash
python3 --version
python3 check_evidence.py templates/evidence.json
python3 -m unittest discover -s tests -v
```

```text
{"artifact_files_verified": false, "backend_verified": false, "format_valid": true, "graduation_awarded": false, "public_operation_verified": false, "scenario_status_counts": {"blocked": 0, "fail": 0, "not_run": 24, "pass": 0}}
```

返回 0 只说明材料格式合格：场景 ID 齐全、声明分离、引用格式完整、路径不是越界路径、时间等字段可解析。它**不打开证据文件核对哈希，不认证报告真实性，不调用后端，不扫描所有秘密，也不确认评分或部署**。测试特意在内存构造一份虚构但格式正确的报告，证明它仍可能通过格式检查且 backend_verified 永远是 false。这个单元测试不是虚构上线证据。

作者实际运行了 15 项材料单元测试，包括空模板、缺场景、重复 ID、无引用的 pass、越界路径、虚假时间、缺原因的 blocked、悬空合成数据和损坏 JSON。未运行任何学生项目的 24 项业务场景。不要把两种数量合并成“39 项后端测试通过”。

## 10. 暂停点记录证据，不预设你的实现顺序

可以按需求理解、设计评阅、行为观察、交付/恢复证据、独立答辩等状态暂停，但这些是材料成熟度，不是指定先建哪个表、再写哪个接口的开发路线。你可以用自己的开发顺序，只要每项承诺最终都可核对。

<Code language="json">{getGraduationExample('templates/checkpoint.json')}</Code>

每次暂停至少记下代码/结构版本、独占目标、最后实际命令、最后已证实事实、未解问题、下一条要收集的证据及已停止的资源。恢复时先确认当前状态与记录是否一致；不要因为“上次应该通过了”跳过检查。缺环境要保留 blocked 及责任人，缺测试结果要保留 not_run，而不是填一个预期的成功值。

证据包可以引用相对路径与摘要以便评阅定位，但请先脱敏；不要上传完整环境变量、Token、连接密码、真实用户正文或私钥。运行日志的关联 ID 应帮助还原问题，不应成为另一个数据泄漏入口。格式检查器不是保密审计，提交者仍负责人工检查。

## 11. 本章交付界限与必要来源

学生最终交付自己的模型与接口决策、迁移审查、实现和回归、失败与并发记录、发布回退与隔离恢复、受邀反馈、维护预算/限制，以及独立问题说明。可下载包仅帮助表达这些要求，不能代替产物。课程内容完成、作者材料验证、学生毕业和真实公网运营仍是四个分别判断的结论。

核验日期 **2026-09-28**。必要官方依据仅用于澄清既有验收边界，不引入新架构：

- [OWASP API1 对象级授权](https://owasp.org/API-Security/editions/2023/en/0xa1-broken-object-level-authorization/)：登录成功不等于有权访问给定对象。
- [PostgreSQL 18 SQL Dump 与恢复](https://www.postgresql.org/docs/18/backup-dump.html)：产生备份和实际恢复验证是不同事情；本章不给恢复实现步骤。
- [HTTP 语义中的幂等方法](https://www.rfc-editor.org/rfc/rfc9110.html#name-idempotent-methods)：重复请求效果与方法语义有关，创建评论的产品去重承诺不会由一个 POST 方法名自动获得。

未完成、未声称完成：学生后端、学生业务场景运行、O06 代验收、毕业评定、真实受邀使用、公网发布或长期运营。本章可审查的是要求与材料工具本身，其他状态由真实证据和主线评阅决定。
