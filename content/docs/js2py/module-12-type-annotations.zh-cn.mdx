## 1. 什么时候值得把数据和行为放在一起？

此前用字典保存任务、用函数修改任务，没有错，也不会因为出现 class 就自动落后。当多个函数都依赖同一组字段和规则时，把一份状态与围绕它的行为组合成对象，可以让调用者更容易找到正确操作。但类不会自动产生数据库、身份权限或不可破坏的约束。

本章把“任务完成”做成一个可以追踪的小模型。你需要理解对象里有什么、多个名字是否指向同一对象、谁允许修改状态，而不是学完语法就把每个字典改成类。

## 2. 从已有字典方案比较，而不是从术语开始

任务有 title、minutes、done。原来可以写 mark_done(task)，从字典取 done，必要时更新，再返回是否发生变化。对象版本写 task.mark_done()。关键不是句点更漂亮，而是状态和行为的关系更直接；是否减少错误还要看规则设计和测试。

类描述怎样建立及操作某类对象；实例是一次创建得到的具体对象。Task("Read", 30) 和再创建一次相同参数的 Task，不是同一个实例。让另一个名字指向已有 task 则没有复制。不要把“字段内容相同”和“身份相同”混为一谈。

Python 类不是 TypeScript 的 interface：类定义和实例都在运行时存在。Python 类也不要简单等同于 JavaScript 原型对象；本章先理解可观察的创建、属性和方法，不假定你已经会任何后端框架。

## 3. self 是收到的实例，不是隐藏的全局变量

下面是可以独立运行的最小例子：

```python
class Counter:
    def __init__(self, start: int = 0) -> None:
        self.value = start

    def increase(self) -> int:
        self.value += 1
        return self.value


first = Counter()
second = Counter(10)
print(first.increase(), second.value)
print(Counter.increase(first))
```

```text
1 10
2
```

通常的实例方法访问会把实例绑定为第一个参数。first.increase() 在这里与 Counter.increase(first) 做同一件事；self 是约定的名字，不是特殊关键字。与 JS 的 this 绑定经验不同，方法定义里明确写出接收实例的参数，但通过实例调用时不再手动传它。

`self.value = start` 在当前实例上设置属性；局部变量 value 与 self.value 不是一个存储位置。__init__ 在新实例建立后负责初始化，不应返回业务对象。本章不实现底层对象分配；把 __init__ 理解为初始化步骤就足够。

<details>
<summary>解释题答案：把 second = first 之后会发生什么？</summary>

两个名字引用同一个实例。经任何一个名字调用 increase 都改变同一份 value。重新构造 Counter(first.value) 得到的是另一个计数器；这两种操作不能只因初始数字相同就被称为相同的复制。

</details>

## 4. 初始化校验建立起点，不是永久封印

任务初始化要检查非空白标题、普通非负整数 minutes，以及严格 bool 的 done。验证成功后才把结果保存到实例。构造时失败意味着调用者拿不到这个正常构造完成的 Task；不要用默认零值偷偷吞掉失败。

mark_done 返回第一次变化是否发生，重复完成不重复计数；remaining_minutes 根据当前 done 计算，而不是再保存一个可能忘记同步的总计字段。很多状态错误来自维护重复信息，并非缺少继承层次。

不过 Task 的属性仍公开可写。构造通过后直接把 task.minutes 改成 -1，当前模型不会自动再次校验。使用方法是一种约定，不是安全沙箱。以后服务入口、数据库约束和业务操作各有责任；不能因为定义了一个“模型类”就停止验证。

## 5. 组合先问“拥有哪个容器，共享哪些对象”

Plan 持有任务列表，是“有多个 Task”，不是“是一种 Task”。它复制传入的外层列表，避免调用者清空自己的列表时意外清空计划。但列表中的 Task 实例有意共享，所以把 read 标为完成后，计划看到的剩余时间也变化。

这不是深复制，也不是把任务冻结成快照。画三个箭头：原列表指向 task，Plan.tasks 指向同一个 task，两个列表自身不同。若业务要求独立快照，必须另外定义复制哪些状态及后续更新的政策，不能只写 list(...) 就声称完成。

本章用普通 for 循环汇总，避免为了简写提前要求生成器表达式。Plan 也不是一个防御所有错误输入的公共 API：它约定接收 Task 列表，未实现任意对象转换。

## 7. 在使用 dataclass 前，先解释这一行 @

`@dataclass` 放在类定义上方，表示类创建后交给 dataclass 处理，再把结果绑定回类名。对于本章简单使用，可以理解为写完 class 后再做 `Estimate = dataclass(Estimate)`。它不是每次读取字段时执行的魔法。L13 会完整拆解装饰器的求值、包装与注册；这里先建立足够使用该库的局部机制。

dataclass 根据声明的字段生成常用方法，例如初始化、可读表示与字段比较。RawEstimate 故意没有校验：把字符串放进标为 int 的 minutes 仍能构造成功。Estimate 则在自动初始化调用的 __post_init__ 中明确验证，规则来自我们写的代码，不来自类型注解。

`field(default_factory=list)` 提供一个创建默认值的函数。未传 tags 时，每个实例各调用一次 list，得到自己的空列表；传 list 而不是 list()。但调用者显式传入列表时，默认工厂不负责复制它，所以 __post_init__ 再复制外层列表，并检查元素为文本。

不要直接用共享的 tags = [] 当实例默认值。本章 dataclass 会拒绝这种常见可变默认声明；普通类的类属性却可能悄悄共享，下一节会实际观察。__post_init__ 同样只守初始化阶段，之后直接 append 非文本值仍可能破坏约定。

## 13. 一手资料与模型适用范围

类帮助组织责任，但设计清楚的数据流、显式校验与行为测试仍是核心。一个只有字典和函数的清晰方案，通常好过一个状态归属不明的庞大继承树。
