## 1. 從兩條記錄，到數量會變化的數據

L02 的學習計劃只有兩條，我們可以直接訪問 `plans[0]` 和 `plans[1]`。現在想象三個變化：今天沒有計劃；明天有五條；有些已經完成，有些還沒有預計時長。繼續寫死下標不僅重複，而且會把“數據數量變了”變成程序錯誤。

本章要解決兩個問題：**哪些語句應該執行，以及同一套操作應該對哪些數據重複執行。** 這叫控制流。你熟悉 JS 的分支與循環，但 Python 的縮進、容器真值、遍歷方式和名稱綁定有自己的規則，不能只把花括號換成冒號。

## 2. 分支：冒號和縮進決定哪些語句屬於一起

### 2.1 先讀控制流，再記語法

我們先按預計分鐘數給一項任務分類。當前輸入保證是整數；如何處理來自外部的任意文本不在本節範圍。

文件：`branches.py`。

<Code language="python">{getControlFlowExample('branches.py')}</Code>

預期：

```text
Short session
Checked
```

按執行順序解釋：

1. 先把 25 綁定給 `minutes`。
2. `if` 檢查第一個條件，False 時繼續檢查 `elif`，即“否則，如果”。
3. 遇到第一個為真的條件，只執行它對應的縮進語句塊；同一條分支鏈中的後續條件不再檢查。
4. 如果前面都不成立，才進入 `else`；`else` 後沒有條件。
5. `print("Checked")` 已退回最外層縮進，因此無論選中了哪一支，正常執行都會來到這裡。

`if`、`elif`、`else` 這幾行以冒號結束。條件不必像 JS 一樣套在括號裡；需要分組時仍可用括號。使用四個空格表示一個縮進層級；四個空格是慣例，而**同一個塊的縮進一致**是語法要求。不要混用 Tab 與空格。

這不是視覺排版：把最後一行縮進到 `else` 內，含義就會變成“僅在長任務時打印 Checked”，即使沒有異常也已經改了程序。

先預測，再只修改第一行輸入：

| minutes | 分類輸出 | 為什麼 |
| --- | --- | --- |
| -1 | Invalid estimate | 先拒絕負數，後續分支不參與 |
| 0 | No time required | 0 是單獨的邊界，不被短時長分支吞掉 |
| 1、25 | Short session | 上界包含 25 |
| 26 | Long session | 前三個條件都不滿足 |

每一種還應打印 `Checked`。如果把 `minutes <= 25` 放在負數與 0 的檢查前面，後兩者也會先匹配它；分支順序表達業務優先級，不是任意排列的標籤。

### 2.2 多個 if 不等於一條 if/elif 鏈

以下是完整、獨立的對照：

```python case=separate_if
minutes = 0
if minutes == 0:
    print("Zero")
if minutes <= 25:
    print("Short")
else:
    print("Long")
```

預期：

```text
Zero
Short
```

兩個 `if` 都會分別檢查；`else` 屬於緊挨著它、同一縮進層級的第二個 `if`，不是第一個。規則互斥時適合一條鏈；多個條件可以同時成立時，獨立的 `if` 可能正是需要的行為。不要因為輸出多了一行就機械地刪除分支。

### 2.3 第一個失敗：沒有縮進，不會先打印一部分

以下是**預期語法失敗**，不是可交付腳本。可以單獨保存為 `missing_indent.py` 實驗：

```python expected-error=SyntaxError case=missing_indent
if True:
print("Inside")
print("After")
```

在執行任何一行之前，Python 就會報告 `IndentationError`，它屬於語法錯誤的一種；本例指向應有縮進的第二行，沒有標準輸出。補上第二行的四個空格、保留第三行頂格後，才會依次輸出 `Inside`、`After`。

缺冒號通常報告 `SyntaxError`；混用縮進可能報告 `TabError`。先核對冒號、塊的起點與退回的位置，再看業務條件。**能解析不代表邏輯正確**，下一節以後仍需通過輸入變化來驗證。

## 3. 真值與邏輯運算：空容器不是 JS 的空對象

### 3.1 條件不要求表達式本身就是 bool

Python 在條件位置判斷一個值的真值。`bool(value)` 可以把這種判斷顯式顯示為 True 或 False；這是轉換，不是在解析字符串中的英文詞語。

本章用到的假值包括 `None`、`False`、數值零、空字符串以及空的列表、元組、字典、集合。非空容器為真，即使裡面只放了 False；非空字符串 `"False"` 和 `"0"` 也都為真。

文件：`truthiness.py`。

<Code language="python">{getControlFlowExample('truthiness.py')}</Code>

預期：

```text
False
False
False
False
False
False
True
True
No tasks
```

`if tasks` 在此表達“列表裡有沒有條目”，不是“每一條任務是否合格”。`bool([False])` 為 True 正好提醒我們：容器是否非空，與條目的真假是兩個問題。

下面是靜態語法對照，使用本地腳本驗收，不依賴網頁運行器：

<PythonEditor title="空容器的真值差異" compare={true} canRun={false}>
```javascript case=truth_comparison
console.log(Boolean([]));
console.log(Boolean({}));
console.log(Boolean("False"));
```

```python case=truth_comparison
print(bool([]))
print(bool({}))
print(bool("False"))
```
</PythonEditor>

Python 輸出：

```text
False
False
True
```

JS 輸出：

```text
true
true
true
```

不能直接把前端 `if (items)` 的含義照搬過來；對 JS 數組你通常還需要看 `.length`，這裡 Python 空列表本身是假值。規則依據 [Python 真值測試](https://docs.python.org/3.13/library/stdtypes.html#truth-value-testing) 與 [MDN Truthy](https://developer.mozilla.org/en-US/docs/Glossary/Truthy)。

### 3.2 and/or 會短路，也可能返回非 bool 值

| 運算 | 求值過程 | 結果 |
| --- | --- | --- |
| `x and y` | 先判斷 x；x 為假就不計算 y | 假的 x，或計算得到的 y |
| `x or y` | 先判斷 x；x 為真就不計算 y | 真的 x，或計算得到的 y |
| `not x` | 判斷 x 的真值並取反 | 總是 bool |

這與 JS 的 `&&`、`||`、`!` 有相似之處，但參加判斷的值遵循 Python 的真值規則。短路意味著右邊**可能根本不執行**，不只是最後結果相同。

文件：`logical.py`。

<Code language="python">{getControlFlowExample('logical.py')}</Code>

預期：

```text
False
Untitled
Ready
True
25
0
```

- 空列表使 `titles and ...` 停在左邊，`titles[0]` 沒有求值，因此沒有 IndexError；外面的 bool 把返回的空列表變成 False。顛倒兩邊就失去這層保護。
- `"" or "Untitled"` 返回的是字符串，不是 True；`"Read" and "Ready"` 同樣返回一個操作數。
- `minutes or 25` 會把合法的 0 改成 25。如果規則是“僅 None 使用默認時長”，就顯式寫 `if minutes is None`。它不是 JS `??` 的同義寫法。
- 缺失字段與已有 None 仍然不同；要區分它們，繼續用 L02 的鍵成員檢查，而不是靠真假推斷。

`not` 比 `and` 優先，`and` 比 `or` 優先；比較通常先於這三個運算。初學時把意圖寫清楚，例如 `(minutes >= 0) and (minutes <= 25)`。本章不依賴複雜運算符組合來考記憶。

**暫停點 A**：運行分支邊界表，解釋空列表與 `"False"`，修復一次縮進錯誤。記錄最後一個輸入、你預測的分支、實際輸出；下次從自己的預測恢復，而不是重新安裝環境。

## 4. 普通 for：每次綁定一個條目，再執行同一塊代碼

### 4.1 循環不是先把所有語句複製很多份

對於數量變化的一組任務，我們需要：開始前準備累計值，每次處理一條，最後再輸出總結果。

文件：`for_tasks.py`。

<Code language="python">{getControlFlowExample('for_tasks.py')}</Code>

預期：

```text
Tasks: 3; total: 55 minutes
Pending: 2
```

`for task in tasks:` 從列表依次取得條目，每次把名稱 `task` 綁定到當前字典，再執行整個縮進塊。本例裡內層 `if` 多縮進一級；循環結束後的兩個 print 退回最外層，只執行一次。

`total = total + task["minutes"]` 先用舊 total 算出新值，再重新綁定；不是數學方程。本章先用完整賦值看清狀態變化，不靠縮寫隱藏它。

| 時刻 | 當前 minutes / done | total | pending |
| --- | --- | --- | --- |
| 循環前 | 還沒有當前條目 | 0 | 0 |
| 第一輪後 | 20 / True | 20 | 0 |
| 第二輪後 | 35 / False | 55 | 1 |
| 第三輪後 | 0 / False | 55 | 2 |

把 `tasks` 改成空列表，循環體執行零次，最終總時長和待辦數都為 0。初始化在循環前，所以仍有合法的結果。如果把 total 的初始化挪到循環裡，每次就會清零；空列表時甚至根本沒有執行賦值。

當前保證每條記錄有這三個字段，minutes 是非負整數，done 是 bool。`for` 不會自動驗證記錄結構；少鍵依然可能 KeyError。這不是處理任意外部輸入的校驗器。

### 4.2 當前條目是綁定，不是自動複製

文件：`loop_binding.py`。

3. `task["done"] = True` 修改的是循環取得的那個共享字典，因此列表裡的任務也變了。這是 L02 引用關係的延續，不是 for 的額外複製機制。

## 5. range：明確起點、終點與步長

需要重複若干次或生成整數位置時才引入 `range`，不必把每一次列表遍歷都改寫成索引操作。最簡單的 `range(stop)` 從 0 開始、步長為 1，**不包含 stop**。

三實參形式是 `range(start, stop, step)`；負步長向下走，零步長不合法。本節新增的 `list(...)` 會把可逐項取得的數據收集成一個列表，方便觀察，不是所有循環前都必須做一次轉換。

文件：`ranges.py`。

<Code language="python">{getControlFlowExample('ranges.py')}</Code>

預期：

```text
range(0, 3)
[0, 1, 2]
[1, 3, 5]
[3, 2, 1]
[]
[]
1
2
3
```

最後循環中的 `range(1, 4)` 才會給出 1、2、3。`range(3, 0)` 默認向上走，而起點已經超過終點，所以為空；想倒數需要顯式負步長。

`range` 是一種可重複遍歷的整數序列對象，不是已經展開的列表，也不是生成器。你現在只需理解“可迭代”：for 能從中依次取得條目直到結束。`range` 不事先保存整個整數列表；只有這裡為展示而寫的 list 轉換才收集條目。不要為了打印而展開極大的範圍。

文件：`errors/zero_step.py`。

<Code language="python">{getControlFlowExample('errors/zero_step.py')}</Code>

第一行即產生 `ValueError`，不會運行到 print。修復方法是選擇非零且符合方向的步長，不是調整縮進。接著把 `range(1, 4)` 改成 `range(1, 1)`，先解釋為什麼零次迭代是正確行為，再運行。

### 6.2 enumerate 把計數與條目放在一起

需要“第幾項 + 當前條目”時，使用 `enumerate`，避免自己維護容易錯位的計數器。它逐次給出一對值：計數、條目；for 的兩個目標每輪解包這一對值。

文件：`numbered_tasks.py`。

<Code language="python">{getControlFlowExample('numbered_tasks.py')}</Code>

預期：

```text

2. Practice
Read
```

`enumerate(titles, start=1)` 中，`start=1` 是**關鍵字實參**：把這個調用的 start 設置為 1，不是在外面創建一個名叫 start 的變量。省略它，計數默認從 0 開始。完整的參數機制放 L04，現在只需要會讀這個調用。

顯示編號從 1 開始，並不會讓列表下標也從 1 開始；最後的 if 先確認非空，才用 `titles[0]` 取第一項。空列表既不會生成編號，也不會執行這個下標訪問。這裡 enumerate 給出的迭代器會被遍歷消耗；需要重新編號時重新調用，不要把它和可重複遍歷的 range 混為一談；迭代器內部協議以後再學。

## 7. 字典遍歷：默認拿到鍵，不是鍵值對

文件：`dict_iteration.py`。

<Code language="python">{getControlFlowExample('dict_iteration.py')}</Code>

預期：

```text
title
minutes
title: Read
minutes: 20
```

`for key in task` 每次取得一個鍵。`task.items()` 返回字典鍵值條目的視圖，可逐項取得 `(key, value)` 對；因此第二個循環需要兩個解包目標。這個視圖不是凍結的快照，也不是列表；本章讀取期間不修改字典。

把 `for key, value in task` 當作縮寫是錯誤的：它會嘗試把每個鍵本身解包，而不是自動查詢對應的值。有些字符串鍵長度恰好為 2，甚至可能不報錯卻給出兩個字符，更危險。選擇 `.items()` 是在表達需要鍵與值兩者。

字典按插入順序遍歷，這不是按鍵自動排序；集合不提供這樣的順序承諾。遍歷字典時增加或刪除鍵可能觸發 RuntimeError 或漏掉條目，本章不依賴這種行為。容器的訪問方式不同，不能只更換變量名就期待同一種循環語義。

## 8. while：除了條件，還必須說明如何向結束推進

for 適合“對這些條目逐一操作”；while 適合“只要條件仍成立，就再做一輪”。while 在每輪開始前檢查條件，第一次就為假時，一輪也不執行。

我們把一段非負整數分鐘數拆成最多 20 分鐘的小塊。不是等待用戶輸入，也不是訪問服務器，只在已有整數上計算。

文件：`while_budget.py`。

<Code language="python">{getControlFlowExample('while_budget.py')}</Code>

預期：

```text
Block: 20 minutes
Block: 20 minutes
Block: 10 minutes
Blocks: 3; remaining: 0
```

| 輪次 | 開始時 remaining | used | 更新後 remaining |
| --- | --- | --- | --- |
| 1 | 50 | 20 | 30 |
| 2 | 30 | 20 | 10 |
| 3 | 10 | 10 | 0 |
| 下一次檢查 | 0 | 不進入循環 | 結束 |

每輪開始 remaining 為正；used 要麼是 20，要麼是剩餘的正數，因此每輪都讓 remaining 減少且不小於 0。**“每輪發生什麼進展”與“什麼條件結束”要一起解釋。** 只寫了 `while remaining > 0` 並不保證終止。

驗證輸入 0、1、20、21，分別應得到 0、1、1、2 塊，最後 remaining 都為 0。負數不屬於此例約定的輸入；它會跳過循環但保留負數，並不等於程序已經校驗並修復了數據。

如果誤刪更新 remaining 的那一行，當前正數輸入會無限重複打印。不要為了練習刻意放任它運行；終端出現持續重複時用 `Ctrl+C` 中斷，再檢查推進語句的位置與數值方向。中斷可能顯示 `KeyboardInterrupt`，不是系統替你修好了循環。本章不要求捕獲這個異常。

## 9. continue 與 break：跳過本輪，不等於結束全部

普通遍歷已經學會後，再處理兩個具體需求：已完成的任務直接跳過；找到第一項可在預算內完成的待辦，就不必再找。

文件：`loop_controls.py`。

<Code language="python">{getControlFlowExample('loop_controls.py')}</Code>

預期：

```text
Check: Finished
Check: Long practice
Check: Zero estimate
First match: Zero estimate
```

- `continue` 跳過**當前這一輪的剩餘語句**，從下一輪繼續，所以 Finished 不參加預算比較。
- Long practice 未匹配，也會自然進入下一輪；不需要為每一輪都寫 continue。
- `break` 結束**最近一層循環**，隨後執行循環外代碼；不會直接結束整個腳本，也不會自動退出所有外層循環。
- `found = None` 在循環前表示尚未找到。匹配後它指向當前任務字典，沒有複製；循環後明確用 `is None` 區分無匹配與已匹配。
- `Check:` 是診斷輸出，告訴你實際訪問了哪些條目；最後的 Read 沒有被訪問，是提前結束的證據。

這裡保證 minutes 非負且字段存在，budget 也是非負整數。0 分鐘待辦是合法候選，不應被 `if task["minutes"]` 排除。`task['title']` 在 f-string 花括號裡仍是普通字典訪問；內外引號不同，便於閱讀。

把輸入改成空列表，或全部完成，結果應為 `No match`；把 budget 改為 0，Zero estimate 仍然匹配。若把 continue 用在 while 裡，必須確認它沒有跳過推進變量的更新，否則可能一直停在同一個狀態。本章不引入循環的 else 子句或嵌套搜索，避免把基本流程藏起來。

## 10. 邏輯錯誤實驗：一邊遍歷，一邊刪除，為什麼漏了一項？

文件：`pitfalls/mutation_skip.py`。這是可運行的**錯誤方案**，沒有異常不代表結果正確。

<Code language="python">{getControlFlowExample('pitfalls/mutation_skip.py')}</Code>

實際輸出：


意圖是刪除所有已完成任務，但 Second 留下了：

1. 第一輪讀到位置 0 的 First，並刪除它。
2. Second 左移到位置 0，Third 左移到位置 1。
3. 列表遍歷繼續讀取下一個位置 1，拿到 Third；Second 沒有再被檢查。

`enumerate` 只是附帶計數，不會為你凍結列表。不要把“修改當前字典的字段”與“改變正在遍歷的列表長度”混成同一種修改；前者改變記錄內容，後者會改變後續讀取的位置。

改為讀取原列表、構建新列表。文件：`safe_filter.py`。

<Code language="python">{getControlFlowExample('safe_filter.py')}</Code>

預期：


原列表仍有三條，新列表只有待辦；False 說明結果列表與原列表不是同一個外層對象，篩選沒有刪除源數據。

但 **新建結果列表不是深複製**。用下面這個獨立的單項實驗檢查內層共享，而不是在通用篩選腳本末尾寫死某個下標：

```text

Changed
```

## 11. 最後才學列表推導式：縮短已理解的循環

當邏輯只有“遍歷 → 可選篩選 → 計算一個結果 → 收集”時，可以用列表推導式表達。它不是一種必須替代所有 for 的高級寫法。

文件：`comprehensions.py`。

<Code language="python">{getControlFlowExample('comprehensions.py')}</Code>

預期：

```text
['Practice', 'Review']
['Practice', 'Review']
True
False
```

讀法是：從 tasks 逐項取 task；保留 `not task["done"]` 成立的項；把 `task["title"]` 放進新的列表。語法把“要放入的表達式”寫在最前面，理解時仍從中間的 for 開始讀。

沒有篩選時可去掉末尾的 if。結果列表保留遍歷中的相對順序，空輸入會得到空列表；這裡兩個結果內容相等，但不是同一個列表對象。這裡收集的是字符串；若改成收集 task，就又會共享字典，不能認為推導式自動複製了任務。

與普通 for 還有一個必須知道的差異：推導式的目標名稱不洩漏到外面。

```python case=comprehension_binding
title = "Outside"
labels = [title for title in ["Read", "Practice"]]
print(title)
print(labels)
```

預期：

```text
Outside
['Read', 'Practice']
```

因此這裡只說“生成的列表內容等價”，不說“任何狀態變化都與普通循環一樣”。完整作用域在 L04 繼續展開。不要為了追求一行寫法加入多層 for、打印副作用、賦值技巧或複雜條件；一旦需要累計多種狀態、break 或清晰的錯誤分類，保留普通循環更合適。

**暫停點 C**：解釋 while 的終止、break 與 continue 的區別，復現刪除漏項，再把一個普通篩選循環改成簡單推導式。不能解釋中間狀態時，先保留長寫法，不算退步。

## 12. 串起來：不寫死數量的任務彙總

現在把分支、累計、空輸入和編號組合起來，而不是新增一批 API。這個腳本的輸入契約是：tasks 為列表；每項含字符串 title、bool done、非負整數 minutes。

文件：`task_summary.py`。

<Code language="python">{getControlFlowExample('task_summary.py')}</Code>

預期：

```text
Tasks: 3
Done: 1; pending: 2
Remaining: 35 minutes
Pending average: 17.5 minutes
1. Practice loops
2. Check boundaries
```

為什麼這樣安排？

- 計數器、累計分鐘與結果列表都在循環前初始化，所以零輪也是完整執行路徑。
- 每項要麼進入完成分支，要麼進入待辦分支，不會被重複統計；完成數量與待辦數量之和應等於輸入數量。
- 只有待辦時長加入 remaining；0 分鐘仍然是一項待辦，也計入平均值分母。
- 先判斷 pending_count 大於 0，才做除法，避免沒有待辦時除以零。沒有平均值用 `n/a` 表達，不虛構一個業務上有效的 0。
- `:.1f` 表示把數值顯示為一位小數，是格式化，不改變 average 的內部值。最後再用 enumerate 給已收集標題編號。

只改輸入，不改統計邏輯，完成下面的檢查：

| 輸入變化 | 必須觀察到的結果 |
| --- | --- |
| tasks 改成空列表 | Tasks: 0；done/pending/remaining 都是 0；平均值 n/a；沒有編號行 |
| 所有 done 改成 True | pending 為 0，平均值 n/a；不會除以零 |
| 只留一條 0 分鐘待辦 | pending 為 1，平均值 0.0；仍有一行編號 |
| 再追加一條 5 分鐘待辦 | 原例 pending 為 3、remaining 為 40、平均值顯示 13.3 |

如果少了 minutes，本腳本仍可能失敗；我們沒有用異常捕獲掩蓋字段契約。下一道獨立練習會明確增加“時長未知”的業務規則，而不是假裝所有數據一直完美。
