## 1. 先有行为，再把契约写给人和工具

L10 的程序已经能运行、保存和测试。为什么还要类型？当一个函数期望分钟列表，而调用者给了字符串列表，越早发现两方对数据的理解不同，排错范围就越小。注解把这种约定放在函数入口和返回值旁，让编辑器、检查器和协作者不必到每个调用点猜测。

这与 TypeScript 的基础经验相通，但不要认为 Python 会先经过一个自动拦住错误的编译关卡。执行 Python 与运行静态检查器是两条独立命令；注解本身通常不拒绝错误输入。测试观察具体运行，静态检查分析源代码，运行时校验守住真实数据入口，三者不能相互替代。

| 本章契约 | 范围 |
| --- | --- |
| 前置 | L02 容器、L04 函数、L06 模块、L10 独立项目 |
| 新能力 | 函数和容器注解、联合与可空、缺省、静态诊断、外部输入校验 |

解压后进入 u11-typing。实测基线（2026-09-28）为 CPython 3.13.15、uv 0.12.13、mypy 2.3.1、pytest 8.4.2；这是一组固定验收版本，不是要求你随时追逐最新版。

<Code language="toml">{getTypingExample('pyproject.toml')}</Code>

```bash
uv sync --locked

uv run --locked python -m pytest -q
```

mypy 配置只把已注解的业务文件、入口与独立参考函数列为正常检查范围，要求这些范围内的函数有注解。错误示例和刻意传错类型的运行时测试不在这条通过命令中；它们稍后单独执行，不能悄悄删除来“变绿”。pytest 默认只发现 tests 下的正常套件，独立答案也单独运行。

检查器显示成功时，先问它检查了哪些文件、是否检查函数体、有哪些动态类型入口，而不是把绿色当成全项目保证。运行程序不隐含运行 mypy，CI 也只有在你明确配置后才会执行检查。

如果你用过 TypeScript，可以把 mypy 理解为同类工具，但默认更保守：TypeScript 在 tsconfig.json 打开 strict 后检查整个项目，而这里的 mypy 只检查配置中列出的已注解文件；没有注解的 Python 代码会静默通过。这正是上面的绿色只覆盖配置范围、而不是每个函数的原因。

## 3. 从已理解的函数读懂注解语法

先阅读这个没有注解的旧函数，预测它如何跳过超预算项并继续向后选择：

<Code language="python">{getTypingExample('baseline.py')}</Code>

函数的参数名后用冒号标类型，右箭头标返回类型；局部变量可以注解，也可以由赋值推断。以下是完整的声明实验，可以独立执行；没有调用就没有打印。

```python smoke=typing
def add_minutes(left: int, right: int) -> int:
    total: int = left + right
    return total


def show_minutes(value: int) -> None:
    print(value)
```

`-> None` 表示正常返回没有业务结果，不表示函数不会执行、不会失败或“任何返回值都可以”。没有显式 return 的 Python 函数正常结束也返回 None。类型是契约的一部分，不能表达全部业务规则：int 不等于非负分钟，str 不等于非空标题。

先自己给 baseline 的参数和返回值补注解，不改算法。稍后完整实现会额外保留运行时规则；**“补注解”与“加校验”是两个有意分开的改动**。

## 4. 联合、可空和可省略，是三个相关但不同的问题

```python smoke=typing
def required_budget(budget: int | None) -> str:
    if budget is None:
        return "unlimited"
    return str(budget)


def default_budget(budget: int = 45) -> int:
    return budget


def optional_budget(budget: int | None = None) -> str:
    return required_budget(budget)
```

`int | None` 允许值是整数或 None；它不替你提供默认实参。required_budget 必须传参，可以显式传 None。default_budget 可以不传，但其静态契约不接受 None。optional_budget 同时允许不传和传 None。不要把 TypeScript 可选属性、Python 默认实参以及可空值合并成一个概念。

在分支中先用 `is None` 排除 None，检查器才能把剩余路径缩窄成 int。用 `if budget` 会同时把合法的 0 排除；类型提示不能替你决定“零预算”和“不限预算”是否相同。本章约定零只允许零分钟项，None 表示不限。

<details>
<summary>解释题答案：怎样判断一个参数能不能省略？</summary>

看是否有默认值，不是看类型里有没有 None。分别预测 required_budget()、required_budget(None)、default_budget()、default_budget(None)：第一项运行时缺参数，第二项合法，第三项用 45，第四项违反静态契约，但没有运行时守卫的函数仍可能把 None 原样返回。

</details>

## 5. 容器描述元素，不自动描述整个业务模型

`list[int]` 约定列表元素为 int；空列表也符合。`dict[str, int]` 约定键为 str、值为 int，但不保证恰好存在 count 和 minutes，也不限制只能有这两个键。混合字段字典若标成 `dict[str, object]`，取出的值还需缩窄才能做整数运算。本章不为了给每个字段精确建模而抢先引入类或复杂类型语法，L12 会解决另一部分模型表达问题。

Any 与 object 也不是同义词。Any 让检查器容许许多未经证明的操作；object 表示“这是某个 Python 对象，但还不知道具体能力”，使用特定能力前需要检查。以下两个函数不在声明时执行。第一种契约容许未经证明的 upper 调用；第二种先检查再使用能力。

```python smoke=typing
from typing import Any


def unchecked_label(value: Any) -> str:
    return value.upper()


def value_label(value: object) -> str:
    if isinstance(value, str):
        return value.upper()
    return "not text"
```

两个函数都可以通过当前静态检查，但第一个若收到整数仍会运行失败。对比时请在自己的副本里删去第二个函数的判断，直接返回 value.upper()：object 没有承诺 upper，这次检查器会拒绝。不要用把参数改成 Any 或添加忽略指令的方式掩盖缺失的边界检查。

## 7. 把外部数据从未知变成已验证的值

下面是最终业务实现，先沿着 text → JSON 解码 → 数组形状 → 单项检查 → 新列表 → 选择 → 汇总读一遍，再逐函数解释责任：

<Code language="python">{getTypingExample('estimates.py')}</Code>

JSON 解码器能产生对象、数组、文本、数值、布尔和空值，返回类型是动态的。把它接成 object 是明确的检查边界，不是一次数据转换。确认 list 后，逐项交给接受 object 的 non_negative_int；只有完成检查才进入结果列表。内部逻辑得到可信的分钟，但函数仍保留显式业务检查，避免从别的运行时入口绕过规则。

`type(value) is int` 刻意表达本章“普通整数，拒绝 bool 和整数子类”的精确政策。bool 在 Python 的类型关系中也是 int 的子类，mypy 可能接受它；业务上 true 不是一分钟。泛用库可能合理接受子类，本章不是推荐所有程序一律精确类型判断。

<Code language="python">{getTypingExample('errors/bool_static.py')}</Code>

```bash
uv run --locked python -m mypy errors/bool_static.py
uv run --locked python -m errors.bool_static
```

前者通过，后者由显式守卫抛出 ValueError。这正是静态契约与业务规则不能画等号的可重复证据。dict 返回值只表达同类数值映射，具体键名和结果关系还要由实现、测试和文档共同约定。

<details>
<summary>提示与核对方向</summary>
