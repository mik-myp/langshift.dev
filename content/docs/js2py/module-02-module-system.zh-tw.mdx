## 2. 先決定數據表達什麼，再選擇容器

下面只是學習地圖，具體機制會逐節實驗，**不是看完這張表就算學會了四種類型**。

| 容器 | 當前適合表達的意思 | 訪問方式 | 本章關注的限制 |
| --- | --- | --- | --- |
| `list` 列表 | 有順序的一組任務或標題，允許重複 | 位置索引 | 可以修改；順序改變後，同一個索引可能指向另一項 |
| `dict` 字典 | 一條任務的有名字的字段 | 鍵，例如 `"title"` | 可以修改；不存在的鍵與值為 None 不相同 |
| `tuple` 元組 | 固定位置含義的一組值，例如座標 | 位置索引 | 元組自身的槽位不能替換，不代表內部對象都不可變 |
| `set` 集合 | 不重複的標籤、成員關係 | 成員檢查，不按位置取值 | 無位置順序保證；成員必須可哈希，稍後解釋 |

這不是“列表只能裝同類型，元組必須裝不同類型”的語言規定。選擇首先來自數據含義。為了可讀性，我們的任務列表放任務、標籤列表放字符串，不把所有類型隨意混在一起。

JS 的 Array、Object、Set 能幫助你產生直覺，但不能把 Python 容器當作換了拼寫的同一套對象：越界、相等判斷、缺失字段和集合成員都有差異。

## 3. 列表：位置、修改和返回值

### 3.1 方括號裡的條目，與讀取條目的方括號

`["Read names", "Practice values"]` 創建一個列表。逗號分隔條目，兩個字符串仍然是兩個值，不是拼接成了一段文字。

創建之後，`titles[0]` 表示讀取索引為 `0` 的條目。列表從 `0` 開始編號；兩項列表的有效非負索引是 `0` 和 `1`。`titles[-1]` 從尾部讀取最後一項，`-2` 是倒數第二項。負索引不是循環迴繞，越過開頭仍然會出錯。

`len(titles)` 返回條目個數，不是最後一個索引。空列表寫作 `[]`，長度是 `0`，沒有可讀取的第一個條目。

### 3.2 先說明這個實驗會用到的操作

- `titles[1] = "Practice containers"` 替換現有位置上的條目，修改列表，不是重新綁定 `titles`。
- `titles.append("Review")` 把**一個條目**追加到末尾，直接修改列表，返回 `None`，不是返回新列表。
- `titles.pop(0)` 刪除並返回索引 `0` 的條目；剩餘條目的位置向前移動。不傳索引時，`pop()` 取走最後一項。
- `titles[0:1]` 是切片：從索引 `0` 開始，到索引 `1` 之前，得到一個新列表。右邊界不包含在結果裡。這裡先觀察外層列表，是否複製內部對象留到第 7 節。
- `"Review" in titles` 檢查是否有相等的條目，產生布爾值，不是取得索引，也不是執行循環體。

文件：`lists.py`。先預測，再運行。

輸出整個列表時，你看到的是容器的表示形式：保留方括號，字符串條目顯示引號。單獨 `print(titles[0])` 則輸出那個字符串本身，不帶界定引號。它不是自動把 Python 數據轉換成 JSON。

重點追蹤三次變化：先替換第二項，再追加第三項，最後移除第一項。`pop(0)` 後的 `titles[0]` 已經是 `Practice containers`。所以“某項曾經在索引 0”不是這項任務永久的業務身份；後面做真正的後端時會另外學習標識符。

### 3.3 修改成功，不代表方法返回容器

`result` 是 `None`，但列表已經追加成功。**方法的副作用和返回值必須分別看。** `append` 為修改服務，`pop` 則既修改又交還被移除的值，不能概括成“所有修改方法都返回 None”。

修復不是改成另一種索引，而是不要接收 `append` 的結果來覆蓋列表名稱：保留 `titles.append("Review")` 這次調用，再單獨讀取列表。也不要套用 JS Array `push` 的返回值經驗，Python `append` 不返回新長度。

## 4. 字典：用鍵表達一條記錄

### 4.1 為什麼標題、時長、負責人不該靠位置猜

如果把一條任務寫成 `["Read names", 25, None]`，讀者需要記住每個位置的含義。字典可以寫成 `{"title": "Read names", "minutes": 25, "owner": None}`，讓字段名稱直接出現在數據裡。

花括號包住鍵值對；每一對用冒號連接鍵與值，逗號分隔各對。本章用字符串作為鍵。`task["title"]` 取對應值；Python 字典不是通過 `task.title` 讀取這個字段。

把字典寫成多行時，大括號已經界定了表達式，換行和縮進是排版幫助，不是下一章才會學習的控制流代碼塊。最後一對後面的逗號也允許保留。

### 4.2 已有鍵被替換，新鍵被加入

文件：`dictionaries.py`。

<Code language="python">{getContainerExample('dictionaries.py')}</Code>

預期：

```text
Read names
{'title': 'Read names', 'minutes': 30, 'owner': None, 'done': False}
None
False
3
```

本例先創建三個字段，接著修改已有的 `minutes`，再加入原先沒有的 `done`。同一個鍵不會因此出現兩份；對已有鍵賦值是替換其關聯值。

`task.pop("owner")` 刪除該鍵並返回原來關聯的值，所以這裡得到 `None`。這是本例原本就存入的值，不是“刪除沒有成功”。之後 `"owner" in task` 為 `False`，字典只剩三個字段。

注意同名方法的參數含義：列表 `pop(0)` 使用位置，字典 `pop("owner")` 使用鍵；字典的 `pop` 需要提供鍵，不是無參數刪除最後一項的列表操作。

Python 3.13 的字典保留插入順序，替換已有鍵的值不會把它重新排到末尾。但保留順序不等於按索引訪問：`task[0]` 是查找整數鍵 `0`，不是讀取第一個字段。字典的相等比較關注鍵和值，不以插入順序是否相同為條件。

到這裡先使用明確的字符串鍵，不把 JS 對象的數字屬性名轉換規則套過來。Python 的鍵有自己的類型，例如整數鍵 `1` 與字符串鍵 `"1"` 不同；不是所有對象都能作鍵，集合章節會補上“可哈希”這個限制。

## 5. 字段缺失與字段值為 None，必須分開

### 5.1 方括號在表達一個較強的要求

`task["owner"]` 表示“我要讀取這個鍵關聯的值”。鍵不存在時，不會自動生成一個 None 字段，而是拋 `KeyError`。

故意失敗的文件：`errors/missing_key.py`。

<Code language="python">{getContainerExample('errors/missing_key.py')}</Code>

沒有正常輸出；第 2 行的錯誤最後一行是 `KeyError: 'owner'`。先核對需求：這個字段必須存在，還是允許缺失？不能為消除異常就一律塞入 None，否則會改變數據表達的意思。

### 5.2 `get` 的默認值只針對缺失

`task.get("owner")` 在鍵缺失時返回 `None`，不會拋上述 KeyError。提供第二個參數，如 `task.get("owner", "unassigned")`，則只在**鍵缺失**時返回這個默認值。它不會把已存在的 None、空字符串、0 或 False 自動替換掉，也不會把默認值寫回字典。

因此，如果業務需要區分“沒這個字段”和“字段明確為空”，僅檢查 `get` 的結果是不是 None 不夠，還要檢查鍵是否存在。這裡先分別打印這些事實，不提前寫條件分支。

文件：`missing_values.py`。

<Code language="python">{getContainerExample('missing_values.py')}</Code>

預期：

```text
True
None
False
None
None
unassigned
[]
False
```

| 檢查 | 為什麼得到這個結果 |
| --- | --- |
| `"owner" in task` | 鍵已經存在，雖然值是 None |
| `task.get("owner")` | 返回已經存入的 None |
| `"deadline" in task` | 沒有這個鍵 |
| `task.get("deadline")` | 缺失時默認返回 None，單看結果與上面無法區分 |
| `task.get("owner", "unassigned")` | 鍵存在，不用默認值 |
| `task.get("deadline", "unassigned")` | 鍵缺失，返回默認值 |
| 最後再檢查 `deadline` | 仍然缺失，`get` 不會插入默認字段 |

輸出 `[]` 的那一行是兩個方括號字符夾著空標題，**不是打印了一個空列表**。它證明空字符串也沒有被 `get` 的默認值替換。這沿用 L01 讓空白可見的方法。

`in` 對字典檢查的是**鍵**，不是所有值。`"Read" in {"title": "Read"}` 為 False，因為這裡的鍵是 `title`。選擇不同容器時，必須重新確認成員檢查究竟查什麼。

服務端以後也可能需要區分“請求沒有提供字段”和“明確要求清空字段”；現在只是建立數據表達基礎，沒有開始講接口更新協議。依據：[字典類型與 get](https://docs.python.org/3.13/library/stdtypes.html#mapping-types-dict)。

## 6. 共享引用：改名稱，還是改對象？

### 6.1 回到 L01 沒有提前展開的問題

L01 中兩個名稱綁定同一個整數後，重新賦值一個名稱不會改變另一個名稱。但列表可以被原地修改。賦值規則沒有變，變的是我們現在對對象做的操作。

本節將 `is` 從 L01 的 None 檢查擴展為一個實驗工具：判斷兩邊是否是**同一個對象**。不需要查看地址或記憶 `id()` 數字。

文件：`aliases.py`。

<Code language="python">{getContainerExample('aliases.py')}</Code>

預期：

```text
True
['todo', 'review']
['todo', 'review']
['done']
False
```

執行 `alias = original` 後，只有一個列表，兩個名稱都能訪問它。`alias.append("review")` 通過其中一個名稱修改這個列表，所以從 `original` 看也能看到新條目。並不是 Python 把一次修改廣播到了兩個副本，因為本來就沒有兩個副本。

隨後 `alias = ["done"]` 創建另一個列表，並讓 `alias` 改為指向它。`original` 仍指向原來的列表；重新綁定一個名稱，不會把原列表裡的條目重置掉。

| 寫法 | 改變的對象或關係 |
| --- | --- |
| `alias = other` | 改變名稱 `alias` 的綁定 |
| `alias[0] = value` | 修改 `alias` 當前指向的列表中的一個位置 |
| `alias.append(value)` | 修改 `alias` 當前指向的列表，新增一個條目 |
| `task["tags"] = new_tags` | 修改字典的一個關聯，讓這個鍵指向另一份值 |

這也是為什麼“賦值左邊有沒有下標”會影響理解，不能把所有帶 `=` 的行都解釋成同一種名稱重新綁定。

### 6.2 值相等，不等於同一個容器

兩個內容相同、分別創建的列表可以 `==` 相等，同時 `is` 為 False。與 JS 對照時，不能把 Python `==` 直接當成 JS 對數組使用 `===`。

下面只做靜態語法對照；本章以本地 CPython 和獨立示例驗收，不依賴網頁運行器。


## 7. 複製：必須說清複製到哪一層

### 7.1 先看只有字符串條目的列表

文件：`list_copy.py`。

<Code language="python">{getContainerExample('list_copy.py')}</Code>

預期：

### 7.2 新字典，舊的內層列表

**淺複製**的意思是新建外層容器，但其中保存的條目或值仍引用原來的對象。字典的 `.copy()` 也遵循這個原則。

現在讓任務的 `tags` 字段保存一個列表。`draft["tags"]` 先從字典取出這個列表，後面的 `.append(...)` 再修改該列表；不是向字典新增一個名叫 append 的字段。

文件：`shallow_copy.py`。

<Code language="python">{getContainerExample('shallow_copy.py')}</Code>

預期：

```text
False
True
Read
['python', 'basics']
Practice
```

畫出關係，比背“淺拷貝”三個字更重要：

| 執行階段 | 外層字典 | `tags` 指向的列表 |
| --- | --- | --- |
| 創建 `original` | 一份 | 一份，內容是 `python` |
| `draft = original.copy()` | 兩份不同的字典 | 兩個字典仍共享同一份列表 |
| 改 `draft["title"]` | 只替換草稿字典中的關聯 | 不涉及標籤列表 |
| 改 `draft["tags"]` 取得的列表 | 外層仍是兩份 | 共享列表被追加，因此原任務也看到新標籤 |

給 `draft["title"]` 賦新字符串，不會修改原字典的 `title` 關聯。可是兩次下標訪問 `draft["tags"]`、`original["tags"]` 取得的是同一個可變列表。這是兩種不同的操作對象，不是字典複製“有時成功、有時失效”。

### 7.3 按本章數據形狀，隔離將要修改的層

當前數據形狀已知：外層是字典，只有 `tags` 是我們會修改的內層列表，列表中都是不可變字符串。因此先複製字典，再複製該字段的列表，就能滿足當前編輯需求。

文件：`isolated_copy.py`。

<Code language="python">{getContainerExample('isolated_copy.py')}</Code>

預期：

```text

Practice

```

關鍵是 `draft["tags"] = original["tags"].copy()`：右邊新建列表，左邊只替換草稿字典中的 `tags` 關聯。修改之前就切斷了這條不希望共享的路徑。

**這不是通用深複製函數。** 如果標籤條目以後變成可變字典，或增加另一份可變字段，這段代碼不保證它們也獨立。應重新畫關係、明確哪些層會修改。也不是所有共享都錯誤：看板和任務詳情有時就應該引用同一份任務。

## 9. 元組：固定的是槽位，不是整個對象圖

列表適合需要增刪條目的序列。有些數據由固定位置承載含義，例如二維座標；元組可以表達這組槽位不被原地增刪或替換。

`(2, 5)` 是兩個元素的元組。單元素元組必須保留逗號：`("todo",)`；`("todo")` 只有用於分組的括號，結果仍是字符串。空元組寫作 `()`。可以按索引讀取、用 `len` 計數，但沒有列表的 `append`。

文件：`tuples.py`。

<Code language="python">{getContainerExample('tuples.py')}</Code>

預期：

```text

1
<class 'str'>
<class 'tuple'>
('task-1', ['python', 'basics'])
```

最後的 `record` 有兩個槽位：字符串和列表。`record[1].append(...)` 先取出列表，再修改列表；元組的第二個槽位仍然指向原來的那個列表，所以沒有違反元組自身不可變的規則。

把“元組不可變”理解為“裡面每層都深度只讀”會出錯。對於本章這個例子，固定的是元組持有的引用，不是被引用列表的內容。

如果需求是得到新座標，可以創建新的元組，例如把名稱重新綁定到 `(9, position[1])`；如果需求本來就需要頻繁替換槽位，應重新考慮列表是否更適合。不能只為讓異常消失而盲目換類型。參見[元組與序列](https://docs.python.org/3.13/tutorial/datastructures.html#tuples-and-sequences)。

## 10. 集合：關心成員，而不是條目位置

### 10.1 用“還缺哪些標籤”建立動機

一項任務的標籤可能重複錄入。如果我們只關心標籤是否存在，而不要求記錄先後順序和出現次數，集合可以表達“不重複的成員”。

非空集合可以寫成 `{"python", "basics"}`；它使用花括號，但沒有字典的鍵值冒號。**空花括號 `{}` 是字典，空集合必須寫 `set()`。** `set` 是內置功能，不需要導入。

先說明本例要用的操作：

| 操作 | 本例的意思 |
| --- | --- |
| `tag in tags` | 檢查成員是否存在，產生布爾值 |
| `tags.add(tag)` | 加入一個成員，已有則不增加重複項 |
| `tags.discard(tag)` | 移除一個成員；不存在時也不因此報 KeyError |
| `required - tags` | 新集合：要求有、但當前沒有的成員 |
| `required & tags` | 新集合：兩邊都有的成員 |
| `required \| tags` | 新集合：兩邊所有不重複成員 |

後三種運算不會在本例中修改原集合。`add`、`discard` 則原地修改，返回 None，不是返回新集合。

集合沒有列表那樣的位置順序保證，也不支持 `tags[0]`。為了讓教材輸出穩定，我們調用內置 `sorted(tags)` 得到一份排好序的**列表**再打印。當前只有小寫 ASCII 字符串，可以用普通字母順序預測結果；`sorted` 不會給原集合建立位置編號，也不修改它。

文件：`sets.py`。

<Code language="python">{getContainerExample('sets.py')}</Code>

預期：

```text
2
True
['basics', 'practice', 'python']
['sql']
['python']
['basics', 'practice', 'python', 'sql']
0
```

開頭寫了兩次 `python`，但它是同一個成員值，因此長度為 2。不要靠打印原集合得到的偶然順序安排界面，也不要用集合保存需要保留重複和先後關係的學習記錄。集合適合哪種業務含義，比背三個符號重要。

### 10.2 為什麼列表不能作為集合成員？

集合成員和字典鍵需要**可哈希**。在這裡先理解必要約束：對象要能提供生命週期內穩定的哈希值，並且相等的對象必須具有相同哈希值，容器才能按相應規則組織和查找成員。我們不需要計算這些數字，也不需要提前實現類的方法。

本章使用的 `str`、`int` 可以作為鍵或集合成員；`list`、`dict`、`set` 不可以。元組只有在每個元素都可哈希時才可哈希，所以“元組自身不可變”還不足以保證帶列表的元組能放進集合。不要把“不可變”和“可哈希”當成完全等價的術語。

故意失敗的文件：`errors/unhashable_member.py`。

<Code language="python">{getContainerExample('errors/unhashable_member.py')}</Code>

沒有正常輸出；第 2 行產生 `TypeError: unhashable type: 'list'`。代碼嘗試加入的是列表 `["python"]`，不是字符串 `"python"`。如果需求是一個標籤，傳入那個字符串即可；不要為了過關隨意把任意對象變成文本。

同樣，拿列表作字典鍵也會得到 TypeError。這與 JS Set 可以按對象身份保存數組對象的用法不同，不能把“JS 能放進去”當作 Python 的許可。

另外，成員去重依賴相等關係，不只是外觀拼寫。L01 已經解釋過 `True == 1`，因此集合不會把這兩個值當成兩個獨立成員；字典也不能靠它們區分兩個不同鍵。本章用同類字符串標籤，避免把布爾狀態和編號混為一類。依據：[集合類型](https://docs.python.org/3.13/library/stdtypes.html#set-types-set-frozenset)、[hashable 術語](https://docs.python.org/3.13/glossary.html#term-hashable)、[sorted](https://docs.python.org/3.13/library/functions.html#sorted)。

**停靠點 C：** 分別解釋“元組裡為什麼還能有變化”和“集合為什麼不能按第 0 項讀取”。然後為“有順序的任務”和“不重複的標籤”各選一種容器，並說出選擇理由。
