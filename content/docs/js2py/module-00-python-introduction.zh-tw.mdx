## 1. 這一章只跨過一道門檻

你已經會組織前端項目、寫 JavaScript 和聯調接口，不需要重新上一遍“編程是什麼”。但是，前端工程經驗不能自動告訴你 Python 的名稱、語法和運行方式怎樣工作，也不意味著你已經實現過服務端。

因此，本章不從“搭建一個完整的 Python 工程”開始。我們先完成一件更小、但需要真正理解的事：**自己創建一份 Python 文件，解釋其中每一行，運行它，修改它，再修復一個自己製造的錯誤。**

後面會逐步學習語言差異、文件與模塊、測試與工程環境，然後才進入 HTTP、FastAPI、數據庫和部署。最終目標沒有降低，只是不把終點的要求提前當成起點的門檻。

## 2. 先讀懂三行代碼，再處理安裝

先不用運行，也不要打開一長串配置文件。下面就是本章的完整程序，文件名為 `first_steps.py`：

<Code language="python">{getFirstScriptExample('first_steps.py')}</Code>

它預計打印兩行：

```text
Hello!
Python
```

這裡的“預計”很重要：先根據代碼解釋結果，再運行驗證，而不是看到終端沒有報錯就認為自己已經理解。

### 2.1 `course = "Python"`：給名稱賦一個值

`"Python"` 是字符串字面量，表示一段文本。兩邊的引號是代碼語法，不是這段文本自帶的內容。

`course` 是我們選擇的名稱。執行賦值後，後續代碼可以用這個名稱取得對應的值。Python 中這種賦值不需要在前面寫 `let`、`const` 或 `var`。

先掌握這裡可觀察的行為：執行賦值之後，`course` 可以被讀取；名稱拼錯，就不是在讀取同一個名稱。本章不要求你提前掌握可變對象、複製與作用域，下一階段會用專門的例子解釋它們。

### 2.2 `print("Hello!")`：調用一個已有功能

`print` 是 Python 提供的內置函數，本例不需要導入它。圓括號表示調用，括號裡的 `"Hello!"` 是傳給它的內容。本例會把這段文本寫到標準輸出；正常本地運行時，你在終端看到它，並在末尾換行。

注意區分：**調用已有函數**不等於**現在必須學會定義自己的函數**。你已經理解 JS 函數調用的一般概念，這裡只需要看懂當前這一種 Python 調用。

### 2.3 `print(course)`：先取得值，再輸出

這次括號裡沒有引號。Python 先查找名稱 `course` 的值，再把它交給 `print`。因此打印的是 `Python`，而不是 `course`。

這兩種寫法的區別可以單獨驗證：

```python
course = "Python"
print(course)
print("course")
```

預期結果：

```text
Python
course
```

第二行代碼讀取名稱，第三行代碼直接使用字面量。不要把“編輯器中看起來相似的文字”理解成“Python 會把它們當成同一個東西”。

### 2.4 逐行跟蹤，而不是記住結果

| 執行位置 | 發生的事情 | 新產生的輸出 |
| --- | --- | --- |
| 第 1 行 | 名稱 `course` 獲得值 `"Python"` | 無 |
| 第 2 行 | 調用 `print`，傳入 `"Hello!"` | `Hello!` |
| 第 3 行 | 讀取 `course`，把得到的值傳給 `print` | `Python` |

保存一行賦值並不會自動把值顯示出來。本章運行的是腳本文件，想看某個值時要顯式輸出它，不要把瀏覽器開發者控制檯的交互反饋直接套在文件執行上。

空行可以分隔代碼，不會產生輸出。`#` 在字符串外面可以開始一條行註釋；例如下面最後一行是給讀者看的說明：

```python
course = "Python"
print(course)
# This comment does not print anything.
```

## 3. 借用 JS 經驗，但保留差異

下面的對照只用於閱讀語法；本章的運行驗收放在本地終端，不依賴網頁編輯器的執行環境。

<PythonEditor title="讀取名稱並輸出" compare={true} canRun={false}>
```javascript !! js
const name = "Python";
console.log(name);
```

```python !! py
name = "Python"
print(name)
```
</PythonEditor>

兩邊在這個小例子中都輸出 `Python`，但這不是說 `const` 與 Python 賦值完全等價，也不是說 `console.log` 與 `print` 的所有功能相同。

Python 的名稱可以在後面重新賦值。本章只先觀察這一行為：

```python
course = "Python"
print(course)
course = "FastAPI"
print(course)
```

輸出為：

```text
Python
FastAPI
```

第一次輸出發生在重新賦值之前，不會因為後面改了名稱的值就“回頭改變”。這些都是普通文本；**寫出字符串 `"FastAPI"` 不會安裝框架，也不會啟動服務器。**

## 4. 是誰在運行 `.py` 文件？

前端開發中，編輯器負責修改文件，瀏覽器或 Node.js 等運行環境負責執行代碼。Python 也需要區分這些職責：

- **編輯器**：讓你創建、修改並保存源碼。語法高亮不代表代碼已經運行。
- **Python 語言**：規定這幾行代碼的寫法和含義。
- **Python 解釋器**：實際讀取和執行代碼的程序。本課程本地使用 CPython，它是 Python 的一種實現。
- **終端**：讓你發出啟動命令、查看輸出與錯誤。終端命令不是 Python 源碼。

最小過程是：

```text
保存 first_steps.py
        ↓
在终端启动 Python 解释器，并指定这个文件
        ↓
解释器读取文件，检查语法，再执行代码
        ↓
在终端看到输出，或者看到错误信息
```

`.py` 是 Python 源文件常用的擴展名。把文件改成這個後綴，不會讓裡面的 JS 自動變成 Python；真正執行的仍然是文件中的內容。

有些文檔展示以 `>>>` 開頭的 Python 交互式會話。`>>>` 是提示符，不是你應該複製進文件的源碼。本章固定使用文件運行，先不在幾種執行方式之間來回切換。

## 5. 只准備本章需要的運行條件

我們使用 **CPython 3.13** 作為教學基線，不聲稱它是最新版本。這個腳本沒有第三方 Python 依賴，不需要創建工程配置或安裝 FastAPI。

為減少不同電腦上 Python 命令的差異，本教材用 **uv 幫助準備和選擇解釋器**。這裡它只是一個運行工具：先知道每條命令做什麼，不在本章學習完整依賴管理。已經有可用 uv 的讀者可跳過安裝步驟。

### 5.1 安裝並確認 uv

安裝命令應從 [uv 官方安裝說明](https://docs.astral.sh/uv/getting-started/installation/)核對。下面的命令會獲取並運行官方安裝腳本；公司設備應遵守組織的軟件安裝要求，不要對來源不明的地址照抄這種模式。

**macOS / Linux 終端：**

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

**Windows PowerShell：**

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

安裝完成後，新開一個終端，執行：

```bash
uv --version
```

看到 `uv` 和版本號，說明新終端可以找到這個工具。如果仍提示找不到命令，先按照安裝輸出檢查終端與路徑；此時還沒進入 Python 代碼執行階段，不需要修改腳本。

### 5.2 準備並確認解釋器

在終端逐行執行，而不是把它們寫入 `.py` 文件：

```bash
uv python install 3.13
uv run --no-project --python 3.13 python --version
```

第一條準備 Python 3.13，已安裝時通常可以複用。第二條選擇這個版本的解釋器，讓它報告自己的版本，結果應以 `Python 3.13.` 開頭；末尾補丁號可能不同。

首次安裝可能下載文件，需要網絡。下載進度或 uv 提示來自工具，不是我們即將編寫的程序輸出。安裝成功以後，這份腳本本身不會訪問網絡。

### 5.3 建立一個普通練習文件夾

選擇你平時保存練習的目錄，再在終端執行：

```bash
mkdir js2py-first-steps
cd js2py-first-steps
```

這只是新建並進入文件夾，**不是創建工程框架**。如果你之前已經建立了它，直接進入即可，不必刪除重建。

用編輯器打開這個文件夾，新建 `first_steps.py`，填入第 2 節的三行代碼並保存。檢查文件名沒有變成 `first_steps.py.txt`；尤其在隱藏擴展名的系統上，顯示名稱可能造成誤解。

也可以[下載本章文件](/learning-assets/js2py/u00-first-script.zip)，解壓後在其中的 `u00-first-script` 文件夾打開終端。手寫和下載是兩種取得同一份文件的方式，不需要做兩遍；下載不能代替逐行理解。`solutions` 文件夾是獨立練習的答案，先不要看。

## 6. 完成第一次運行，並解釋命令

確認終端當前目錄中有 `first_steps.py`，執行：

```bash
uv run --no-project --python 3.13 python first_steps.py
```

可以分段理解這條命令：

| 部分 | 本章中承擔的職責 |
| --- | --- |
| `uv run` | 通過 uv 啟動一個命令 |
| `--no-project` | 不把當前或父目錄的 uv 工程作為運行上下文 |
| `--python 3.13` | 選擇 Python 3.13 解釋器 |
| `python` | 要運行的程序是 Python 解釋器 |
| `first_steps.py` | 交給解釋器執行的文件，按當前終端目錄定位 |

這不是讓你背下一張參數表。我們固定這一條路徑，是為了先排除“機器上究竟用了哪一個 Python”的歧義。**現在不需要執行 `uv init`、創建鎖文件或安裝測試框架。** 環境與依賴為什麼需要隔離，會在後面的工程章節單獨講清。

正常的程序輸出是：

```text
Hello!
Python
```

看到輸出後，再回到編輯器，把第一行的 `"Python"` 改成 `"FastAPI"`，**保存**，重新執行同一條命令。第二行輸出應改變，第一行仍為 `Hello!`。完成後把文件恢復成原版。

如果輸出沒有變化，先核對三個對象：編輯器保存的是哪個文件、終端在哪個目錄、命令執行的是哪個文件。不要馬上重裝 Python；這次問題可能只是你修改與運行的不是同一份文件。

## 7. 兩個可恢復的錯誤實驗

在當前練習目錄複製一份 `first_steps.py` 作為備份。每次只改一個地方，觀察之後恢復，再進行下一個實驗。不要修改其他項目的文件。

### 7.1 名稱寫錯：語法能成立，執行時找不到名稱

把程序最後一行的 `course` 改成 `cours`，其餘保持不變：

```python expected-error=NameError
course = "Python"
print("Hello!")
print(cours)
```

運行後，你會看到 `Hello!`，隨後出現包含 `NameError` 的錯誤。前兩行已經執行；到第三行需要讀取 `cours` 時，找不到這個名稱，所以停止了正常執行。

先看錯誤末尾的類型與消息，再往上找到自己的文件名和行號，回到編輯器核對那一行。`course` 和 `cours` 是兩個不同名稱，修復的是源碼拼寫，不是安裝一個叫 `cours` 的包。

這裡不要求背誦完整 traceback 格式。先能定位自己的文件、理解這次失敗的直接原因即可。修復後重跑，確認兩行正常輸出回來。

### 7.2 引號漏寫：在執行之前就無法讀懂文件

把第一行結尾的雙引號刪掉：

```python expected-error=SyntaxError
course = "Python
print("Hello!")
print(course)
```

這次會出現 `SyntaxError`，腳本中的兩條 `print` 都不會執行。區別在於：解釋器還沒開始逐行執行，就發現這份文件不是完整、合法的 Python 語法。

錯誤消息或箭頭在不同補丁版本中可能有細微差別，不需要記住它們的整段文字。恢復引號、保存、重跑，才算完成這個排錯實驗。

### 7.3 先分清錯誤發生在哪一層

| 現象 | 先檢查什麼 | 不要先做什麼 |
| --- | --- | --- |
| 找不到 `uv` 命令 | 安裝是否完成，新終端能否找到它 | 改 Python 業務代碼 |
| 無法打開 `first_steps.py` | 當前目錄、文件名、是否誤存為 `.txt` | 安裝第三方 Python 包 |
| `SyntaxError` | 指向的代碼、引號或括號是否完整 | 換一套框架 |
| `NameError` | 使用的名稱是否已賦值、拼寫是否一致 | 清空環境重裝 |
| 輸出仍是舊內容 | 文件是否保存，執行的是否同一份文件 | 把正常輸出誤當成緩存問題 |

這個表只是本章涉及的幾種現象，不是所有同名錯誤的完整原因清單。遇到不同問題，要保留實際命令和報錯，不能只憑一個錯誤名稱猜結論。

## 8. 練習：從解釋到獨立寫出

### 練習一：先預測，再驗證

不運行代碼，寫出下面程序的三行輸出，並解釋為什麼後一次賦值不會改變已經打印的內容。

```python
topic = "Python"
print(topic)
topic = "FastAPI"
print("topic")
print(topic)
```

<details>
<summary>完成後查看解釋</summary>

```text
Python
topic
FastAPI
```

第一次調用讀取舊值；第二次直接輸出字面量 `"topic"`；第三次讀取重新賦值後的值。終端中已輸出的文本不是一個會隨著名稱變化而自動更新的前端組件。

</details>

### 練習二：只修改一個地方

從原版 `first_steps.py` 出發，把最後一行改成 `print("course")`。預測兩行輸出，保存後運行核對，再恢復原版。

解釋為什麼這次不會讀取第一行賦給 `course` 的值。如果你只能說“有引號所以不一樣”，繼續補全：引號中的內容是什麼？沒有引號時解釋器會做什麼？

<details>
<summary>完成後查看結果</summary>

輸出是 `Hello!` 和 `course`。最後一行直接傳入字符串字面量，沒有通過名稱獲取值。恢復為 `print(course)` 後，它才讀取賦值產生的值。

</details>

### 練習三：獨立創建另一份文件

在同一個練習目錄裡新建 `about_me.py`，不復制整份答案，只根據下面的要求寫代碼：

1. 把 `"Python"` 賦給名稱 `subject`。
2. 先輸出 `My next skill:`，再輸出 `subject` 當前的值。
3. 把同一個名稱重新賦為 `"FastAPI"`，再輸出它的新值。

不能用把三行結果全部寫死的方式繞過“讀取名稱與重新賦值”。這道題不需要 `import`、循環、自定義函數或額外工具。

運行命令：

```bash
uv run --no-project --python 3.13 python about_me.py
```

應得到：

```text

Python
FastAPI
```
