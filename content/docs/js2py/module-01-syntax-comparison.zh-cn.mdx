## 2. 名称绑定：不是给变量装上一个固定类型的盒子

### 2.1 先预测三个输出

文件：`bindings.py`。

<Code language="python">{getScalarExample('bindings.py')}</Code>

预期：

```text
30
45
30
```

赋值可以分两步看：先求右边的值，再把左边的名称绑定到那个值所对应的对象。这里说「对象」只是说明运行时的值有自己的类型和行为，不要求你已经学会编写类。

| 执行语句 | `minutes` 此时绑定 | `saved_minutes` 此时绑定 | 新输出 |
| --- | --- | --- | --- |
| `minutes = 30` | 整数 `30` | 尚未绑定 | 无 |
| `saved_minutes = minutes` | 整数 `30` | 同一个整数值对象 | 无 |
| `print(minutes)` | 整数 `30` | 整数 `30` | `30` |
| `minutes = 45` | 整数 `45` | 仍是整数 `30` | 无 |
| 后两次输出 | 整数 `45` | 整数 `30` | `45`，然后 `30` |

`minutes = 45` 改的是名称的绑定，不是把原来的整数 `30` 原地修改成 `45`。`saved_minutes` 也不是一条「以后持续读取 minutes」的公式。它在赋值发生时读取了一次右边的值。

这里也**不能反推「Python 赋值会自动复制数据」**。两个名称可以指向同一个对象；本例之所以没有连带修改，是因为我们重新绑定名称，而整数本身不可变。容器的共享引用与修改在 L02 用另一组实验讲解；现在不用记忆地址、`id()` 或缓存规则来解释这个程序。

终端已经打印的第一行同样不会变成 `45`。`print` 是当时发生的一次输出，不是订阅名称变化的 UI。

### 2.2 与前端经验的连接，以及类比的边界

你可以把本例的重新赋值与 JS 的 `let` 类比，但 Python 的普通赋值前没有 `let`/`const` 声明词，也没有因此获得 JS `const` 的绑定限制。下面是命名惯例，不是语法保护：

```python case=constant_convention
MINUTES_PER_SESSION = 25
MINUTES_PER_SESSION = 30
print(MINUTES_PER_SESSION)
```

输出：

```text
30
```

全大写表示「作者希望把它当常量」，解释器不会阻止上面的重新赋值。不要把团队约定当作运行时约束。

本书普通名称采用 `snake_case`，例如 `saved_minutes`。名称大小写敏感，`minutes` 与 `Minutes` 不同；不能以数字开头，不能占用 `class` 等关键字。也不要把 `print`、`str`、`int` 当自己的变量名，否则会遮住后面要调用的内置功能。局部作用域规则留到函数章节。

**停靠点 A：** 不运行，解释把第一行的 `30` 改成 `20` 后哪几行输出会变。若还觉得 `saved_minutes` 应该自动变成 `45`，先画上述绑定表，而不是继续背运算符。

## 3. 值有类型，名称可以重新绑定

### 3.1 同样的外观，不同的值

| 写法 | 类型名 | 此处表达的含义 |
| --- | --- | --- |
| `30` | `int` | 整数，可以参与整数计算 |
| `30.0` | `float` | 浮点数，用有限精度近似表示数值 |
| `"30"` | `str` | 两个字符组成的文本，不会因为像数字就自动变成整数 |
| `True`、`False` | `bool` | 布尔值，首字母大写 |
| `None` | `NoneType` | 专门表示「此处没有值」的对象，含义由业务约定 |

我们把这些称作本章的基本单值，便于与下一章的容器区别；这不是一种新的 Python 声明语法。字符串也有序列行为，后面再展开。

`type(value)` 可以观察当前值的类型。这里先学会调用它，不需要研究元类。文件：`scalar_types.py`。

<Code language="python">{getScalarExample('scalar_types.py')}</Code>

预期：

```text
<class 'int'>
<class 'float'>
<class 'str'>
<class 'bool'>
<class 'NoneType'>
<class 'int'>
<class 'str'>
```

`print(type(30))` 先调用内层 `type` 得到类型，再把结果交给外层 `print`。输出里的 `class` 是类型的显示形式，不是提示你必须先写一个类。

末尾的名称 `minutes` 先绑定整数，后来绑定字符串；语言允许这样做。但「允许重新绑定不同类型」不意味着「不同类型可以混着做所有运算」。程序越长，同一个名称承担互相冲突的含义就越难理解，因此真实代码通常会用 `raw_minutes` 保存原始文本，用 `minutes` 保存转换后的整数。

### 3.2 表达式、结果与输出是三件事

`30 + 15` 是会求出一个值的表达式。`total = 30 + 15` 保存它的结果；`print(total)` 才把结果写到终端。仅把 `30 + 15` 写在脚本一行上，不会像某些交互控制台那样自动回显。

后面的每个输出示例都保留了 `print`，不是因为运算必须依赖它，而是为了让你观察计算结果。

## 4. 数值运算：重点不是符号，而是结果规则

### 4.1 先看正数，再检查类型

文件：`numbers.py`。先只预测前七行，再看后面三个边界。

<Code language="python">{getScalarExample('numbers.py')}</Code>

完整输出：

```text
9
5
14
3.5
3
1
49
3.0
-4
1
```

| 表达式 | 结果 | 原因 |
| --- | --- | --- |
| `7 + 2`、`7 - 2`、`7 * 2` | `9`、`5`、`14` | 加、减、乘 |
| `7 / 2` | `3.5` | 真除法；两个整数使用 `/` 也得到浮点结果 |
| `7 // 2` | `3` | 向下取整的除法，不是保留小数部分 |
| `7 % 2` | `1` | 与整除结果配对的余数 |
| `7 ** 2` | `49` | 幂运算；不要用 `^` 代替乘方 |
| `7.0 // 2` | `3.0` | 结果向下取整，但有浮点操作数时结果仍是 `float` |

同样，`8 / 2` 是 `4.0`，不是 `4`。`//` 的「整」指取整规则，不能简单记作「返回 int 的除号」。这些规则来自 Python 的[数值类型定义](https://docs.python.org/3.13/library/stdtypes.html#numeric-types-int-float-complex)。

乘除比加减优先；有意图不清的组合就写括号，不靠读者猜：

```python case=precedence
print(2 + 3 * 4)
print((2 + 3) * 4)
print(-(3 ** 2))
print((-3) ** 2)
```

输出：

```text
14
20
-9
9
```

最后两行分别是「平方后取负」与「负数整体平方」。现在先用括号表达清楚意图，不需要背完全部运算符优先级。除数为零会报 `ZeroDivisionError`，不是得到 JavaScript Number 的 `Infinity`；本章不要把零作为时间换算的除数。

### 4.2 负数会揭穿「去掉小数」的误解

`-7 / 2` 是 `-3.5`；向下取整是走向更小的整数，所以 `-7 // 2` 是 `-4`，不是 `-3`。与它配对的余数是 `1`，因为：

```text
-7 = (-4) * 2 + 1
```

对整数且除数不为零，商和余数满足 `a == (a // b) * b + a % b`。在非零余数的情况下，Python 整数 `%` 的结果与除数同号。JS 的 `%` 使用余数规则，不是同一套负数行为；例如 JS 的 `-7 % 2` 是 `-1`。需要核对时查看 [Python 表达式参考](https://docs.python.org/3.13/reference/expressions.html#binary-arithmetic-operations)和 [JS remainder 说明](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Operators/Remainder)。

本章产物用正分钟数，不需要依赖负数取余做业务功能；这里的实验是为了防止把 `//` 错记成「砍掉小数」。

### 4.3 大整数和小数：两种不同的精度问题

下面的静态对照展示两种语言的边界；本章以本地 CPython 的运行结果验收，不依赖网页运行器。

<PythonEditor title="Python int 与 JavaScript Number" compare={true} canRun={false}>
```javascript case=integer_precision

console.log(2 ** 53 + 1);
```

```python case=integer_precision

```
</PythonEditor>

Python 输出：

```text

9007199254740993
```

JS Number 两行都输出 `9007199254740992`。Python `int` 不受 JS Number 的安全整数范围约束，会在可用资源范围内保持整数精度；这不代表计算和内存无限。JS 的 `BigInt` 是另一种类型，不能把这里的对照扩展成「JS 无法处理大整数」。详见 [Number.MAX_SAFE_INTEGER](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/MAX_SAFE_INTEGER)。

`float` 则不能精确存储所有十进制小数：

```python case=float_precision
print(0.1 + 0.2)
print(0.1 + 0.2 == 0.3)
```

输出：

```text
0.30000000000000004
False
```

比较符号 `==` 表示比较值是否相等，下一节正式展开。这个结果不是 Python 随机算错，而是二进制浮点近似经过运算后可见的误差。不要用「只显示两位」冒充「已经精确计算」；本章用时间估算而不是金额结算来练习，精确十进制方案等有前置基础后再教。官方[浮点教程](https://docs.python.org/3.13/tutorial/floatingpoint.html)解释了这一限制。

**停靠点 B：** 现在应该能独立说明 `95 // 60` 与 `95 % 60` 各代表什么，以及 `7.0 // 2` 为什么带 `.0`。如果只记住输出，还没能解释规则，先用纸笔换一组数。

## 5. 比较、布尔值和「没有值」

### 5.1 `=` 保存绑定，`==` 比较值

`minutes = 30` 是赋值；`minutes == 30` 会产生一个布尔值，并不修改名称。Python 没有 `===`。但也不能把 Python 的 `==` 整体叫作 JS 的宽松相等或严格相等：它不会把 `"30"` 自动转成整数来比较，同时数值类型之间又允许数值相等。

下面把比较与缺失值放在一个独立脚本里。文件：`boolean_none.py`。

<Code language="python">{getScalarExample('boolean_none.py')}</Code>

预期：

```text
True
False
True
True
True
False
None
True
False
```

逐项解释：

- `30 == 30.0` 为 `True`：类型不同，但数值相等。
- `"30" == 30` 为 `False`：数字文本不会在这里自动转成整数。
- `True == 1` 为 `True`：`bool` 是 `int` 的子类型，布尔值在数值比较中与 `1`、`0` 有关系。知道这个边界即可，业务上仍然应把「是否完成」和「数量」当作不同含义处理，不鼓励靠它省略数据检查。
- `!=` 表示不相等；`<`、`<=`、`>`、`>=` 分别表示小于、小于等于、大于、大于等于。它们产生布尔结果，不会自动输出文字结论或改变程序走向。

现在只是观察布尔值，还没有教 `if`、`and`、`or` 或通用真值规则；不要求提前用条件语句处理这些结果，也不要自行把 `bool("False")` 当成文本解析方案。

### 5.2 `None` 与「名称不存在」不是一回事

在这个例子中，我们约定 `assignee = None` 表示「尚未指定负责人」。这条赋值已经绑定了名称，读取 `assignee` 合法，并得到 `None`。

以下几种状态必须分开：

| 状态 | 本例中如何解释 |
| --- | --- |
| `assignee = None` | 有这个名称，约定它暂时没有负责人 |
| `assignee = ""` | 有这个名称，值是空字符串；是否允许空名字要另定规则 |
| `assignee = "None"` | 四个字母组成的普通文本，不是缺失值对象 |
| 从未给 `assignee` 赋值就读取 | 名称没有绑定，按 L00 的实验会得到 `NameError` |

`0` 和 `False` 也各有自己的值，不能当作 `None` 的同义写法。

本章把 `value is None` 学成一个边界明确的检查：看值是不是那个专用的 `None` 对象。它不是字符串匹配，也不会把空字符串视为 `None`。`is` 一般讨论对象身份，不是另一个严格相等符号；**不要拿 `is` 比较数字和字符串内容**。其他身份问题等容器与引用章节再展开。参考 [None 常量](https://docs.python.org/3.13/library/constants.html#None)和 [PEP 8 的 None 比较建议](https://peps.python.org/pep-0008/#programming-recommendations)。

## 6. 字符串：清理文本不等于修改原值

任务标题可能带着首尾空格。我们希望显示清理后的标题，同时保留原始值用于核对。

先读懂 `raw_title.strip()`：点号后面是字符串提供的 `strip` 方法，圆括号表示现在调用。这里不传参数，它返回去掉首尾空白的字符串，不会删除中间的空格，也不会原地修改 `raw_title`。调用已有方法不要求现在定义类或方法。

文件：`strings.py`。

<Code language="python">{getScalarExample('strings.py')}</Code>

预期：


前两行故意在文本外拼接方括号，让空格不再「看不见」。这个例子里的方括号是引号内的普通字符，**不是列表语法**。

## 7. 显式转换：输入看起来像数字，不代表已经是数字

### 7.1 先决定要计算，还是要连接文本

内置的 `int`、`float`、`str` 在本章分别用于取得整数、浮点数与文本表示。文件：`conversions.py`。

<Code language="python">{getScalarExample('conversions.py')}</Code>

### 7.2 两种失败，要诊断而不是掩盖

第一次实验的文件：`errors/text_plus_number.py`。

<Code language="python">{getScalarExample('errors/text_plus_number.py')}</Code>

在当前示例中没有正常输出；错误最后一行类似：

```text
TypeError: can only concatenate str (not "int") to str
```

看第 2 行：传给 `print` 的表达式必须先求值，加法已经失败，所以连 `print` 都没有拿到结果。后面的 `finished` 也不会出现。错误说明类型组合不支持这项操作，而不是 `print` 本身不能输出数字。

## 8. f-string：把值做成文字，不是建立响应式视图

手动写 `"Minutes: " + str(minutes)` 可以工作，但随着信息增多容易漏空格、漏转换。f-string 在引号前加 `f`，在文本中的花括号内写表达式；Python 在执行到这一行时求值，把格式化结果放入一段新字符串。

文件：`formatting.py`。

<Code language="python">{getScalarExample('formatting.py')}</Code>

预期：

```text
Estimate: 95 minutes
Estimate: 95 minutes
Estimate: 120 minutes
Decimal hours: 1.58
1.5833333333333333
```

`report` 在 `minutes` 等于 `95` 时就构造好了。后来把 `minutes` 改成 `120`，不会回头改写已经生成的字符串。最后一次直接构造新的 f-string，才会读到新的分钟数。这和 JS 模板字符串求值后的普通字符串一样，不是 Vue 的计算属性或 React 的下一次渲染。

`{hours:.2f}` 中，冒号前的 `hours` 是要格式化的值，后面的 `.2f` 要求固定小数格式、显示两位小数。它改变生成的文字，不修改 `hours`；最后一行还会显示原来的浮点结果。格式化不是精确金额计算或业务舍入策略。

若忘记开头的 `f`，花括号只是普通文本，不会插入变量。f-string 与格式说明的权威说明分别在[输出教程](https://docs.python.org/3.13/tutorial/inputoutput.html#formatted-string-literals)和[格式规范](https://docs.python.org/3.13/library/string.html#format-specification-mini-language)中；本章不要求掌握整个格式语言。
