## 这套教材为谁编写？

你能够独立搭建前端项目，做过接口联调，熟悉 Promise 与 async/await，了解 TypeScript 基础类型，但还没有亲自实现后端或数据库。这就是本教材的读者起点。

我们不要求你先学 Express，也不把复杂类型体操作为门槛。已有工程经验会帮助你理解项目组织、测试和协作，但不能替代第一次设计表结构、事务、权限与部署流程的实践。教材会把这些陌生职责逐步讲清，而不是用一张库名和 API 表格代替教学。

## 学习目标：能交付，而不只是能看懂

最终目标是：允许查阅文档，能够根据需求独立实现、测试、部署和维护一个可供受邀用户使用的中小型后端，并完成一次没有逐步实现教程的新需求。

“读完所有页面”不是完成标准。每个阶段都需要实际产物、成功与失败场景、验收步骤，以及对设计的解释。后续开放公共注册等功能还需要额外的安全与运维验收，不能把演示程序直接当成完整产品。

## 怎样使用本教材？

一个知识点通常沿着这样的过程展开：

1. 先提出一个真实问题，解释为什么需要这个知识。
2. 借用你熟悉的前端经验建立联系，同时说明类比失效的边界。
3. 解释概念与运行机制，再给出必要的语法和 API。
4. 运行完整例子，预测并解释输入、输出及失败行为。
5. 完成带提示的修改，然后独立完成变式需求。
6. 用测试或明确操作验收，之后再查看分开放置的参考答案。

从 L10 开始建立自己的产品仓库。后续 API、PostgreSQL、身份、对象权限、异步和运维实验都要回到这份仓库，保留自己的迁移、测试、发布、回退和恢复记录；独立实验用于理解机制，不能直接替代完整产品整合。

使用[贯穿项目指南](/zh-cn/docs/js2py/project-integration)完成阶段交接、真实目标环境发布验收和长期维护记录。

使用[官方来源矩阵](/zh-cn/docs/js2py/official-sources)区分上游行为、锁定版本和课程自定义契约。

使用[生产发布与维护运行手册](/zh-cn/docs/js2py/deployment-runbook)把 O 阶段证据接入真实目标环境。

不是所有例子都适合在网页运行。纯语法可以使用浏览器实验；多文件、依赖、数据库和 Web 服务应在明确的本地环境中执行。配置文件、故意错误的例子和服务程序不能仅因有一个编辑器，就被称为“点击即可运行”。

## 分阶段的能力路线

| 阶段 | 需要形成的能力 | 产物 |
| --- | --- | --- |
| Python 基础 | 语言差异、函数、类型、模块、异常、资源与测试 | 可复现的本地任务程序 |
| HTTP 与 FastAPI | 接口契约、验证、响应、路由、依赖与配置 | 可联调的 API |
| 数据库 | SQL、关系、约束、事务、ORM 与迁移 | 不靠内存保存状态的服务 |
| 多用户 | 身份、密码、凭证失效、对象级权限 | 不会跨用户泄露数据的应用 |
| 可靠性 | API/数据库测试、异步边界、超时与故障处理 | 可以解释和验证失败行为的项目 |
| 交付与维护 | 部署、日志、备份恢复、迭代与回退 | 受控真实上线与独立新功能 |

先把同步后端的基本行为做正确，再学习有具体用途的异步。数据分析、复杂元类、高级泛型和分布式任务等内容可以作为选修，不阻断第一个项目的交付。这个顺序不是压缩基础，而是避免让不必要的复杂度抢在必要知识之前。

## 先后顺序比一次学多少更重要

新的 Python 主线按小步骤展开：**第一次运行 → 名称与值 → 容器 → 控制流 → 函数 → 异常 → 模块 → 文件/JSON → 环境与依赖 → 基础测试 → 第一个独立可复现项目**。随后再补齐类型、类、装饰器和资源生命周期，进入服务端与 FastAPI。

每一步都有当前知识足以解释的小程序，不是先读完整本语法书才实践，也不是先搭工程再长期欠下解释。各章按前置能力验收，不按固定周数推进。按目录逐章通过能力验收，而不是读过标题就算掌握。环境准备、凭证处理、迁移安全和恢复都有自己的教学与证据；后续章节不会无声地把本地演示升级成生产服务。

## 从哪里开始？

从[第 00 章：读懂并运行第一份脚本](/zh-cn/docs/js2py/module-00-python-introduction)开始。本章只用 uv 准备和选择 CPython 3.13，不教学整套工程配置；虚拟环境、锁文件和 pytest 在具备语言与模块基础之后再系统学习。

普通 Python 函数使用 `def`，并不需要 `self`；实例方法才会涉及显式的实例参数。Python 的 async/await 与 JS 表面相似，也不表示调度和执行行为完全一样。我们会通过可验证的例子建立准确联系，不用一句“对应关系”抹平差异。

学习时间可以不固定。每次结束时记录当前代码状态、通过的测试、仍不理解的问题和下次第一步。按能力验收推进，而不是按周数赶进度。
