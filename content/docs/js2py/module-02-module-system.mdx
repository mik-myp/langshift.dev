## 1. The problem now involves more than one value

## 2. Choose the meaning of the data before its container

This is a learning map, not a substitute for the experiments. **Reading the table does not mean you have learned all four types.**

| Container | Meaning it can express here | Access | Boundary to understand |
| --- | --- | --- | --- |
| `list` | An ordered collection of tasks or titles, allowing duplicates | Position index | Mutable; after reordering, an index may refer to another entry |
| `dict` | Named fields in one task record | A key such as `"title"` | Mutable; a missing key differs from a value of None |
| `tuple` | Positions with fixed meaning, such as coordinates | Position index | Its own slots cannot be replaced; referenced objects are not necessarily immutable |
| `set` | Distinct tags and membership | Membership checks, not positions | No positional order guarantee; members must be hashable, explained later |

These are not language rules requiring lists to contain one type or tuples to contain different types. Choose according to meaning. For readability, our task lists contain tasks and tag lists contain strings rather than arbitrary mixtures.

JS Array, Object, and Set provide useful intuition, but Python containers are not merely alternative spellings. Bounds, equality, missing fields, and permissible set members differ.

## 3. Lists: positions, mutation, and return values

### 3.1 Brackets that create entries and brackets that access one

`["Read names", "Practice values"]` creates a list. Commas separate entries; the two strings remain separate values rather than being concatenated.

After creation, `titles[0]` reads the entry at index `0`. Indexing starts at zero, so a two-entry list has valid nonnegative indices `0` and `1`. `titles[-1]` reads the last entry from the end; `-2` reads the second-to-last. Negative indices do not wrap indefinitely: going past the beginning still fails.

`len(titles)` returns the entry count, not the final index. An empty list is `[]`, has length `0`, and has no first entry to read.

### 3.2 Introduce the operations before using them

- `titles[1] = "Practice containers"` replaces an existing entry. It mutates the list rather than rebinding `titles`.
- `titles.append("Review")` adds **one entry** at the end, mutates the list, and returns `None`, not a new list.
- `titles.pop(0)` removes and returns the entry at index `0`. Remaining positions shift forward. Without an index, `pop()` removes the last entry.
- `titles[0:1]` is a slice: start at index `0`, stop before index `1`, and produce a new list. The ending boundary is excluded. For now, observe the outer list; section 7 explains whether its contents are copied.
- `"Review" in titles` checks for an equal entry and produces a Boolean. It neither returns an index nor executes a loop body you must write.

## 4. Dictionaries: named fields in a record

### 4.1 Why title, duration, and owner should not require guessing positions

Representing a task as `["Read names", 25, None]` makes readers remember what each position means. A dictionary can instead be `{"title": "Read names", "minutes": 25, "owner": None}`, placing field names directly in the data.

Braces surround key-value pairs. A colon connects each key to its value; commas separate the pairs. This chapter uses string keys. `task["title"]` retrieves its associated value; a Python dictionary does not use `task.title` for this field.

In a multiline dictionary, braces already delimit the expression. Newlines and indentation aid layout rather than introducing the control-flow blocks taught next chapter. A comma after the final pair is also permitted.

### 4.2 Existing keys are replaced; new keys are added

File: `dictionaries.py`.

<Code language="python">{getContainerExample('dictionaries.py')}</Code>

Expected:

```text
Read names
{'title': 'Read names', 'minutes': 30, 'owner': None, 'done': False}
None
False
3
```

The example starts with three fields, replaces the existing `minutes` value, and adds the previously absent `done`. Assignment to an existing key replaces its association rather than creating a second copy of the key.

`task.pop("owner")` removes that key and returns its former value, so the result is `None`. That is the value the example originally stored, not an indication that deletion failed. Afterwards, `"owner" in task` is `False`, and three fields remain.

The same method name can take different kinds of arguments: list `pop(0)` uses a position; dictionary `pop("owner")` uses a key. Dictionary `pop` requires a key, unlike the no-argument list operation that removes the final entry.

Dictionaries in Python 3.13 preserve insertion order, and replacing an existing key's value does not move it to the end. But preserving order is not positional access: `task[0]` looks for integer key `0`, not the first field. Dictionary equality concerns keys and values rather than insertion order.

Use explicit string keys for now rather than importing JS object numeric-property conversion rules. Python keys have their own types: integer key `1` differs from string key `"1"`. Not every object can be a key; the set section introduces the hashability constraint.

## 5. A missing field differs from a field whose value is None

### 5.1 Brackets express a stronger requirement

`task["owner"]` asks to retrieve that key's associated value. If the key does not exist, it raises `KeyError` rather than generating a field containing None.

Intentional failure: `errors/missing_key.py`.

<Code language="python">{getContainerExample('errors/missing_key.py')}</Code>

There is no normal output; the final error line for line 2 is `KeyError: 'owner'`. First check the requirement: must the field exist, or may it be absent? Inserting None everywhere just to eliminate an exception changes the meaning of the data.

### 5.2 The default in `get` applies only to absence

`task.get("owner")` returns `None` for a missing key instead of raising that KeyError. A second argument, as in `task.get("owner", "unassigned")`, supplies a default used **only if the key is missing**. It does not replace an existing None, empty string, 0, or False. It also does not write the default into the dictionary.

If the application distinguishes an absent field from an explicitly empty one, testing whether a `get` result is None is insufficient: you also need to check whether the key exists. We print these facts separately for now, without premature conditional branches.

## 6. Shared references: changing a name or changing an object?

### 6.1 Return to the question deliberately deferred in L01

In L01, two names could refer to an integer, yet rebinding one did not change the other. A list can be mutated in place. Assignment rules have not changed; the operation performed on the object has.

Here we extend L01's use of `is` for None checks into an experimental tool: determine whether both sides are the **same object**. Memory addresses and `id()` numbers are unnecessary.

File: `aliases.py`.

<Code language="python">{getContainerExample('aliases.py')}</Code>

Expected:

```text
True
['todo', 'review']
['todo', 'review']
['done']
False
```

After `alias = original`, there is one list accessible through two names. `alias.append("review")` mutates it through one name, so the new entry is also visible through `original`. Python did not broadcast a change to two copies: there never were two copies.

Next, `alias = ["done"]` creates another list and makes `alias` refer to it. `original` still refers to the initial list. Rebinding a name does not reset that list's contents.

| Statement | What changes |
| --- | --- |
| `alias = other` | The binding of the name `alias` |
| `alias[0] = value` | One position in the list currently referenced by `alias` |
| `alias.append(value)` | The current list, by adding one entry |
| `task["tags"] = new_tags` | One dictionary association, making that key refer to another value |

This is why a subscript on the left matters. Not every line containing `=` can be explained as the same kind of name rebinding.

### 6.2 Equal contents do not imply the same container

Separately created lists with equal contents can compare `==` while `is` is False. Python `==` must not be translated directly into JS `===` on arrays.

### 7.2 A new dictionary can contain the old inner list

A **shallow copy** creates an outer container while its entries or values continue to refer to the original objects. Dictionary `.copy()` follows this principle too.

Let a task's `tags` field contain a list. `draft["tags"]` first retrieves that list, and `.append(...)` mutates it. This is not the addition of a dictionary field named append.

| Stage | Outer dictionaries | The list referenced by `tags` |
| --- | --- | --- |

| Assign `draft["title"]` | Only the draft's association changes | The tag list is not involved |
| Mutate the list retrieved by `draft["tags"]` | Still two dictionaries | The shared list gains an entry, visible through the original too |

Assigning a new string to `draft["title"]` does not replace the original dictionary's `title` association. But `draft["tags"]` and `original["tags"]` retrieve the same mutable list. These operations target different objects; dictionary copying is not succeeding inconsistently.

## 9. Tuples fix their slots, not the entire object graph

Lists suit sequences whose entries need adding or removing. Some data uses positions with fixed meanings, such as two-dimensional coordinates. A tuple can express that its own slots are not added, removed, or replaced in place.

`(2, 5)` is a two-element tuple. A one-element tuple requires the comma: `("todo",)`. `("todo")` merely groups a string expression and still produces a string. The empty tuple is `()`. You can index it and count elements with `len`, but it has no list-style `append`.

File: `tuples.py`.

<Code language="python">{getContainerExample('tuples.py')}</Code>

Expected:

```text

1

```

The final `record` has two slots, containing a string and a list. `record[1].append(...)` retrieves and mutates the list. The tuple's second slot still refers to that same list, so the tuple's own immutability is not violated.

“Tuples are immutable” does not mean every referenced layer is deeply read-only. In this example, the references held by the tuple are fixed, not the contents of the referenced list.

## 10. Sets: membership rather than entry positions

### 10.1 Start with the question: which required tags are still missing?

A task's tags might be entered more than once. If only membership matters, without recording order or frequency, a set can represent distinct members.

A nonempty set can be `{"python", "basics"}`: braces, but no dictionary key-value colons. **Empty braces `{}` create a dictionary. An empty set is `set()`.** `set` is built in and requires no import.

Introduce the operations used in this example first:

| Operation | Meaning here |
| --- | --- |
| `tag in tags` | Produce a Boolean indicating membership |
| `tags.add(tag)` | Add one member without duplicating an existing member |
| `tags.discard(tag)` | Remove a member; absence does not itself raise KeyError |
| `required - tags` | New set of required members that are currently missing |
| `required & tags` | New set of members present on both sides |
| `required \| tags` | New set containing all distinct members from both sides |

The final three expressions do not mutate the original sets here. `add` and `discard` mutate in place and return None, not a new set.

A set has no list-style positional order guarantee and does not support `tags[0]`. To keep textbook output stable, we call the built-in `sorted(tags)` to obtain a sorted **list** for printing. Our values are lowercase ASCII strings, so ordinary alphabetical order is sufficient to predict the result. `sorted` neither assigns positions to the original set nor mutates it.

### 10.2 Why cannot a list be a set member?

Set members and dictionary keys must be **hashable**. Understand the necessary constraint first: an object must provide a hash value stable during its lifetime, with equal objects having equal hashes, allowing the container to organize and find members accordingly. We do not need to calculate these numbers or implement class methods yet.

The `str` and `int` values used here can be keys and set members; `list`, `dict`, and `set` cannot. A tuple is hashable only when each element is hashable. Its own immutability therefore does not make a tuple containing a list eligible for a set. “Immutable” and “hashable” are not interchangeable terms.

Intentional failure: `errors/unhashable_member.py`.

<Code language="python">{getContainerExample('errors/unhashable_member.py')}</Code>

Using a list as a dictionary key similarly raises TypeError. This differs from JS Set storing array objects by identity. Permission to store something in JS does not establish the Python rule.

Deduplication also depends on equality, not merely spelling. L01 explained `True == 1`; a set therefore does not keep these as two distinct members, and a dictionary cannot use them as two distinct keys. We use homogeneous string tags rather than mixing Boolean state with identifiers. | Relationship | Design intention |
| --- | --- |
| The template, first task, and second task dictionaries | Three different dictionaries; title and duration edits do not affect the template |
| Their three `tags` lists | Three different lists; editing one does not affect the other two |
| `board[0]` and `first` | The same task dictionary; `first` should observe an edit made through the board |
| `board[1]` and `second` | The same task dictionary, not an automatic copy created by insertion into a list |

That is why the final numbers are `40` and `25`. Editing the first task through the board makes `first` observe 40, while the template keeps 25.
