## 1. 这一章只跨过一道门槛

你已经会组织前端项目、写 JavaScript 和联调接口，不需要重新上一遍“编程是什么”。但是，前端工程经验不能自动告诉你 Python 的名称、语法和运行方式怎样工作，也不意味着你已经实现过服务端。

因此，本章不从“搭建一个完整的 Python 工程”开始。我们先完成一件更小、但需要真正理解的事：**自己创建一份 Python 文件，解释其中每一行，运行它，修改它，再修复一个自己制造的错误。**

后面会逐步学习语言差异、文件与模块、测试与工程环境，然后才进入 HTTP、FastAPI、数据库和部署。最终目标没有降低，只是不把终点的要求提前当成起点的门槛。

## 2. 先读懂三行代码，再处理安装

先不用运行，也不要打开一长串配置文件。下面就是本章的完整程序，文件名为 `first_steps.py`：

<Code language="python">{getFirstScriptExample('first_steps.py')}</Code>

它预计打印两行：

```text
Hello!
Python
```

这里的“预计”很重要：先根据代码解释结果，再运行验证，而不是看到终端没有报错就认为自己已经理解。

### 2.1 `course = "Python"`：给名称赋一个值

`"Python"` 是字符串字面量，表示一段文本。两边的引号是代码语法，不是这段文本自带的内容。

`course` 是我们选择的名称。执行赋值后，后续代码可以用这个名称取得对应的值。Python 中这种赋值不需要在前面写 `let`、`const` 或 `var`。

先掌握这里可观察的行为：执行赋值之后，`course` 可以被读取；名称拼错，就不是在读取同一个名称。本章不要求你提前掌握可变对象、复制与作用域，下一阶段会用专门的例子解释它们。

### 2.2 `print("Hello!")`：调用一个已有功能

`print` 是 Python 提供的内置函数，本例不需要导入它。圆括号表示调用，括号里的 `"Hello!"` 是传给它的内容。本例会把这段文本写到标准输出；正常本地运行时，你在终端看到它，并在末尾换行。

注意区分：**调用已有函数**不等于**现在必须学会定义自己的函数**。你已经理解 JS 函数调用的一般概念，这里只需要看懂当前这一种 Python 调用。

### 2.3 `print(course)`：先取得值，再输出

这次括号里没有引号。Python 先查找名称 `course` 的值，再把它交给 `print`。因此打印的是 `Python`，而不是 `course`。

这两种写法的区别可以单独验证：

```python
course = "Python"
print(course)
print("course")
```

预期结果：

```text
Python
course
```

第二行代码读取名称，第三行代码直接使用字面量。不要把“编辑器中看起来相似的文字”理解成“Python 会把它们当成同一个东西”。

### 2.4 逐行跟踪，而不是记住结果

| 执行位置 | 发生的事情 | 新产生的输出 |
| --- | --- | --- |
| 第 1 行 | 名称 `course` 获得值 `"Python"` | 无 |
| 第 2 行 | 调用 `print`，传入 `"Hello!"` | `Hello!` |
| 第 3 行 | 读取 `course`，把得到的值传给 `print` | `Python` |

保存一行赋值并不会自动把值显示出来。本章运行的是脚本文件，想看某个值时要显式输出它，不要把浏览器开发者控制台的交互反馈直接套在文件执行上。

空行可以分隔代码，不会产生输出。`#` 在字符串外面可以开始一条行注释；例如下面最后一行是给读者看的说明：

```python
course = "Python"
print(course)
# This comment does not print anything.
```

## 3. 借用 JS 经验，但保留差异

下面的对照只用于阅读语法；本章的运行验收放在本地终端，不依赖网页编辑器的执行环境。

<PythonEditor title="读取名称并输出" compare={true} canRun={false}>
```javascript !! js
const name = "Python";
console.log(name);
```

```python !! py
name = "Python"
print(name)
```
</PythonEditor>

两边在这个小例子中都输出 `Python`，但这不是说 `const` 与 Python 赋值完全等价，也不是说 `console.log` 与 `print` 的所有功能相同。

Python 的名称可以在后面重新赋值。本章只先观察这一行为：

```python
course = "Python"
print(course)
course = "FastAPI"
print(course)
```

输出为：

```text
Python
FastAPI
```

第一次输出发生在重新赋值之前，不会因为后面改了名称的值就“回头改变”。这些都是普通文本；**写出字符串 `"FastAPI"` 不会安装框架，也不会启动服务器。**

## 4. 是谁在运行 `.py` 文件？

前端开发中，编辑器负责修改文件，浏览器或 Node.js 等运行环境负责执行代码。Python 也需要区分这些职责：

- **编辑器**：让你创建、修改并保存源码。语法高亮不代表代码已经运行。
- **Python 语言**：规定这几行代码的写法和含义。
- **Python 解释器**：实际读取和执行代码的程序。本课程本地使用 CPython，它是 Python 的一种实现。
- **终端**：让你发出启动命令、查看输出与错误。终端命令不是 Python 源码。

最小过程是：

```text
保存 first_steps.py
        ↓
在终端启动 Python 解释器，并指定这个文件
        ↓
解释器读取文件，检查语法，再执行代码
        ↓
在终端看到输出，或者看到错误信息
```

`.py` 是 Python 源文件常用的扩展名。把文件改成这个后缀，不会让里面的 JS 自动变成 Python；真正执行的仍然是文件中的内容。

有些文档展示以 `>>>` 开头的 Python 交互式会话。`>>>` 是提示符，不是你应该复制进文件的源码。本章固定使用文件运行，先不在几种执行方式之间来回切换。

我们使用 **CPython 3.13** 作为教学基线，不声称它是最新版本。这个脚本没有第三方 Python 依赖，不需要创建工程配置或安装 FastAPI。

第一条准备 Python 3.13，已安装时通常可以复用。第二条选择这个版本的解释器，让它报告自己的版本，结果应以 `Python 3.13.` 开头；末尾补丁号可能不同。

首次安装可能下载文件，需要网络。下载进度或 uv 提示来自工具，不是我们即将编写的程序输出。安装成功以后，这份脚本本身不会访问网络。

## 6. 完成第一次运行，并解释命令

确认终端当前目录中有 `first_steps.py`，执行：

```bash
uv run --no-project --python 3.13 python first_steps.py
```

可以分段理解这条命令：

| 部分 | 本章中承担的职责 |
| --- | --- |
| `uv run` | 通过 uv 启动一个命令 |
| `--no-project` | 不把当前或父目录的 uv 工程作为运行上下文 |
| `--python 3.13` | 选择 Python 3.13 解释器 |
| `python` | 要运行的程序是 Python 解释器 |
| `first_steps.py` | 交给解释器执行的文件，按当前终端目录定位 |

这不是让你背下一张参数表。我们固定这一条路径，是为了先排除“机器上究竟用了哪一个 Python”的歧义。**现在不需要执行 `uv init`、创建锁文件或安装测试框架。** 环境与依赖为什么需要隔离，会在后面的工程章节单独讲清。

正常的程序输出是：

```text
Hello!
Python
```

看到输出后，再回到编辑器，把第一行的 `"Python"` 改成 `"FastAPI"`，**保存**，重新执行同一条命令。第二行输出应改变，第一行仍为 `Hello!`。完成后把文件恢复成原版。

如果输出没有变化，先核对三个对象：编辑器保存的是哪个文件、终端在哪个目录、命令执行的是哪个文件。不要马上重装 Python；这次问题可能只是你修改与运行的不是同一份文件。

## 7. 两个可恢复的错误实验

在当前练习目录复制一份 `first_steps.py` 作为备份。每次只改一个地方，观察之后恢复，再进行下一个实验。不要修改其他项目的文件。

### 7.1 名称写错：语法能成立，执行时找不到名称

把程序最后一行的 `course` 改成 `cours`，其余保持不变：

```python expected-error=NameError
course = "Python"
print("Hello!")
print(cours)
```

运行后，你会看到 `Hello!`，随后出现包含 `NameError` 的错误。前两行已经执行；到第三行需要读取 `cours` 时，找不到这个名称，所以停止了正常执行。

先看错误末尾的类型与消息，再往上找到自己的文件名和行号，回到编辑器核对那一行。`course` 和 `cours` 是两个不同名称，修复的是源码拼写，不是安装一个叫 `cours` 的包。

这里不要求背诵完整 traceback 格式。先能定位自己的文件、理解这次失败的直接原因即可。修复后重跑，确认两行正常输出回来。

### 7.2 引号漏写：在执行之前就无法读懂文件

把第一行结尾的双引号删掉：

```python expected-error=SyntaxError
course = "Python
print("Hello!")
print(course)
```

这次会出现 `SyntaxError`，脚本中的两条 `print` 都不会执行。区别在于：解释器还没开始逐行执行，就发现这份文件不是完整、合法的 Python 语法。

错误消息或箭头在不同补丁版本中可能有细微差别，不需要记住它们的整段文字。恢复引号、保存、重跑，才算完成这个排错实验。

### 7.3 先分清错误发生在哪一层

| 现象 | 先检查什么 | 不要先做什么 |
| --- | --- | --- |
| 找不到 `uv` 命令 | 安装是否完成，新终端能否找到它 | 改 Python 业务代码 |
| 无法打开 `first_steps.py` | 当前目录、文件名、是否误存为 `.txt` | 安装第三方 Python 包 |
| `SyntaxError` | 指向的代码、引号或括号是否完整 | 换一套框架 |
| `NameError` | 使用的名称是否已赋值、拼写是否一致 | 清空环境重装 |
| 输出仍是旧内容 | 文件是否保存，执行的是否同一份文件 | 把正常输出误当成缓存问题 |

这个表只是本章涉及的几种现象，不是所有同名错误的完整原因清单。遇到不同问题，要保留实际命令和报错，不能只凭一个错误名称猜结论。

## 8. 练习：从解释到独立写出

### 练习一：先预测，再验证

不运行代码，写出下面程序的三行输出，并解释为什么后一次赋值不会改变已经打印的内容。

```python
topic = "Python"

```

<details>
<summary>完成后查看解释</summary>

```text

topic
FastAPI
```

第一次调用读取旧值；第二次直接输出字面量 `"topic"`；第三次读取重新赋值后的值。终端中已输出的文本不是一个会随着名称变化而自动更新的前端组件。

</details>

### 练习二：只修改一个地方

从原版 `first_steps.py` 出发，把最后一行改成 `print("course")`。预测两行输出，保存后运行核对，再恢复原版。

解释为什么这次不会读取第一行赋给 `course` 的值。如果你只能说“有引号所以不一样”，继续补全：引号中的内容是什么？没有引号时解释器会做什么？

<details>
<summary>完成后查看结果</summary>

输出是 `Hello!` 和 `course`。最后一行直接传入字符串字面量，没有通过名称获取值。恢复为 `print(course)` 后，它才读取赋值产生的值。

</details>
