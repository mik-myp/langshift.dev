## 1. Understand the behavior before annotating its contract

The L10 application already runs, saves data, and has tests. Why add types? If a function expects minutes but its caller supplies strings, discovering the disagreement before execution narrows the investigation. Annotations put expectations beside parameters and results so collaborators, editors, and checkers do not have to infer them from every call site.

Your basic TypeScript experience transfers, but Python does not automatically run a type-checking build gate before execution. Running Python and running a static checker are separate commands. Annotations alone generally do not reject invalid input. Tests observe particular executions, static checking analyzes source, and runtime validation protects actual data boundaries. None replaces the others.

| Contract | Scope |
| --- | --- |
| Prerequisites | L02 containers, L04 functions, L06 modules, L10 independent project |
| New capabilities | Function/container annotations, unions, nullability, defaults, diagnostics, external input validation |
| Acceptance | Annotate an existing function, repair static errors, prove that passing a checker does not make JSON trustworthy |

## 3. Read annotations on behavior you already understand

First read the unannotated function. Predict how it skips an over-budget item but keeps looking at later items:

<Code language="python">{getTypingExample('baseline.py')}</Code>

A colon after a parameter name declares its expected type; an arrow declares the return type. Local variables can be annotated or inferred from assignments. This complete declaration experiment executes independently but prints nothing until a function is called.

```python smoke=typing
def add_minutes(left: int, right: int) -> int:
    total: int = left + right
    return total


def show_minutes(value: int) -> None:
    print(value)
```

`-> None` means normal completion has no business result. It does not mean the function does nothing, cannot fail, or may return anything. A Python function that finishes without an explicit return also returns None. Types capture only part of the contract: int is not the same as non-negative minutes, and str is not the same as a non-blank title.

Annotate the baseline parameters and return without changing the algorithm. The complete implementation later also retains runtime rules. **Adding annotations and adding validation are distinct changes.**

## 4. Unions, nullable values, and omittable arguments

```python smoke=typing
def required_budget(budget: int | None) -> str:
    if budget is None:
        return "unlimited"
    return str(budget)


def default_budget(budget: int = 45) -> int:
    return budget


def optional_budget(budget: int | None = None) -> str:
    return required_budget(budget)
```

`int | None` permits an integer or None. It does not supply a default argument. required_budget requires an argument but permits explicit None. default_budget may be called without an argument, but its static contract does not accept None. optional_budget permits both omission and explicit None. Do not collapse TypeScript optional properties, Python default arguments, and nullable values into one concept.

After a branch eliminates None using `is None`, the checker can narrow the other path to int. `if budget` would also discard the valid value 0. Type hints cannot decide whether zero budget and unlimited budget mean the same thing. Here, zero permits only zero-minute items; None means unlimited.

<details>
<summary>Explanation answer: how do you know whether an argument may be omitted?</summary>

Look for a default, not for None in the annotation. Predict required_budget(), required_budget(None), default_budget(), and default_budget(None). The first lacks an argument at runtime; the second is valid; the third uses 45; the fourth violates the static contract, but the unguarded function can still return None at runtime.

</details>

## 5. Containers describe elements, not an entire business schema

`list[int]` describes integer elements; an empty list qualifies. `dict[str, int]` describes string keys and integer values, not exactly two required keys named count and minutes. A heterogeneous dictionary annotated `dict[str, object]` requires narrowing its retrieved values before integer operations. We will not introduce classes or elaborate typing just to describe every record field early; L12 develops another part of model representation.

Any and object are not synonyms. Any permits many operations without proof; object says there is a Python object but does not promise its specific capabilities. These function bodies do not execute during declaration. The first contract permits an unproven upper call; the second checks before using that capability.

```python smoke=typing
from typing import Any


def unchecked_label(value: Any) -> str:
    return value.upper()


def value_label(value: object) -> str:
    if isinstance(value, str):
        return value.upper()
    return "not text"
```

Both pass the current static checks, but the first still fails if it receives an integer. In your own copy, remove the second function's check and return value.upper() directly: object does not promise upper, so the checker now rejects the operation. Replacing object with Any or suppressing the diagnostic would conceal the missing boundary rather than explain it.

## 7. Turn external data into validated values

Read this implementation along the data flow: text → JSON decoding → array shape → element validation → new list → selection → summary. Then explain each function's responsibility.

<Code language="python">{getTypingExample('estimates.py')}</Code>

JSON decoding can produce objects, arrays, text, numbers, booleans, and nulls; its return type is dynamic. Assigning it to object establishes an explicit checking boundary, not a conversion. After confirming a list, pass every element to non_negative_int, whose parameter is object. Only a validated value enters the result. Internal operations receive validated minutes but retain explicit rules so another runtime caller cannot bypass the business policy.

`type(value) is int` deliberately means ordinary integers, excluding bool and integer subclasses. Python's type relationships make bool a subclass of int, so mypy may accept it. In this business contract true is not one minute. General-purpose libraries may legitimately accept subclasses; this is not advice to use exact type checks everywhere.

<Code language="python">{getTypingExample('errors/bool_static.py')}</Code>

```bash
uv run --locked python -m mypy errors/bool_static.py
uv run --locked python -m errors.bool_static
```

The checker passes; runtime validation raises ValueError. This is reproducible evidence that static types and business rules differ. The summary return type describes a homogeneous mapping; exact keys and relationships also depend on implementation, tests, and documentation.

## 12. Acceptance and a resumable checkpoint

You are ready when you can annotate the old function without consulting the answer, distinguish defaults from nullability, reproduce static failure and a static-pass/runtime-rejection case, draw the JSON boundary, and finish the independent variation. Make tests detect a premature return that skips later validation. Documentation is allowed; memorizing diagnostic wording is not required.

Before pausing, record Python/mypy versions, the selected checking scope, the last two successful commands, intentional failures, unverified inputs, and the next concrete step. Resume by running the normal suite, then isolate the pending failure instead of treating all of errors as a passing suite.

L12 introduces classes and data models through instance ownership and explicit validation. Neither dataclass nor type hints will be presented as an automatic guard around every input.
